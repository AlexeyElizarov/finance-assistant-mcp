# MCP-инструменты коллекции идентификаторов банковского счёта

**Статус:** Утверждено (2026-08-20, rev.3).

## Назначение

- Операторы не могут вести идентификаторы банковского счёта через инструменты MCP.
- Нужен доступ к коллекции идентификаторов и к её чтению на счетах без прямого вызова HTTP.

## Критерий приёмки

- Коллекция идентификаторов банковского счёта доступна через MCP для всех операций публичной HTTP-поверхности идентификаторов согласно целевому поведению.
- Чтение списка банковских счетов и запись счёта через существующие инструменты возвращают коллекцию идентификаторов согласно целевому поведению.
- Запись банковского счёта через существующий инструмент не принимает и не изменяет идентификаторы.
- Доменные ошибки API идентификаторов пробрасываются в ошибку инструмента без потери кода ошибки.
- Справочник доступных инструментов MCP обновлён.
- Поведение покрыто функциональным тестированием.

## Объём и границы

### Входит в объём

#### Возможности

- В объём входят инструменты MCP списка идентификаторов профиля с необязательным фильтром по счёту.
- В объём входят инструменты MCP чтения идентификатора по идентификатору строки.
- В объём входят инструменты MCP создания одного идентификатора.
- В объём входят инструменты MCP пакетного создания идентификаторов.
- В объём входят инструменты MCP изменения значения идентификатора по идентификатору строки.
- В объём входят инструменты MCP пакетного изменения значения идентификаторов.
- В объём входят инструменты MCP удаления идентификатора по идентификатору строки.
- В объём входят инструменты MCP пакетного удаления идентификаторов.
- В объём входит чтение коллекции идентификаторов в списке банковских счетов через существующий инструмент списка.
- В объём входит чтение коллекции идентификаторов в ответе записи банковского счёта через существующий инструмент upsert.
- В объём входит отказ записи идентификаторов через существующий инструмент upsert банковского счёта.

#### Артефакты приёмки

- В объём входят обработчики и схемы инструментов коллекции в MCP-сервере.
- В объём входит модуль тонких обёрток над HTTP API идентификаторов.
- В объём входит расширение существующего модуля счетов чтением коллекции идентификаторов.
- В объём входят функциональные тесты.
- В объём входит обновление справочника доступных инструментов MCP.

### Не входит в объём

#### Зависимости и соседние возможности

- Не входят модель, миграция схемы и операции слоя сохранения идентификаторов (FIN-309).
- Не входит проектирование HTTP-контракта коллекции идентификаторов (FIN-320).
- Не входит пользовательский интерфейс ведения идентификаторов счёта (FIN-322).
- Не входят инструменты MCP справочника банков сверх уже существующей поверхности (FIN-293).
- Не входит начальное заполнение известных значений на постоянных профилях.
- Не входит автоматический импорт идентификаторов из файла выписки.

#### Не планируется

- Не входит одно поле IBAN на теле банковского счёта.
- Не входит одно поле номера банковского счёта на теле банковского счёта.
- Не входит один инструмент MCP с перечислением действия вместо отдельных инструментов.
- Не входит отдельное чтение банковского счёта по идентификатору.
- Не входит фильтр списка идентификаторов по домохозяйству.
- Не входит пагинация и клиентская сортировка списка.
- Не входит контрольная сумма IBAN по ISO 13616.
- Не входит таблица длин и структур IBAN по странам.
- Не входит разбор банковской части IBAN по правилам страны.

## Факт реализации (до)

| Область | Текущее поведение | Проблема |
| -------- | ----------------- | -------- |
| MCP идентификаторов | Инструментов коллекции нет | Ops не создают, не меняют и не удаляют строки без raw HTTP |
| MCP счетов | `list_bank_accounts` / `upsert_bank_account` по FIN-240 и FIN-293 без коллекции идентификаторов | После FIN-320 ответ HTTP содержит коллекцию; MCP её не гарантирует; запись счёта не умеет явно отвергнуть запрещённые ключи |
| HTTP | FIN-320: восемь операций идентификаторов и поле коллекции на списке и записи счёта | Нужна MCP-поверхность с полным паритетом |

## Обратная совместимость

- Новые инструменты коллекции добавляются без изменения семантики прочих существующих инструментов MCP, кроме перечисленных ниже.
- Инструмент `list_bank_accounts` добавляет ключ коллекции идентификаторов в элементы списка без изменения существующих полей счёта.
- Инструмент `upsert_bank_account` не получает новых обязательных аргументов.
- Вызов `upsert_bank_account` без ключей идентификаторов сохраняет прежнюю семантику записи полей FIN-240 и FIN-293.
- Контракт HTTP API идентификаторов и счетов этой задачей не меняется.
- HTTP банков и платёжных инструментов не получает полей идентификатора счёта.

## Целевое поведение

### Паритет поверхности идентификаторов (D-01)

#### Таблица инструментов

| Инструмент MCP | Операция HTTP | Смысл |
| -------------- | ------------- | ----- |
| `list_bank_account_identifiers` | `GET /api/v1/bank-account-identifiers` | Список |
| `get_bank_account_identifier` | `GET /api/v1/bank-account-identifiers/{identifier_id}` | Чтение по идентификатору строки |
| `create_bank_account_identifier` | `POST /api/v1/bank-account-identifiers` | Создание одной записи |
| `create_bank_account_identifiers` | `POST /api/v1/bank-account-identifiers/batch` | Пакетное создание |
| `patch_bank_account_identifier` | `PATCH /api/v1/bank-account-identifiers/{identifier_id}` | Изменение значения по идентификатору строки |
| `patch_bank_account_identifiers` | `PATCH /api/v1/bank-account-identifiers` | Пакетное изменение значения |
| `delete_bank_account_identifier` | `DELETE /api/v1/bank-account-identifiers/{identifier_id}` | Удаление по идентификатору строки |
| `delete_bank_account_identifiers` | `DELETE /api/v1/bank-account-identifiers` | Пакетное удаление |

#### Правила набора

- Для публичной HTTP-поверхности FIN-320 MCP предоставляет однозначно соответствующую поверхность.
- Каждой операции HTTP API соответствует отдельный MCP-инструмент с той же функциональной семантикой.
- Создание, изменение и удаление разведены по разным инструментам.
- Индивидуальные и пакетные операции разведены по разным инструментам.
- Идентификатор строки при создании задаёт слой сохранения.
- Клиент MCP поле идентификатора строки при создании не передаёт.
- Один инструмент с перечислением действия не используется.
- Доменные правила тел, атомарности пакетов и кодов ошибок наследуются из FIN-320 без дублирования в MCP.

### Общий конвейер (D-02)

```
1. получить сессию API (профиль данных, базовый URL)
2. проверить аргументы MCP до HTTP
3. собрать путь, параметры запроса и тело
4. выполнить вызов метода GET, POST, PATCH или DELETE
5. при коде HTTP 200 или 201 ожидать тело ответа и обернуть сущность или коллекцию в конверт ok / profile / base
6. при коде HTTP 204 не ожидать тела ответа и вернуть только конверт ok / profile / base
7. иначе вернуть ошибку инструмента с телом ответа API
8. сетевые сбои пробросить без дополнительной обёртки
```

- Порядок шагов фиксирован.
- Успех операции определяется кодом HTTP, а не наличием или отсутствием тела в ответе.
- Доменные инварианты FIN-309 и FIN-320 в MCP не дублируются.

### Модуль и регистрация (D-03)

- Логика обёрток коллекции идентификаторов размещается в `scripts/bank_account_identifiers.py`.
- Расширение чтения коллекции на счетах выполняется в существующем `scripts/households.py`.
- Обработчики и схемы инструментов регистрируются в `server.py`.
- Справочник доступных инструментов обновляется в `mcp-gaps.md`.

### Валидация до HTTP (D-04)

#### Слои проверки

- Схема MCP проверяет типы и обязательность объявленных аргументов, включая поля элементов пакетного создания.
- Схема MCP отклоняет незаявленные аргументы.
- Нарушение схемы даёт ошибку валидации MCP до HTTP.
- Тип Python-исключения при отклонении схемой не фиксируется.
- Обработчик не дублирует проверку типов.
- Обработчик не дублирует отклонение незаявленных аргументов.
- Обработчик применяет `strip` и проверку непустоты только к полям, перечисленным в подразделах ниже.
- Нарушение правил обработчика даёт `ValueError` без вызова API.
- Формат UUID, неизвестные поля HTTP, атомарность пакета и доменные инварианты FIN-309 / FIN-320 проверяет только backend.

#### Идентификаторы пути чтения и удаления

- MCP проверяет, что идентификатор строки пути после `strip` непуст для чтения одной записи.
- MCP проверяет, что идентификатор строки пути после `strip` непуст для удаления одной записи.

#### Создание одной записи

- MCP проверяет, что идентификатор счёта после `strip` непуст.
- MCP проверяет, что тип идентификатора после `strip` непуст.
- MCP проверяет, что значение после `strip` непусто.

#### Пакетное создание

- Обработчик проверяет только наличие непустого массива `bank_account_identifiers`.
- Схема MCP проверяет структуру, типы и обязательность полей каждого элемента пакетного создания.
- Обязательные поля элемента совпадают с D-09: идентификатор счёта, тип идентификатора и значение.
- Отсутствие обязательного поля элемента даёт ошибку валидации MCP до HTTP.
- Обработчик не применяет к полям элементов `strip` и проверку непустоты.
- Пустые строковые значения полей элемента передаются backend.
- Непустоту, нормализацию и доменные инварианты значений элемента проверяет backend FIN-320.

#### Изменение значения одной записи

- MCP проверяет, что идентификатор строки пути после `strip` непуст.
- MCP проверяет, что значение после `strip` непусто.

#### Пакетное изменение значения

- MCP проверяет наличие непустого массива `bank_account_identifiers`.
- У каждого элемента после `strip` непуст идентификатор строки.
- У каждого элемента после `strip` непусто значение.

#### Пакетное удаление

- MCP проверяет наличие непустого списка идентификаторов `ids`.
- Каждый элемент `ids` после `strip` непуст.

#### Фильтр списка

- Отсутствие ключа фильтра означает список без ограничения по счёту.
- Ключ фильтра со значением `null`, пустой строкой или строкой из пробелов отклоняется на MCP-уровне до HTTP.

### Отсутствие ключа и явное обнуление (D-05)

- Ключ, отсутствующий в аргументах MCP, не попадает в JSON тела запроса и не попадает в параметры запроса.
- Поля создания и изменения значения не допускают JSON `null`.
- Явная передача `null` для обязательного строкового поля отклоняется на MCP-уровне до HTTP.
- Тип Python-исключения при отклонении `null` схемой не фиксируется.
- Пустая строка после `strip` на полях, которые проверяет обработчик по D-04, даёт `ValueError` без вызова API.
- Пустая строка не преобразуется в `null`.
- Значение по умолчанию параметра в коде не смешивает «ключ не передан» и «ключ передан со значением `null`».
- Построение тела опирается на набор реально переданных полей аргументов.

### Инварианты (D-06)

- MCP не ослабляет инварианты HTTP API идентификаторов и счетов.
- Тело запроса содержит только явно переданные ключи аргументов.
- MCP не нормализует значения REST-ответа.
- MCP не нормализует структуру REST-ответа, кроме явно установленного в D-16 подставления пустого массива `identifiers` при отсутствии ключа.
- При коде HTTP 204 ключ сущности отсутствует.
- Обёртка успеха добавляет только конверт `ok` / `profile` / `base` и ключ сущности или коллекции.

### Список идентификаторов (D-07)

#### Вход

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; по умолчанию `prod` |
| `base` | string | нет | Базовый URL API; по умолчанию из сессии |
| `bank_account_id` | string | нет | Фильтр по банковскому счёту; отсутствие ключа означает список всего профиля |

#### Результат

- При успехе ответ инструмента содержит `ok: true`, профиль, базовый URL и коллекцию `bank_account_identifiers`.
- Пустой список допустим и сохраняет `ok: true`.
- Успех соответствует ответу API с кодом HTTP 200.
- Несуществующий счёт в фильтре даёт ошибку инструмента по ответу API с кодом HTTP 404 и кодом ошибки `bank_account_not_found`.

### Создание одного идентификатора (D-09)

#### Вход

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; по умолчанию `prod` |

| `bank_account_id` | string | да | Идентификатор существующего счёта профиля |

#### Результат

- Поле идентификатора строки в аргументах создания не передаётся.
- Успешное создание соответствует ответу API с кодом HTTP 201.
- При успехе ответ инструмента содержит `ok: true` и объект `bank_account_identifier` с выданным идентификатором.
- Значение в ответе уже нормализовано HTTP по FIN-309 D-04.
- Несуществующий счёт даёт ошибку инструмента по ответу API с кодом HTTP 404 и кодом ошибки `bank_account_not_found`.

### Ошибки коллекции (D-15)

- Ответ API с кодом, отличным от успеха операции, даёт `RuntimeError` через `format_api_error`.
- Мягкий ответ вида `{ "ok": false }` без исключения не используется.
- Все доменные ошибки полностью наследуются из FIN-320.
- MCP не вводит собственных кодов ошибок коллекции идентификаторов.

| Ситуация | Источник | `error.code` |
| -------- | -------- | ------------ |
| Валидация тела, параметров, невалидный UUID, запрещённые ключи HTTP | API | `validation_error` |
| Банковский счёт не найден | API | `bank_account_not_found` |
| Строка идентификатора не найдена | API | `identifier_not_found` |
| Повтор той же четвёрки профиль, счёт, тип и нормализованное значение | API | `duplicate_identifier` |
| Повтор IBAN у другого счёта того же профиля | API | `duplicate_iban` |
| Повтор номера типа `account_number` у другого счёта того же профиля и того же банка | API | `duplicate_account_number` |
| Нарушение схемы MCP: тип, обязательность, незаявленный аргумент | MCP до HTTP | ошибка валидации MCP; код API отсутствует |
| Нарушение правил обработчика D-04 | MCP до HTTP | `ValueError`; код API отсутствует |

### Коллекция на ответах счёта (D-16)

#### Чтение списка

- Каждый элемент коллекции `bank_accounts` в ответе `list_bank_accounts` всегда содержит ключ `identifiers`.
- Значение берётся из ответа HTTP API счёта.
- Отсутствующий ключ в ответе API даёт пустой массив в элементе MCP; это единственное преобразование структуры REST-ответа, которое допускает D-06.
- Значение ключа `identifiers` в ответе MCP не бывает `null`.
- Счёт без строк идентификаторов возвращает пустой массив.
- Элементы массива имеют те же поля, что объект D-09.
- MCP не отбрасывает ключи элементов коллекции из тела HTTP.
- MCP не переименовывает ключи элементов коллекции из тела HTTP.

#### Чтение записи

- Успешный ответ `upsert_bank_account` всегда содержит ключ `identifiers` в объекте `bank_account`.
- Нормы отсутствующего ключа, пустого массива и запрета `null` совпадают с чтением списка.
- Успешная запись прежних полей счёта не создаёт, не изменяет и не удаляет строки идентификаторов.

#### Пример фрагмента счёта без идентификаторов

```json
{
  "id": "acc-sparkasse-mastercard",
  "identifiers": []
}
```

### Запрет записи идентификаторов через upsert счёта (D-17)

- Схема `upsert_bank_account` не объявляет ключ `identifiers`.
- Схема `upsert_bank_account` не объявляет ключ `iban`.
- Схема `upsert_bank_account` не объявляет ключ `account_number`.
- Схема отклоняет незаявленные аргументы, включая эти три ключа.
- Присутствие любого из этих ключей даёт ошибку валидации MCP до HTTP.
- Тип Python-исключения при этом отклонении не фиксируется.
- Обработчик не помещает эти ключи в тело вызова метода `PUT`.
- Прочие поля записи счёта FIN-240 и FIN-293 не меняются.
