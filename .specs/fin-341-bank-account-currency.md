# MCP валюты банковского счёта

**Статус:** Утверждено (2026-08-25, rev.3).

## Назначение

- Операторы не могут прочитать и задать валюту банковского счёта через `list_bank_accounts` и `upsert_bank_account`.
- Операторам нужен тот же контур списка и создания или изменения счёта, чтобы прочитать валюту счёта, задать её при создании и однократно заполнить у существующего счёта.

## Критерий приёмки

- Инструмент списка `list_bank_accounts` и инструмент создания или изменения `upsert_bank_account` принимают и возвращают валюту счёта согласно целевому поведению.
- Создание банковского счёта без валюты счёта отклоняется.
- Однократное заполнение пустой валюты счёта выполняется согласно целевому поведению.
- Попытка сменить уже заданную валюту счёта отклоняется.
- Справочник доступных инструментов MCP обновлён.
- Поведение покрыто функциональными тестами.

## Объём и границы

### Входит в объём

#### Возможности

- В объём входит расширение `list_bank_accounts` и `upsert_bank_account` полем валюты счёта из FIN-339.
- В объём входит чтение валюты счёта в успешном ответе списка и в успешном ответе создания или изменения.
- В объём входит передача валюты счёта при создании и при изменении существующего банковского счёта.
- В объём входит однократное заполнение пустой валюты счёта через `upsert_bank_account`.
- В объём входит проброс доменных кодов ошибок валюты счёта в ошибку инструмента.

#### Артефакты приёмки

- В объём входят схемы и обработчики `list_bank_accounts` и `upsert_bank_account`.
- В объём входит расширение модуля тонких обёрток счетов.
- В объём входят функциональные тесты.
- В объём входит обновление справочника доступных инструментов MCP.

### Не входит в объём

#### Зависимости и соседние возможности

- Не входят модель, миграция схемы и слой сохранения валюты счёта (FIN-340).
- Не входит программный интерфейс HTTP валюты банковского счёта (FIN-339).
- Не входит пользовательский интерфейс ведения валюты счёта (FIN-342).
- Не входит начальное заполнение валюты существующих счетов на постоянных профилях (FOPS-39).
- Не входят валюта операции, снимок на заголовке и конвертация факта (FIN-170).
- Не входит справочник ISO 4217 и проверка кода по зарегистрированному перечню (FIN-343).
- Не входит создание банковского счёта T-Bank (FOPS-36).

#### Не планируется

- Не входит новый инструмент списка, создания, изменения или чтения счёта.
- Не входит отдельное чтение банковского счёта по идентификатору.
- Не входят пакетная запись счетов и удаление счёта.
- Не входит значение по умолчанию `EUR` на слое MCP.
- Не входит история валюты счёта.
- Не входит смена семантики прочих полей счёта, ссылки на банк и вложенной коллекции идентификаторов.

## Целевое поведение

### Паритет поверхности (D-01)

- Набор инструментов банковских счетов совпадает с FIN-240, FIN-293 и FIN-321.
- Эта задача не добавляет инструменты и не убирает инструменты.

| Инструмент MCP | Операция HTTP | Смысл |
| -------------- | ------------- | ----- |
| `list_bank_accounts` | `GET /api/v1/households/{household_id}/bank-accounts` | Список |
| `upsert_bank_account` | `PUT /api/v1/households/{household_id}/bank-accounts/{account_id}` | Создание или изменение |

- Публичной HTTP-поверхности FIN-339 соответствуют те же два инструмента.
- Отдельное чтение счёта по идентификатору, частичное обновление, пакетная запись и удаление в MCP не вводятся.
- Их нет в HTTP FIN-339.
- Норма полного набора CRUD для нового ресурса к этой задаче не применяется.
- Эта задача расширяет уже существующие инструменты одним полем уже существующего HTTP-контракта.
- Доменные правила нормализации, обязательности при создании, неизменяемости и однократного заполнения наследуются из FIN-340 и FIN-339 без дублирования в MCP.

### Конвейер (D-02)

```
1. получить сессию API (профиль данных, базовый URL)
2. проверить аргументы MCP до HTTP
3. собрать путь и тело
4. выполнить вызов метода GET или PUT
5. при коде HTTP 200 и теле-объекте обернуть коллекцию или сущность в конверт ok / profile / base
6. иначе вернуть ошибку инструмента с телом ответа API
7. сетевые сбои пробросить без дополнительной обёртки
```

- Порядок шагов совпадает с существующими инструментами счетов.
- Успех определяется кодом HTTP 200 и тем, что тело является объектом.
- Любой иной код HTTP, включая прочие `2xx`, даёт ошибку инструмента.
- Инварианты FIN-340 и FIN-339 в MCP не дублируются.

### Модуль и регистрация (D-03)

- Расширение списка и создания или изменения выполняется в существующем `scripts/households.py`.
- Схемы инструментов `list_bank_accounts` и `upsert_bank_account` обновляются в `server.py`.
- Справочник доступных инструментов обновляется в `mcp-gaps.md`.
- После закрытия задачи label `mcp-gap` снимается с FIN-341.

### Схема аргумента валюты счёта (D-04)

#### Список

- Схема `list_bank_accounts` не получает новых аргументов.

#### Создание или изменение

- Схема `upsert_bank_account` объявляет необязательный аргумент валюты счёта (`currency`).
- Тип аргумента равен `string`.
- Значение JSON `null` схемой не допускается.
- Значение с типом, отличным от строки, схемой не допускается.
- Аргумент не входит в список обязательных.
- Незаявленные аргументы по-прежнему отклоняются, включая ключи коллекции идентификаторов из FIN-321.

#### Отклонение до HTTP

- Отсутствие обязательных аргументов создания или изменения (`household_id`, `account_id`, `provider`, `display_name`, `valid_from`, `bank_id`) отклоняется схемой MCP до обработчика.
- Передача валюты счёта как JSON `null` даёт ошибку валидации схемы MCP до обработчика.
- Передача валюты счёта с типом, отличным от строки, даёт ошибку валидации схемы MCP до обработчика.
- Тип Python-исключения при отклонении схемой не фиксируется.
- HTTP-клиент при отклонении схемой не вызывается.

### Передача валюты счёта в тело создания или изменения (D-05)

#### Отсутствие ключа

- Если ключ валюты счёта во входных аргументах отсутствует, тело HTTP этот ключ не содержит.
- Отсутствие ключа само по себе ошибкой MCP не является.
- Создание без ключа отклоняет HTTP кодом 422 и кодом ошибки `validation_error`.
- Изменение без ключа сохраняет прежнюю валюту счёта, как в FIN-339.

#### Присутствие ключа

- Если ключ присутствует и значение является строкой, тело HTTP содержит этот ключ.
- Строковое значение копируется в тело HTTP без изменения.
- Обработчик не удаляет пробелы по краям.
- Обработчик не приводит буквы к верхнему регистру.
- Обработчик не подставляет значение `EUR`.
- Обработчик не подставляет валюту по каналу импорта.
- Пустая строка передаётся в тело HTTP как пустая строка.
- Строка из пробелов передаётся в тело HTTP без изменения.
- Ключ из тела из-за пустой строки не удаляется.

#### Однократное заполнение

- Если у существующего банковского счёта валюта счёта отсутствует, `upsert_bank_account` с допустимым строковым значением передаёт ключ в HTTP.
- Допуск заполнения, нормализацию и ответ определяет HTTP FIN-339.
- После успеха ответ MCP содержит нормализованный код из HTTP.
- Начальное заполнение постоянных профилей этой задачей не выполняется (FOPS-39).
- Существующие счета постоянных профилей с незаполненной валютой в приёмке T1–T4 не изменяют.

#### Прямой вызов обработчика

- Если обработчик вызван в обход схемы с ключом валюты счёта и значением `null`, обработчик поднимает `ValueError` без вызова HTTP.
- Валюту счёта нельзя очистить через MCP.

### Список и ответ создания или изменения (D-06)

#### Состав

- Каждый элемент коллекции `bank_accounts` в ответе `list_bank_accounts` всегда содержит ключ валюты счёта (`currency`).
- Успешный ответ `upsert_bank_account` всегда содержит ключ валюты счёта в объекте `bank_account`.
- Значение берётся из ответа HTTP, если ключ в объекте HTTP присутствует.

#### Отсутствующий ключ в ответе HTTP

- Если ключ валюты счёта в объекте HTTP отсутствует, элемент MCP содержит этот ключ со значением JSON `null`.
- Цель этого правила: гарантировать вызывающей стороне MCP наличие ключа, как для ссылки на банк в FIN-293.
- Это защита формы ответа MCP.
- Это не замена приёмки контракта FIN-339.
- Отсутствие ключа в HTTP не доказывает, что валюта счёта в базе данных не заполнена.
- Это единственное дополнительное преобразование структуры REST-ответа счёта относительно FIN-293 и FIN-321.
- Ключи ссылки на банк и коллекции идентификаторов сохраняют нормы FIN-293 и FIN-321.

#### Значения

- Если валюта счёта в HTTP равна JSON `null`, в ответе MCP значение равно JSON `null`.
- Если валюта счёта заполнена, в ответе MCP значение равно нормализованному трёхбуквенному коду из HTTP.
- MCP не переименовывает прочие ключи объекта счёта.
- MCP не отбрасывает прочие ключи объекта счёта.

### Нормы валюты счёта (D-07)

- Допустимые значения, нормализация, пустая строка как отсутствие значения и коды ошибок совпадают с FIN-340 и FIN-339.
- Нормализацию строкового значения валюты счёта полностью выполняет HTTP API согласно FIN-339.
- MCP не удаляет пробелы по краям входной строки.
- MCP не меняет регистр входной строки.
- MCP не подставляет значение по умолчанию.
- MCP не ужесточает инварианты FIN-339.
- MCP не смягчает инварианты FIN-339.
- Валюта счёта не отождествляется с валютой бюджета.
- Валюта счёта не отождествляется с валютой операции.

### Ошибки (D-08)

| Ситуация | Источник | Поведение |
| -------- | -------- | --------- |
| Отсутствует обязательный ключ аргумента создания или изменения | MCP до HTTP | ошибка валидации схемы MCP; HTTP не вызывается |
| Валюта счёта передана как JSON `null` | MCP до HTTP | ошибка валидации схемы MCP; HTTP не вызывается |
| Валюта счёта передана со значением нестрокового типа | MCP до HTTP | ошибка валидации схемы MCP; HTTP не вызывается |
| Обработчик вызван с валютой счёта равной `null` | MCP до HTTP | `ValueError`; HTTP не вызывается |
| Создание без ключа валюты счёта | API | HTTP 422, `validation_error` |
| При создании или изменении ключ передан как пустая строка, строка из пробелов или значение не проходит форму трёх букв | API | HTTP 422, `validation_error` |
| Попытка сменить уже заданную валюту счёта | API | HTTP 409, `bank_account_currency_immutable` |
| Несуществующее домохозяйство | API | HTTP 404, как в FIN-240 |
| Прочие ошибки создания или изменения счёта FIN-36, FIN-292, FIN-339 | API | без изменения |
| HTTP status не равен 200, включая прочие `2xx` | MCP | `RuntimeError` с телом API |
| Transport / network | HTTP-клиент | исключение без дополнительной обёртки |

- Мягкий ответ вида `{ "ok": false }` без исключения не используется.
- MCP не вводит собственных кодов ошибок валюты счёта.
- Обёртка MCP при ошибочном HTTP-ответе поднимает `RuntimeError` и сохраняет тело API, включая `error.code`.
- Обёртка MCP не разбирает `error.code`, чтобы выбрать иной исход, кроме ошибки инструмента.
- Функциональные тесты проверяют код HTTP и поле `error.code` в сохранённом теле API.
- Поле `error.message` служит диагностическим текстом для человека.

#### Пример `bank_account_currency_immutable`

```json
{
  "error": {
    "code": "bank_account_currency_immutable",
    "message": "Валюта банковского счёта не изменяется."
  }
}
```

### Обратная совместимость (D-09)

- Вызов `upsert_bank_account` без ключа валюты счёта сохраняет прежнюю семантику записи прочих полей FIN-240, FIN-293 и FIN-321.
- Создание нового счёта без валюты счёта после FIN-339 невозможно и через MCP отклоняется ответом HTTP.
- Добавление ключа валюты счёта в успешный ответ списка и создания или изменения является расширением тела.
- Вызывающая сторона MCP, которая неизвестные ключи ответа игнорирует, продолжает разбирать прежние поля.
- Схема `upsert_bank_account` не получает новых обязательных аргументов.
- Запрет записи идентификаторов через `upsert_bank_account` из FIN-321 сохраняется.
- Контракт HTTP FIN-339 этой задачей не меняется.

### Инварианты (D-10)

- После успешного списка у каждого элемента есть ключ валюты счёта.
- После успешного создания или изменения в объекте `bank_account` есть ключ валюты счёта.
- После успешного создания значение ключа равно нормализованному коду из HTTP.
- После успешного однократного заполнения значение ключа равно нормализованному коду из HTTP.
- После ошибки создания или изменения ни одно поле банковского счёта не сохраняет новых значений.
- Атомарность обеспечивает HTTP FIN-339.
- MCP при ошибке HTTP не считает операцию успешной.
