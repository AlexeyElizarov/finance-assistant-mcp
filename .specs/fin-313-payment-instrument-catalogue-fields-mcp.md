# MCP для полей каталога платёжного инструмента

**Статус:** Утверждено (2026-08-19, rev.3).

## Назначение

- Операторам нужно вести расчётный класс, несекретный фрагмент номера, срок истечения и период действия экземпляра через инструменты MCP в той же семантике, что в справочнике.
- Сейчас инструменты MCP принимают и возвращают только контракт FIN-286 и
 не умеют записать эти признаки каталога без прямого HTTP.

## Критерий приёмки

- Создание, чтение списка, чтение по идентификатору и частичное обновление платёжного инструмента через MCP принимают и возвращают расчётный класс, несекретный фрагмент номера, срок истечения и период действия экземпляра согласно целевому поведению.
- Одиночные и пакетные операции создания и частичного обновления проводят тот же набор полей.
- Недопустимые значения новых полей и недопустимый период действия дают ошибку инструмента с кодом ошибки API.
- Вызов без новых полей каталога остаётся успешным, если выполнены остальные инварианты.
- Полный номер карты в аргументах инструментов отсутствует и не сохраняется.
- Справочник доступных инструментов MCP обновлён.
- Поведение покрыто функциональным тестированием.

## Объём и границы

### Входит в объём

#### Возможности

- В объём входит расширение существующих инструментов MCP платёжных инструментов полями каталога из FIN-312.
- В объём входит чтение новых полей в успешных ответах списка, чтения по идентификатору, создания и частичного обновления.
- В объём входит запись новых полей при создании одной записи, пакетном создании, частичном обновлении одной записи и пакетном частичном обновлении.
- В объём входит согласование начала и конца периода действия экземпляра с FIN-312 на тех же инструментах.
- В объём входит проброс доменных ошибок новых полей в ошибку инструмента без потери кода ошибки.

#### Артефакты приёмки

- В объём входят схемы и обработчики инструментов MCP платёжных инструментов.
- В объём входят правки тонких обёрток над HTTP API платёжных инструментов.
- В объём входят функциональные тесты.
- В объём входит обновление справочника доступных инструментов MCP.

### Не входит в объём

#### Зависимости и соседние возможности

- Не входят модель, миграция схемы и слой сохранения полей каталога (FIN-311).
- Не входит проектирование HTTP-контракта полей каталога (FIN-312).
- Не входит пользовательский интерфейс ведения справочника (FIN-287).
- Не входит начальное заполнение каталога на постоянных профилях (FOPS-29).
- Не входят правила дат сопоставления средства с фондом в инструментах MCP (FIN-286).
- Не входят новые инструменты MCP и новый ресурс HTTP.

#### Не планируется

- Не входит поиск списка по расчётному классу, фрагменту номера или сроку истечения.
- Не входит поле `product_class`.
- Не входит поле `card_product`.
- Не входит значение предоплаты как расчётный класс.
- Не входит приём полного номера карты.
- Не входит изменение семантики удаления записи справочника.
- Не входит изменение инструментов сопоставления средства с фондом.

## Факт реализации (до)

| Область | Текущее поведение | Проблема |
| ------- | ----------------- | -------- |
| HTTP | FIN-312: поля каталога и необязательный период действия | Значения не доходят до MCP |
| Создание MCP | Начало периода обязательно; новых полей нет | Нельзя создать строку каталога через MCP |
| Частичное обновление MCP | Новых полей нет; начало периода нельзя снять через `null` | Нельзя выровнять интервал с FIN-312 |
| Ответ MCP | Объект FIN-286 без расчётного класса, фрагмента номера и срока истечения | Оператор не читает каталог через MCP |
| Сопоставления | Контракт FIN-286 без изменений | Вне этой задачи |

## Обратная совместимость

- Имена существующих инструментов MCP платёжных инструментов не меняются.
- Обязательные поля создания `bank_account_id`, `display_name` и `instrument_type` сохраняют прежнюю обязательность.
- Вызов создания с началом периода действия по контракту FIN-286 по-прежнему допускается.
- Вызов частичного обновления без новых ключей не меняет сохранённые значения новых полей.
- Инструменты сопоставления средства с фондом не меняются.
- Клиенты, которые не читают новые ключи ответа, продолжают разбирать прежние поля.
- Тип начала периода действия во входе создания расширяется: ключ становится необязательным и допускает JSON `null`.
- Вызов с незаявленным аргументом у инструментов создания, чтения и частичного обновления отклоняется схемой.
- Элемент пакетного частичного обновления без изменяемых полей даёт `ValueError` до HTTP.

## Целевое поведение

### Набор инструментов (D-01)

- Набор инструментов MCP платёжных инструментов совпадает с FIN-286.
- Эта задача не добавляет инструменты и не убирает инструменты.
- Операции удаления одной записи и пакетного удаления не меняют семантику FIN-286.
- Инструменты сопоставления средства с фондом не меняются.
- Новые поля каталога входят в уже существующие инструменты создания, чтения и частичного обновления.
- Полный набор CRUD этой задачей не достраивается: расширяется уже существующая поверхность.

### Конвейер (D-02)

```
1. получить сессию API (профиль данных, базовый URL)
2. проверить аргументы MCP до HTTP
3. собрать путь, параметры запроса и тело
4. выполнить вызов метода GET, POST, PATCH или DELETE
5. для успешных кодов ответа выполнить обработку согласно контракту FIN-312:
   - 200 / 201 — ожидать тело и обернуть сущность или коллекцию в конверт ok / profile / base
   - 204 — тело отсутствует; вернуть только конверт ok / profile / base
6. иначе вернуть ошибку инструмента с телом ответа API
7. сетевые сбои пробросить без дополнительной обёртки
```

- Порядок шагов фиксирован.
- Методы `GET`, `POST` и `PATCH` в этом конвейере меняются только составом полей каталога.
- Метод `DELETE` приведён для полноты существующего конвейера FIN-286.
- Изменение реализации удаления этой задачей не требуется.
- Успех операции определяется кодом HTTP, а не наличием или отсутствием тела в ответе.
- Доменные инварианты FIN-311 и FIN-312 в MCP не дублируются.

### Тело ответа (D-03)

#### Состав

- Успешное создание, чтение по идентификатору и частичное обновление возвращают полный объект инструмента из ответа HTTP.
- Успешный список и успешное пакетное создание и пакетное обновление возвращают те же объекты в прежних обёртках FIN-286.
- MCP не отбрасывает ключи каталога из тела HTTP.
- MCP не переименовывает ключи каталога из тела HTTP.
- Поле `profile_id` в объект инструмента не добавляется.
- Поле `household_id` в объект инструмента не добавляется.

#### Поля

| Поле | Описание | Норма |
| ---- | -------- | ----- |
| `id` | Идентификатор | UUID, выданный при создании; неизменяем |
| `bank_account_id` | Банковский счёт | Как в FIN-286; неизменяем после создания |
| `display_name` | Отображаемое имя | Непустая строка после обрезки пробелов |
| `instrument_type` | Тип инструмента | Технический код; неизменяем после создания |
| `payment_network` | Платёжная сеть | `null` или технический код |
| `settlement_class` | Расчётный класс | `null`, `debit` или `credit` |
| `pan_last4` | Несекретный фрагмент номера | `null` или ровно четыре десятичные цифры ASCII |
| `holder_id` | Держатель | `null` или идентификатор члена домохозяйства счёта |
| `valid_from` | Начало периода действия экземпляра | `null` или календарный месяц `YYYY-MM` |
| `valid_to` | Конец периода действия экземпляра | `null` или календарный месяц `YYYY-MM` |
| `issuer_expiry` | Срок истечения | `null` или календарный месяц `YYYY-MM` |
| `created_at` | Время создания | ISO-8601 UTC с суффиксом `Z` |
| `updated_at` | Время обновления | ISO-8601 UTC с суффиксом `Z` |

- Ключи `settlement_class`, `pan_last4` и `issuer_expiry` присутствуют в успешном объекте ответа всегда.
- Если значение в HTTP равно JSON `null`, тот же ключ в ответе инструмента равен JSON `null`.
- Имена `product_class` и `card_product` в ответ не входят.
- Допустимые сохранённые значения и коды ошибок совпадают с FIN-312.
- Обрезка пробелов и перевод пустой строки в `null` выполняются HTTP по FIN-312.
- MCP не вводит вторую нормализацию поверх HTTP.

#### Пример

```json
{
  "ok": true,
  "profile": "cand",
  "base": "http://127.0.0.1:8001",
  "payment_instrument": {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "bank_account_id": "acc-c24",
    "display_name": "C24 Mastercard Алексей",
    "instrument_type": "card",
    "payment_network": "mastercard",
    "settlement_class": "debit",
    "pan_last4": "4242",
    "holder_id": "aleksey",
    "valid_from": "2026-07",
    "valid_to": null,
    "issuer_expiry": "2029-08",
    "created_at": "2026-08-09T10:00:00Z",
    "updated_at": "2026-08-09T10:00:00Z"
  }
}
```

### Полный номер карты (D-04)

- Аргумент полного номера карты в схемах инструментов отсутствует.
- MCP не извлекает четыре цифры из более длинной строки.
- MCP не усекает более длинную строку до четырёх цифр.
- Единственным полем фрагмента номера во входном и выходном контрактах является `pan_last4`.
- Формат заданного фрагмента номера проверяет HTTP по FIN-312.
- Полный номер карты в поле фрагмента номера даёт ошибку инструмента с кодом ошибки `validation_error` и не сохраняется.
- Отдельный код ошибки MCP для полного номера карты не вводится.

### Создание (D-05)

#### Вход

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; по умолчанию `prod` |
| `base` | string | нет | Базовый URL API; по умолчанию из сессии |
| `bank_account_id` | string | да | Банковский счёт |
| `display_name` | string | да | Отображаемое имя |
| `instrument_type` | string | да | Тип инструмента |
| `payment_network` | string \| null | нет | Платёжная сеть |
| `settlement_class` | string \| null | нет | Расчётный класс |
| `pan_last4` | string \| null | нет | Несекретный фрагмент номера |
| `holder_id` | string \| null | нет | Держатель |
| `valid_from` | string \| null | нет | Начало периода действия экземпляра |
| `valid_to` | string \| null | нет | Конец периода действия экземпляра |
| `issuer_expiry` | string \| null | нет | Срок истечения |

- Поле идентификатора инструмента в аргументах создания не передаётся.
- Начало периода действия больше не входит в обязательные аргументы.
- Конец периода действия остаётся необязательным.
- Обязательный конец периода из отменённой FIN-316 в эту задачу не входит.

#### Отсутствие значения

- Ключ, отсутствующий в аргументах, не попадает в JSON тела запроса.
- Ключ, переданный со значением `null`, уходит в JSON как `null`.
- Реализация сохраняет различие между отсутствующим аргументом и явно переданным JSON `null`.
- Способ технического представления этого различия спецификацией не определяется.
- Значение по умолчанию параметра в коде не смешивает «ключ не передан» и «ключ передан со значением `null`».
- MCP передаёт необязательные строковые поля тела без преобразования в `null`.
- Пустая строка и строка из одних пробелов уходят в HTTP как строки.
- Нормализацию пустой строки и строки из одних пробелов в `null` выполняет HTTP API согласно FIN-312.
- Необязательные строковые поля этой нормы: платёжная сеть, расчётный класс, фрагмент номера, держатель, начало периода действия, конец периода действия, срок истечения.

#### Пример

```json
{
  "bank_account_id": "acc-c24",
  "display_name": "C24 Mastercard Алексей",
  "instrument_type": "card",
  "payment_network": "mastercard",
  "settlement_class": "debit",
  "pan_last4": "4242",
  "holder_id": "aleksey",
  "valid_from": "2026-07",
  "valid_to": null,
  "issuer_expiry": "2029-08"
}
```

#### Результат

- Успешное создание соответствует ответу API с кодом HTTP 201.
- При успехе ответ инструмента содержит `ok: true` и объект `payment_instrument` с выданным идентификатором.
- Тело объекта следует D-03.

### Частичное обновление (D-06)

#### Изменяемые поля

- Частичное обновление допускает изменение следующих полей: отображаемое имя, платёжная сеть, расчётный класс, фрагмент номера, держатель, начало периода действия, конец периода действия, срок истечения.
- Хотя бы одно из этих полей должно присутствовать в аргументах.
- Отсутствующий ключ не попадает в JSON тела и не меняет сохранённое значение.
- JSON `null` для необязательного поля снимает сохранённое значение.
- Необязательные поля этой нормы: платёжная сеть, расчётный класс, фрагмент номера, держатель, начало периода действия, конец периода действия, срок истечения.
- Начало периода действия во входе допускает JSON `null`.
- Отображаемое имя нельзя снять через JSON `null`.
- Переданный ключ `display_name` после `strip` должен быть непустым.
- Пустая строка и строка из одних пробелов в `display_name` дают `ValueError` до HTTP.

#### Вход

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; по умолчанию `prod` |
| `base` | string | нет | Базовый URL API; по умолчанию из сессии |
| `instrument_id` | string | да | Идентификатор инструмента в пути |
| `display_name` | string | условно | Новое отображаемое имя |
| `payment_network` | string \| null | условно | Новая сеть; `null` снимает значение |
| `settlement_class` | string \| null | условно | Новый расчётный класс; `null` снимает значение |
| `pan_last4` | string \| null | условно | Новый фрагмент номера; `null` снимает значение |
| `holder_id` | string \| null | условно | Новый держатель; `null` снимает значение |
| `valid_from` | string \| null | условно | Новое начало; `null` снимает значение |
| `valid_to` | string \| null | условно | Новый конец; `null` снимает значение |
| `issuer_expiry` | string \| null | условно | Новый срок истечения; `null` снимает значение |

#### Проверка периода действия

- Проверку итогового интервала после наложения выполняет HTTP по FIN-312.
- MCP не собирает сохранённые границы и не проверяет «конец раньше начала» до HTTP.

#### Запрещённые и незаявленные ключи

- Ключи `id`, `bank_account_id`, `instrument_type`, `household_id`, `created_at` и `updated_at` в аргументах частичного обновления одной записи не входят в схему изменяемых полей.
- Для пакетного обновления ключ `id` обязателен у элемента и задаёт целевую запись.
- Незаявленные аргументы отклоняются схемой по D-09.

#### Результат

- Успешное обновление соответствует ответу API с кодом HTTP 200.
- При успехе ответ инструмента содержит `ok: true` и объект `payment_instrument` по D-03.
- Пустой набор изменяемых полей даёт `ValueError` до HTTP.

### Список и чтение (D-07)

- Фильтры списка совпадают с FIN-286: банковский счёт и домохозяйство.
- Параметры списка `pan_last4`, `settlement_class` и `issuer_expiry` в схему инструмента не входят.
- Передача этих параметров отклоняется схемой по D-09.
- Каждый элемент списка содержит ключи из D-03.
- Успешное чтение по идентификатору возвращает объект по D-03.
- Пустой список допустим и сохраняет `ok: true`.

### Пакетные операции (D-08)

- Пакетное создание принимает те же поля элемента, что и создание одной записи.
- Пакетное частичное обновление принимает те же изменяемые поля элемента, что и частичное обновление одной записи.
- У каждого элемента пакетного обновления после обрезки пробелов непуст идентификатор `id`.
- Каждый элемент пакетного частичного обновления содержит хотя бы одно изменяемое поле из D-06.
- Отсутствие изменяемого поля у элемента пакета даёт `ValueError` без вызова API.
- Схема элемента пакета не допускает незаявленные свойства по D-09.
- MCP не реализует собственную атомарность и не агрегирует ошибки.
- Атомарность пакета наследуется из FIN-312.
- Успешный элемент пакета в ответе содержит ключи из D-03.

### Валидация до HTTP (D-09)

#### Схема аргументов

- Тип аргумента проверяет схема MCP.
- Обработчик не дублирует проверку типов.
- Схемы инструментов создания, чтения списка, чтения по идентификатору и частичного обновления не допускают незаявленные свойства.
- Схемы элементов пакетного создания и пакетного частичного обновления не допускают незаявленные свойства.
- Незаявленный аргумент отклоняется схемой MCP до HTTP.
- Код ошибки API у отклонения схемой отсутствует.

#### Пустые строки

- Норма передачи пустой строки и строки из одних пробелов совпадает с D-05.
- Необязательные строковые поля тела, если переданы, правилом непустой строки не ограничиваются.
- Отображаемое имя в этот перечень необязательных полей не входит.
- Переданный ключ `display_name` после `strip` должен быть непустым при создании и при частичном обновлении.

#### Обязательность и присутствие ключей

- После `strip` должны быть непустыми: обязательные строковые параметры, строковые идентификаторы пути и элементов пакета, а также переданные строковые фильтры списка.
- Для частичного обновления одного инструмента присутствует хотя бы один из ключей: `display_name`, `payment_network`, `settlement_class`, `pan_last4`, `holder_id`, `valid_from`, `valid_to`, `issuer_expiry`.
- Для пакетного создания присутствует непустой список элементов `payment_instruments`.
- Для пакетного обновления присутствует непустой список элементов.
- Каждый элемент пакетного частичного обновления содержит `id` и хотя бы один из ключей изменяемых полей из D-06.
- Нарушение правил до HTTP даёт `ValueError` без вызова API.
- Формат UUID, формат фрагмента номера, допустимые коды расчётного класса, формат календарного месяца и доменные инварианты проверяет только HTTP API.

### Инварианты (D-10)

- MCP не ослабляет инварианты HTTP API FIN-312.
- MCP не ужесточает инварианты HTTP API FIN-312.
- Тело запроса содержит только явно переданные ключи аргументов.
- Реализация сохраняет различие между отсутствующим аргументом и явно переданным JSON `null`.
- Способ технического представления этого различия спецификацией не определяется.
- Ответ REST не нормализуется: только конверт `ok` / `profile` / `base` и ключ сущности или коллекции.
- Расчётный класс не подменяет тип инструмента и не подменяет платёжную сеть.
- Срок истечения не участвует в определении, активен ли экземпляр в месяце.

### Ошибки (D-11)

#### Ошибки до HTTP

- Нарушение правил D-09 даёт `ValueError`.
- API при этом не вызывается.
- Незаявленный аргумент отклоняется схемой MCP.
- Код ошибки API у отклонения схемой и у `ValueError` отсутствует.

#### Ошибки HTTP API

| Ситуация | HTTP | `error.code` | Сообщение |
| -------- | ---- | ------------ | --------- |
| Расчётный класс задан и не равен `debit` или `credit`, фрагмент номера задан и не равен ровно четырём десятичным цифрам ASCII, срок истечения задан и не является календарным месяцем, невалидный UUID, конфликт фильтров списка, повтор идентификатора в пакете | 422 | `validation_error` | Ошибка валидации входных данных. |
| Недопустимый формат месяца периода действия или конец периода раньше начала после наложения на сохранённое состояние | 422 | `invalid_validity_interval` | Недопустимый интервал действия. |
| Держатель не из домохозяйства счёта | 422 | `holder_invalid` | Держатель не принадлежит домохозяйству счёта. |
| Инструмент не найден | 404 | `payment_instrument_not_found` | Платёжный инструмент не найден. |
| Банковский счёт не найден | 404 | `bank_account_not_found` | Банковский счёт не найден. |
| Список с фильтром по домохозяйству, которого нет в профиле | 404 | `household_not_found` | Домохозяйство не найдено. |

- Ответ API с кодом, отличным от успеха операции, даёт исключение, создаваемое `format_api_error`.
- Код ошибки API в этом исключении сохраняется.
- Мягкий ответ вида `{ "ok": false }` без исключения не используется.
- Новых кодов ошибок эта задача не вводит.
- Коды удаления и сопоставления с фондом из FIN-286 не меняются.
