# Сумма и валюта движения в MCP

**Статус:** Утверждено (2026-08-26, rev.4).

## Назначение

- Операторы не видят сумму движения и валюту движения в выборке и чтении операций через MCP, хотя HTTP уже отдаёт эти поля.
- Нужно отдавать пару движения без пересчёта и без подстановки.
- Общий механизм `process_month` должен сохранять доменные коды FIN-346 и `error.details` без специальной интерпретации.

## Критерий приёмки

- Чтение операций через MCP возвращает сумму движения и валюту движения согласно целевому поведению.
- Успешный ответ частичного обновления операции и фасада классификации через MCP содержит ту же пару движения.
- Общий механизм журнала импорта в `process_month` сохраняет доменные коды FIN-346 и `error.details` без молчаливой подстановки и без продолжения конвейера.
- Справочник доступных инструментов MCP обновлён.
- Поведение покрыто функциональными тестами.

## Объём и границы

### Входит в объём

#### Возможности

- В объём входит расширение выборки операций парой движения на заголовке.
- В объём входит чтение пары движения в ответе чтения операции.
- В объём входит возврат пары движения в успешном ответе частичного обновления операции.
- В объём входит возврат пары движения в успешном ответе фасада классификации операции.
- В объём входит подтверждение, что общий журнал импорта `process_month` не теряет доменные коды записи пары движения из FIN-346.
- В объём входит отклонение ключей пары движения во входе частичного обновления и фасада классификации схемой MCP до HTTP.

#### Артефакты приёмки

- В объём входят схемы и обработчики существующих инструментов выборки, чтения операции, частичного обновления, фасада классификации и обработки месяца.
- В объём входят модули тонких обёрток этих инструментов.
- В объём входят автотесты с имитацией HTTP для регрессии.
- В объём входит обновление справочника доступных инструментов MCP.
- После закрытия задачи label `mcp-gap` снимается с FIN-347.

### Не входит в объём

#### Зависимости и соседние возможности

- Не входят модель, миграция схемы и слой сохранения суммы и валюты движения (FIN-345).
- Не входит программный интерфейс HTTP суммы и валюты движения (FIN-346).
- Не входит отображение суммы и валюты движения в пользовательском интерфейсе (FIN-348).
- Не входит провайдер T-Bank и маппинг колонок выписки на пару движения (FIN-167).
- Не входят мультивалютность факта и план и факт из сумм в валюте бюджета (FIN-170, FIN-335, FIN-336).

#### Не планируется

- Не входит новый инструмент списка, чтения или записи операций.
- Не входит фильтр выборки операций по сумме движения или валюте движения.
- Не входит запись суммы движения или валюты движения через частичное обновление или фасад классификации.
- Не входит пара движения на позициях операции и в инструментах чтения или замены позиций.
- Не входит изменение агрегата плана и факта и строк расшифровки: сумма движения не является суммой факта.
- Не входит отдельный маршрут создания операции через MCP.
- Не входит восстановление отсутствующей пары движения на слое MCP.
- Не входит унификация типа существующего поля суммы операции между инструментами MCP.
- Не входят имена полей `account_amount` и `account_currency`.

## Целевое поведение

### Паритет поверхности (D-01)

- Набор инструментов операций не расширяется и не сужается.
- Эта задача не добавляет инструмент создания операции.
- Норма полного набора CRUD для нового ресурса к этой задаче не применяется.
- Эта задача расширяет уже существующие инструменты полями уже существующего HTTP-контракта FIN-346.
- Поверхность плана и факта этой задачей не меняется.
- Фасад классификации возвращает пару движения: паритет с ответом HTTP FIN-346 на этом пути.

| Инструмент MCP | Операция HTTP | Что меняется |
| -------------- | ------------- | ------------ |
| `query_transactions` | `GET /api/v1/transactions` | Пара движения в каждой неагрегированной строке |
| `get_transaction` | `GET /api/v1/transactions/{transaction_id}` | Пара движения в заголовке |
| `put_transaction` | `PATCH /api/v1/transactions/{transaction_id}` | Пара движения в ответе; вход её не принимает |
| `put_transaction_category` | `PATCH /api/v1/transactions/{transaction_id}/category` | Пара движения в ответе; вход её не принимает |
| `process_month` | `POST /api/v1/import` | Общий журнал импорта сохраняет доменные коды FIN-346 и `error.details` без специальной интерпретации |

- Доменные правила суммы и валюты движения наследуются из FIN-345 и FIN-346 без дублирования формулы в MCP.

### Конвейер (D-02)

```
1. получить сессию API (профиль данных, базовый URL)
2. проверить аргументы MCP до HTTP, если инструмент это уже делает
3. выполнить существующий вызов HTTP без новых маршрутов
4. при ожидаемом коде HTTP успеха сформировать ответ с парой движения согласно D-04…D-06
5. иначе вернуть ошибку инструмента с телом ответа API
6. сетевые сбои пробросить без дополнительной обёртки
```

- Порядок шагов совпадает с существующими обработчиками этих инструментов.
- MCP не пересчитывает сумму движения и не подставляет снимок с суммы операции.
- Если ключ пары движения в ответе HTTP отсутствует, MCP отдаёт JSON `null` по правилам D-04…D-06 и не подставляет значение из `amount` или `currency`.

### Модули и регистрация (D-03)

- Расширение выборки выполняется в существующем `scripts/query-transactions.py` и в обработчике `query_transactions`.
- Возврат полей заголовка частичного обновления выполняется в существующем `scripts/put_transaction.py`.
- Возврат полей заголовка фасада классификации выполняется в существующем `scripts/put_transaction_category.py`.
- Обеспечение ключей пары движения при чтении операции выполняется в существующем `scripts/get_transaction.py`.
- Журнал ошибок импорта выполняется в существующем `scripts/monthly_close_lib.py`.
- Изменение `monthly_close_lib.py` требуется только если существующий механизм не проходит зафиксированные автотесты проброса `error.code` и `error.details`; допустим результат без изменения production-кода журнала.
- Справочник доступных инструментов обновляется в `mcp-gaps.md`.

### Выборка операций (D-04)

#### Состав неагрегированной строки

- Неагрегированная строка всегда содержит ключ суммы движения (`posted_amount`).
- Неагрегированная строка всегда содержит ключ валюты движения (`posted_currency`).

| Поле | Описание | Норма |
| ---- | -------- | ----- |
| `amount` | Сумма операции | Уже есть; семантика и тип не меняются; сумма движения её не заменяет |
| `currency` | Валюта операции | Уже есть по FIN-336; семантика не меняется |
| `posted_amount` | Сумма движения | Значение `posted_amount` из HTTP без преобразования; если ключ в HTTP отсутствует, JSON `null` |
| `posted_currency` | Валюта движения | Значение `posted_currency` из HTTP без преобразования; если ключ в HTTP отсутствует, JSON `null` |

- По контракту FIN-346 `posted_amount` в HTTP — строковое десятичное представление; ответственность за формат остаётся у HTTP.
- MCP не валидирует и не переформатирует эти значения.
- Пустая строка для этих ключей в ответе MCP не используется, если HTTP отдал JSON `null`.
- FIN-347 не унифицирует тип существующего `amount`; `posted_amount` во всех изменяемых ответах копируется из HTTP как есть.
- Сумма движения в строке выборки не приводится к числу с плавающей точкой поля `amount`.
- Фильтры выборки не меняются.

#### Агрегация по месяцу

- Агрегация по месяцу сохраняет прежнюю семантику суммы поля `amount`.
- Агрегация по месяцу не разбивает группы по валюте движения.
- Агрегированная строка `query_transactions` не содержит ключи `posted_amount` и `posted_currency`.

#### Пример неагрегированной строки

```json
{
  "id": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee",
  "date": "15.07.2026",
  "amount": 10.0,
  "indicator": "D",
  "category": "C0001",
  "transaction_type": "C",
  "expense_owner": null,
  "fund_id": null,
  "provider": "tbank",
  "description": "Card purchase EUR from RUB account",
  "currency": "EUR",
  "budget_currency": "EUR",
  "planned_rate": null,
  "posted_amount": "950.00",
  "posted_currency": "RUB"
}
```

### Чтение операции (D-05)

- Успешный `get_transaction` всегда включает ключи `posted_amount` и `posted_currency` в объекте операции.
- Если HTTP вернул ключ, MCP копирует его значение без изменения.
- Если ключ в HTTP отсутствует, MCP отдаёт JSON `null` для этого ключа.
- MCP не отбрасывает присутствующие ключи пары движения и не подставляет снимок с `amount` или `currency`.
- Пара движения относится только к заголовку: позиции операции собственных ключей пары движения не получают.
- MCP не вычисляет эти поля заново.
- Тип существующего `amount` в теле HTTP этой задачей не меняется.

#### Пример фрагмента операции

```json
{
  "ok": true,
  "profile": "cand",
  "base": "http://127.0.0.1:8000",
  "transaction": {
    "id": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee",
    "amount": "10.00",
    "currency": "EUR",
    "posted_amount": "950.00",
    "posted_currency": "RUB",
    "budget_currency": "EUR",
    "planned_rate": null
  }
}
```

### Частичное обновление и фасад классификации (D-06)

#### Вход частичного обновления

- Схема `put_transaction` не объявляет аргументы `posted_amount` и `posted_currency`.
- Незаявленные аргументы верхнего уровня по-прежнему отклоняются схемой MCP до HTTP.
- HTTP при таком входе не вызывается.

#### Вход фасада классификации

- Схема `put_transaction_category` не объявляет аргументы `posted_amount` и `posted_currency`.
- Незаявленные аргументы верхнего уровня по-прежнему отклоняются схемой MCP до HTTP.

#### Ответ

- Белый список ответа `put_transaction` дополняется ключами `posted_amount` и `posted_currency`.
- Белый список ответа `put_transaction_category` дополняется ключами `posted_amount` и `posted_currency`.
- Если ключ отсутствует в HTTP, в успешном ответе MCP значение равно JSON `null`.
- `posted_amount` в этих ответах копируется из HTTP без преобразования.

### Ошибки записи (D-07)

- FIN-347 не вводит отдельную обработку кодов пары движения на слое MCP.
- Общий механизм `process_month` копирует любой `error.code` и `error.details` из ответа импорта; коды FIN-346 этим механизмом не теряются.
- Перечень кодов ниже иллюстрирует доменные коды FIN-346, которые должны остаться видимыми в журнале; специальной ветки по каждому коду нет.

| Ситуация | Источник | Поведение |
| -------- | -------- | --------- |
| Импорт месяца отвечает кодом HTTP 422 и любым доменным кодом пары движения из FIN-346 | API | `process_month` возвращает `ok` равный `false`; конвейер не продолжается; журнал содержит код ошибки и `error.details` как есть |
| Аргумент `posted_amount` или `posted_currency` во входе `put_transaction` | MCP до HTTP | отклонение схемой MCP; HTTP не вызывается |
| Аргумент `posted_amount` или `posted_currency` во входе `put_transaction_category` | MCP до HTTP | отклонение схемой MCP; HTTP не вызывается |
| Прочие ошибки частичного обновления и классификации | API | без изменения формы ошибки инструмента |
| HTTP status чтения не равен 200 | MCP | `RuntimeError` с телом API |
| Transport / network | HTTP-клиент | исключение без дополнительной обёртки |

- К доменным кодам пары движения FIN-346 относятся: `posted_amount_required`, `posted_pair_incomplete`, `posted_currency_mismatch`, `posted_source_currency_undefined`.
- MCP не вводит собственных кодов ошибок пары движения.
- MCP не подставляет пару движения и не пропускает импорт после этих кодов.
- Форма останова `process_month` через `ok` равный `false` и журнал сохраняется.
- Журнал импорта копирует `error.code` в ключ `error_code` и `error.details` в ключ `error_details`, если они есть в теле HTTP.
- Копирование `error_details` не зависит от кода ошибки и не разбирает содержимое объекта.
- Обёртки чтения и частичного обновления не разбирают `error.code`, чтобы выбрать иной исход, кроме ошибки инструмента.
- Отказ HTTP с кодом 422 и кодом ошибки `validation_error` при ключе пары движения во входном теле частичного обновления остаётся контрактом FIN-346 и через MCP не воспроизводится, потому что схема отклоняет ключ до HTTP.

#### Пример фрагмента журнала импорта

```json
{
  "ok": false,
  "log": {
    "imports": [
      {
        "provider": "tbank",
        "status": 422,
        "error_code": "posted_amount_required",
        "error_details": {}
      }
    ]
  }
}
```

### Обратная совместимость (D-08)

- Вызов `query_transactions` без опоры на новые ключи сохраняет прежние поля строки и прежние фильтры.
- Добавление ключей пары движения в строку выборки и в успешные ответы частичного обновления и фасада классификации является расширением тела.
- Вызывающая сторона, которая неизвестные ключи ответа игнорирует, продолжает разбирать прежние поля этих инструментов.
- Агрегация выборки по месяцу не меняется и не получает ключи пары движения.
- Схемы инструментов не получают новых обязательных аргументов.
- Контракт HTTP FIN-346 этой задачей не меняется.
- План и факт через `query_plan_fact` не меняется.

### Инварианты (D-09)

- После успешной неагрегированной выборки у каждой строки есть ключи `posted_amount` и `posted_currency`.
- После успешного чтения операции в объекте операции есть ключи `posted_amount` и `posted_currency`.
- После успешного частичного обновления и успешного фасада классификации в объекте `transaction` есть те же ключи.
- Агрегированная строка выборки не содержит эти ключи.
- Сумма операции (`amount`) не подменяется суммой движения.
- MCP не считает чтение успешным при коде HTTP, отличном от ожидаемого успеха инструмента.
