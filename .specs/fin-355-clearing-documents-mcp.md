# MCP-инструменты документов выравнивания

**Статус:** Утверждено (2026-09-04, rev.4).

## Назначение

- Ops на пути только через MCP не могут создать, прочитать, перечислить, частично обновить или удалить документ выравнивания и вести строки его состава.
- Нужна MCP-поверхность над уже утверждённым HTTP-ресурсом документов выравнивания FIN-354.

## Входит в объём

- Список документов выравнивания.
- Чтение одного документа по идентификатору.
- Создание одного документа выравнивания.
- Пакетное создание документов выравнивания.
- Частичное обновление заголовка, включая статус.
- Удаление одного документа.
- Пакетное удаление документов.
- Создание, список, чтение, частичное обновление и удаление строки состава.
- Чтение сохранённой записи документа и строки состава в том виде, в каком её возвращает HTTP.

## Вне объёма

- Не входят модель данных, DDL и инварианты одиночных операций слоя сохранения (FIN-353).
- Не входит проектирование HTTP-контракта документов выравнивания (FIN-354).
- Не входит пользовательский интерфейс денежного требования (FIN-356).
- Не входят существующие инструменты сопоставления сторон внутреннего перевода (FIN-351).
- Не входит перенацеливание инструментов FIN-351 на HTTP документов выравнивания (FIN-380). Наличие универсальных инструментов этой задачи FIN-380 не блокирует.
- Не входят инструменты погашения расхода (FIN-271).
- Не входит замена или снятие промежуточного журнала дебиторской задолженности (FIN-116).
- Не входят чтение непогашенного остатка, погашенной суммы, вложенных погашений и совокупной дебиторской задолженности (FIN-385).
- Не входят пакетное частичное обновление документов и пакетные операции над строками состава (FIN-386).
- Не входят отдельные инструменты закрытия, отмены закрытия и связывания позиции как предметные глаголы.

## Текущее поведение

| Область | Текущее поведение | Проблема |
| ------- | ----------------- | -------- |
| HTTP | FIN-354 редакция 17: CRUD документов выравнивания обоих типов и строк состава на `/api/v1/clearing-documents` | Ops на пути только через MCP этот ресурс не вызывают |
| MCP | Инструментов документа выравнивания нет; сопоставление сторон внутреннего перевода обслуживается FIN-351; есть промежуточный журнал `household_receivables` (FIN-116) | Журнал и старые пути сопоставления не являются MCP-паритетом HTTP FIN-354 |

## Целевое поведение

#### Набор инструментов (D-01)

- Эта задача вводит двенадцать инструментов MCP над публичной HTTP-поверхностью документов выравнивания FIN-354 редакции 17.
- Каждой операции HTTP этого ресурса соответствует отдельный инструмент с той же функциональной семантикой. MCP-сервер не исключает тип `internal_transfer` и не добавляет самостоятельные операции предметной области.

| Инструмент MCP | Операция HTTP | Смысл |
| -------------- | ------------- | ----- |
| `list_clearing_documents` | `GET /api/v1/clearing-documents` | Список |
| `get_clearing_document` | `GET /api/v1/clearing-documents/{document_id}` | Чтение документа |
| `create_clearing_document` | `POST /api/v1/clearing-documents` | Создание одного документа |
| `create_clearing_documents` | `POST /api/v1/clearing-documents/batch` | Пакетное создание |
| `patch_clearing_document` | `PATCH /api/v1/clearing-documents/{document_id}` | Частичное обновление заголовка |
| `delete_clearing_document` | `DELETE /api/v1/clearing-documents/{document_id}` | Удаление одного документа |
| `delete_clearing_documents` | `DELETE /api/v1/clearing-documents` | Пакетное удаление |
| `create_clearing_document_item` | `POST /api/v1/clearing-documents/{document_id}/items` | Создание строки состава |
| `list_clearing_document_items` | `GET /api/v1/clearing-documents/{document_id}/items` | Список строк состава |
| `get_clearing_document_item` | `GET /api/v1/clearing-documents/{document_id}/items/{item_id}` | Чтение строки состава |
| `patch_clearing_document_item` | `PATCH /api/v1/clearing-documents/{document_id}/items/{item_id}` | Частичное обновление строки состава |
| `delete_clearing_document_item` | `DELETE /api/v1/clearing-documents/{document_id}/items/{item_id}` | Удаление строки состава |

- Один инструмент с перечислением действия MCP-сервер не вводит.
- Идентификатор документа и идентификатор строки состава при создании задаёт слой сохранения. Клиент MCP ключи `id`, `profile_id` и `document_id` при создании не передаёт.
- Пакетное частичное обновление документов и пакетные операции над строками состава HTTP не вводит (FIN-386). MCP-сервер эти операции не добавляет.
- MCP-сервер не вводит инструменты чтения остатка, погашенной суммы, вложенных погашений, совокупной дебиторской задолженности, закрытия, отмены закрытия и связывания позиции как отдельные операции.
- Существующие инструменты FIN-351 эта задача не изменяет и не удаляет.
- Доменные правила тел, ветвей `document_type`, фильтров, атомарности пакетов, кодов ошибок и состава сохранённой записи принадлежат HTTP FIN-354 редакции 17. MCP-сервер эти правила не дублирует и не ослабляет.

#### Конвейер (D-02)

- Обработчик каждого инструмента этой задачи выполняет шаги в следующем порядке и останавливается на первом отказе:

1. Проверить аргументы по JSON Schema MCP (D-05).
2. Определить эффективные `profile` и `base` (D-04).
3. Выполнить проверки обработчика (D-06, D-07).
4. Собрать путь, параметры запроса и тело HTTP (D-07, D-12–D-23).
5. Выполнить вызов метода HTTP из таблицы D-01.
6. Разобрать исход по D-08.
7. При успехе обернуть тело по D-09. Иначе вернуть ошибку того класса, который определил D-08.

- Сетевой сбой обработчик пробрасывает без дополнительной обёртки формата API.
- Успех операции определяет точный код HTTP по D-12–D-23, а не любой код класса `2xx` и не наличие тела.
- Доменные инварианты типа документа обработчик MCP не повторяет.

#### Модуль и регистрация (D-03)

- Логика обёрток размещается в модуле `scripts/clearing_documents.py`.
- Схемы и обработчики двенадцати инструментов регистрируются в `server.py`.
- Справочник доступных инструментов обновляется в `mcp-gaps.md`.
- После поставки инструментов метка `mcp-gap` снимается с FIN-355.

#### Профиль данных и базовый URL (D-04)

- Необязательные аргументы `profile` и `base` есть у каждого инструмента этой задачи.
- Если ключ `profile` присутствует в аргументах, выбранная строка есть значение аргумента. Иначе если значение сессии есть, выбранная строка есть значение сессии, включая пустую строку и строку из одних пробелов. Иначе выбранная строка есть `prod`. К выбранной строке обработчик удаляет крайние символы `U+0020 SPACE`. Пустой результат даёт `ValueError` до HTTP. Непустой результат есть эффективное значение. Подстановка `prod` выполняется только при отсутствии значения сессии, не после удаления пробелов.
- Если ключ `base` присутствует в аргументах, выбранная строка есть значение аргумента. Иначе если значение сессии есть, выбранная строка есть значение сессии, включая пустую строку и строку из одних пробелов. Иначе возникает ошибка сессии до HTTP. К выбранной строке обработчик удаляет крайние символы `U+0020 SPACE`. Пустой результат даёт `ValueError` до HTTP. Непустой результат есть эффективное значение. Класс «Ошибка сессии» для `base` возникает только при отсутствии значения сессии, не после удаления пробелов.
- Если ключ `profile` или ключ `base` присутствует со значением JSON `null`, обработчик поднимает `ValueError` до HTTP.
- Аргумент имеет приоритет над значением сессии.
- Нормализация выбранной строки `profile` и `base` одинакова независимо от источника: аргумент или сессия.
- Эффективные `profile` и `base` используются при обращении к сессии, в вызове HTTP и в успешном ответе.

#### JSON Schema MCP (D-05)

- JSON Schema каждого инструмента задаёт `additionalProperties: false` в корне аргументов, в объектах элементов массива `clearing_documents` и в объектах элементов массива `items`.
- JSON Schema проверяет тип корневого объекта, тип каждого переданного заявленного ключа и тип каждого элемента переданных массивов.
- JSON Schema не задаёт `required`, `minItems` и `minLength`.
- JSON Schema создания одного документа и пакетного создания не выражает объединение `oneOf`, `anyOf`, `allOf` или дискриминатор по `document_type`. Схема допускает ключи обеих ветвей FIN-354 D-06: в корне — `document_type`, `creditor_subject_id`, `debtor_subject_id`, `clearing_currency` и `items`; в элементе `items` — `debit_credit_indicator`, `clearing_amount`, `clearing_date` и `line_id`. Отсутствие ключей одной ветви при переданном типе другой ветви схемой не отклоняется.
- Для каждого ключа из перечня D-07 JSON Schema допускает заявленный JSON-тип и JSON `null`. Это относится и к вложенным ключам того же имени в элементах `clearing_documents` и `items`.
- Исключения: ключ `allow_closed` имеет тип boolean без `null`; элемент массива `clearing_documents`, `ids` или `items` схемой как `null` не допускается.
- JSON Schema полей `document_type`, `status` и `debit_credit_indicator` принимает `string` или `null` и не задаёт `enum`. Допустимый строковый литерал проверяет HTTP FIN-354.
- Колонка «Обяз.» в таблицах D-12–D-23 означает обязательность для успешного вызова. Проверку выполняет обработчик по D-06.
- Незаявленный ключ даёт ошибку JSON Schema до обработчика. HTTP не вызывается. К незаявленным на создании относятся в том числе `id`, `profile_id`, `clearing_rate`, `remainder`, `settled_amount`, `origination`, `settlements` и `as_of`.
- Элементы массива `clearing_documents` имеют тип object. Элементы массива `ids` имеют тип string. Элементы массива `items` имеют тип object. Значение JSON `null` вместо элемента даёт ошибку JSON Schema до обработчика.
- Тип исключения слоя JSON Schema не фиксируется.

#### Проверки обработчика (D-06)

- Обработчик выполняет структурную проверку после JSON Schema и после D-04.
- При нескольких нарушениях D-06 одновременно проверка останавливается на первом сработавшем шаге в следующем порядке:

1. При вызове в обход схемы: ключ корня, которого нет в таблице входа данного инструмента.
2. Наличие обязательных ключей успешного вызова из корневой таблицы соответствующего инструмента D-12–D-23.
3. Запрет JSON `null` у ключей, для которых D-07 требует `ValueError`.
4. При вызове в обход схемы: значение известного корневого ключа с JSON-типом, отличным от типа в таблице входа данного инструмента.
5. Для пакетного создания: ключ `clearing_documents` присутствует, значение есть массив, длина массива не меньше 1; каждый элемент есть объект; иначе `ValueError`; у каждого элемента присутствуют обязательные ключи вложенной таблицы D-15.
6. Для пакетного удаления: ключ `ids` присутствует, значение есть массив, длина массива не меньше 1; каждый элемент есть непустая строка.
7. Для сегмента пути `document_id` и `item_id`: ключ присутствует, значение есть непустая строка. Обработчик не удаляет крайние пробелы и не проверяет форму UUID.
8. При вызове в обход схемы: каждый элемент массива `items` и каждый элемент массива `clearing_documents` есть объект; иначе `ValueError`. Затем ключ внутри элемента, которого нет во вложенной таблице соответствующего инструмента, даёт `ValueError`. Неверный JSON-тип известного вложенного ключа даёт `ValueError`.

- Нарушение правил D-06 даёт `ValueError` без вызова HTTP.
- Обязательность полей внутри элемента `items`, кроме присутствия самого массива `items` там, где корневая или вложенная таблица помечает его как обязательный, обработчик не проверяет. Отсутствие `debit_credit_indicator`, `clearing_amount`, `clearing_date` или `line_id` в элементе передаётся в HTTP. Обработчик не выбирает ветвь FIN-354 D-06 по значению `document_type` и не отклоняет ключи другой ветви. Форму элемента и ветви задаёт HTTP FIN-354 D-06, D-12 и D-21.
- Пустой массив `items` при создании одной записи сам по себе не даёт `ValueError`. Обработчик передаёт его в HTTP.
- Повтор UUID внутри `ids`, неканонический UUID, ветвь `document_type`, форма команды типа документа, атомарность пакета и доменные инварианты проверяет только HTTP. Обработчик MCP пробрасывает ответ API без смены `error.code`.

#### Отсутствие ключа и null (D-07)

- Ключ, отсутствующий в аргументах MCP, не попадает в JSON тела HTTP и не формирует параметр запроса.
- Отсутствие ключа и явный `null` — различные состояния.
- Пустая строка не преобразуется в `null`.
- Явный `null` для известного аргумента, для которого контракт инструмента не предусматривает `null`, даёт `ValueError` до HTTP. К этим аргументам относятся `profile`, `base`, `document_id`, `item_id`, `document_type`, `creditor_subject_id`, `debtor_subject_id`, `clearing_currency`, `status`, `status_date`, `comment`, `debit_credit_indicator`, `clearing_amount`, `clearing_date`, `line_id`, `clearing_documents`, `ids` и `items`.
- Значение JSON `null` вместо элемента массива `clearing_documents`, `ids` или `items` отклоняет JSON Schema по D-05. Обработчик этот случай как `ValueError` не выделяет.
- Обработчик не подставляет ключ `document_type` и не заменяет переданное значение типа.
- JSON-тело содержит только явно переданные поля тела. Значение по умолчанию параметра в коде не смешивает «ключ не передан» и «ключ передан со значением `null`».

#### Классификация исходов HTTP (D-08)

- Классы ошибок обёртки для операций этой задачи:

| Класс | Условие | HTTP вызывается | Тело |
| ----- | ------- | --------------- | ---- |
| Ошибка JSON Schema | схема аргументов MCP | нет | структура слоя схемы MCP; код ошибки HTTP отсутствует |
| Ошибка обработчика | `ValueError` до HTTP | нет | текст исключения обработчика |
| Ошибка сессии | ключ `base` отсутствует в аргументах и значения сессии нет | нет | ошибка сессии без тела API |
| Ошибка валидации HTTP | код HTTP 422 и в теле есть объект `error` с полем `code` | да | исходное тело ошибки API; `error.code` не заменяется |
| Доменная ошибка HTTP | код HTTP класса 4xx или 5xx, кроме 422, и в теле есть объект `error` с полем `code` | да | исходное тело ошибки API; `error.code` не заменяется |
| Неожиданный код или тело HTTP | любой HTTP-результат, не классифицированный как успех, ошибка валидации HTTP или доменная ошибка HTTP; в том числе иной `2xx`, `1xx`, `3xx`, ожидаемый успешный код с телом неверного вида, код класса 4xx или 5xx без объекта `error.code` | да | сообщение с методом, путём, кодом HTTP и телом API |
| Сетевой сбой | транспорт HTTP | вызов начат | исходное исключение сети без обёртки формата API |

- Ссылки на классы D-08 называют класс по имени из этой таблицы, не по номеру шага алгоритма ниже.
- При нескольких нарушениях одновременно проверка останавливается на первом сработавшем шаге.

1. JSON Schema MCP, включая неизвестный ключ и неверный тип.
2. Разрешение `profile` и `base` по D-04. Пустой результат после удаления крайних символов `U+0020 SPACE` даёт `ValueError`. Отсутствие значения сессии для `base` при отсутствии ключа аргумента даёт ошибку сессии.
3. Проверки обработчика по D-06 и D-07.
4. Вызов HTTP.
5. Ожидаемый успешный код операции и тело допустимого вида по D-09: успех.
6. Код HTTP 422 и в теле есть объект `error` с полем `code`: класс «Ошибка валидации HTTP».
7. Код HTTP класса 4xx или 5xx, кроме 422, и в теле есть объект `error` с полем `code`: класс «Доменная ошибка HTTP».
8. Любой иной результат HTTP: класс «Неожиданный код или тело HTTP».

- Сетевой сбой классифицируется до разбора кода HTTP.
- MCP-сервер не вводит новые значения `error.code`.
- Для ошибки валидации HTTP и доменной ошибки HTTP поле `details` сохраняется, если оно есть в теле API.
- Мягкий ответ вида `{ "ok": false }` без исключения не используется.
- Коды FIN-354 D-18, включая `clearing_document_not_found`, `clearing_document_item_not_found`, `validation_error`, `invalid_monetary_claim_party`, `invalid_clearing_document_operation`, `line_not_found`, `period_closed` и `clearing_document_store_busy`, обработчик не переименовывает.

```json
{
  "error": {
    "code": "validation_error",
    "message": "Ошибка валидации входных данных.",
    "details": [
      {
        "loc": ["body", "document_type"],
        "msg": "Field required"
      }
    ]
  }
}
```

- Вызывающая сторона сравнивает код HTTP и `error.code`.

#### Разворачивание ответа (D-09)

- MCP-сервер не вкладывает HTTP-обёртку коллекции во второй уровень с тем же именем.
- Список документов: HTTP `{"clearing_documents": […]}` даёт MCP `{"ok": true, "profile": …, "base": …, "clearing_documents": […]}`.
- Пакетное создание: HTTP `{"clearing_documents": […]}` даёт MCP тот же ключ `clearing_documents` на верхнем уровне рядом с `ok` / `profile` / `base`.
- Чтение, создание и частичное обновление одного документа: тело HTTP без обёртки списка даёт ключ `clearing_document` на верхнем уровне ответа инструмента.
- Список строк состава: HTTP `{"items": […]}` даёт MCP ключ `items` на верхнем уровне рядом с `ok` / `profile` / `base`.
- Создание, чтение и частичное обновление одной строки состава: тело HTTP без обёртки списка даёт ключ `clearing_document_item` на верхнем уровне.
- Успех с кодом HTTP 204: только `ok` / `profile` / `base` без ключей сущности. Тело HTTP, если оно есть, в ответ инструмента не переносится.
- Для списка документов успех требует код HTTP 200 и значение ключа `clearing_documents` как массив. Иначе применяется класс «Неожиданный код или тело HTTP».
- Для пакетного создания успех требует код HTTP 201 и значение ключа `clearing_documents` как массив. Иначе применяется класс «Неожиданный код или тело HTTP».
- Для списка строк состава успех требует код HTTP 200 и значение ключа `items` как массив. Иначе применяется класс «Неожиданный код или тело HTTP».
- Для чтения, создания и частичного обновления одного документа успех требует ожидаемый код HTTP и тело-объект. MCP-сервер не проверяет наличие ключей внутри объекта документа и не проверяет значение `document_type`.
- Для создания, чтения и частичного обновления одной строки состава успех требует ожидаемый код HTTP и тело-объект. MCP-сервер не проверяет наличие ключей внутри объекта строки.
- MCP-сервер не добавляет ключи в объект документа или строки состава, не удаляет ключи из него и не переименовывает ключи.
- MCP-сервер не подставляет ключи `remainder`, `settled_amount`, `origination` и `settlements`, если их нет в теле HTTP.
- Для списка MCP-сервер переносит из корневого HTTP-объекта только значение ключа `clearing_documents` или `items`. Прочие корневые ключи HTTP, включая `meta`, в ответ MCP не переносятся.
- Пустой массив коллекции является успешным результатом и сохраняет `ok: true`.
- Порядок элементов коллекции MCP-сервер не меняет.

#### Инварианты (D-10)

- MCP-сервер не ослабляет инварианты HTTP API FIN-354 редакции 17.
- JSON-тело содержит только явно переданные поля тела, определённые соответствующим контрактом D-14–D-23. Аргументы пути, параметры запроса, включая `allow_closed`, а также `profile` и `base` в тело не включаются.
- Объекты документа и строки состава внутри успешного ответа MCP не нормализуются. Преобразование корневого HTTP-ответа выполняется по D-09.
- Связанные операции и позиции вызовами этой задачи MCP-сервер не изменяет, кроме изменений, которые выполняет сам HTTP-запрос FIN-354.
- Имена ключей коллекций в успешном ответе совпадают с HTTP: `clearing_documents` для списка документов и пакетного создания; `items` для списка строк состава.

#### Обратная совместимость (D-11)

- Двенадцать новых инструментов добавляются без изменения семантики существующих инструментов MCP.
- Контракт HTTP API FIN-354 этой задачей не меняется.
- Контракт инструмента `household_receivables` этой задачей не меняется и этим контрактом не подменяется.
- Универсальные инструменты этой задачи не заменяют специализированные инструменты сопоставления сторон внутреннего перевода FIN-351.
- Контракт инструментов FIN-351 этой задачей не меняется.
- FIN-380 отвечает только за последующее перенацеливание инструментов FIN-351 на HTTP документов выравнивания и за совместимость этих инструментов. Наличие универсального MCP-контракта этой задачи FIN-380 не блокирует.

#### Нормализация входа MCP (D-24)

- MCP-сервер не нормализует поля тела, пути и фильтров документа выравнивания: `document_id`, `item_id`, `document_type`, `creditor_subject_id`, `debtor_subject_id`, `clearing_currency`, `status`, `status_date`, `comment`, `debit_credit_indicator`, `clearing_amount`, `clearing_date`, `line_id`, элементы `ids`.
- Удаление крайних символов `U+0020 SPACE` у этих полей, проверка UUID, календарной даты, литералов статуса и формы суммы принадлежат HTTP FIN-354 D-02, D-04, D-06, D-11, D-12 и D-14.
- Исключение: аргументы `profile` и `base` нормализуются по D-04.
- MCP-сервер не исправляет неканонический UUID без дефисов и не удаляет табуляцию или неразрывный пробел из полей документа.

#### Конкурентные изменения (D-25)

- Конкурентные изменения между последовательными вызовами инструментов MCP сверх гарантий FIN-354 D-17 явно не нормируются.
- Наблюдаемое состояние успешного ответа относится к телу данного HTTP-ответа. MCP-сервер не выполняет повторное чтение после записи.

## Предположения, предусловия и ограничения

- HTTP-контракт FIN-354. На профиле прогона развёрнут HTTP-контракт документов выравнивания FIN-354 редакции 17, включая пути строк состава, оба значения `document_type` и параметр `allow_closed`.
- Субъекты учёта. В профиле прогона доступны инструменты субъектов учёта FIN-366, и в профиле есть по меньшей мере два различных субъекта учёта, пригодных как кредитор и должник денежного требования.
- Конкурентность. Конкурентное изменение документа между двумя вызовами инструментов MCP отдельно не нормируется.

## Критерий приёмки

#### Продуктовый результат

- Ops создают, читают, перечисляют и удаляют документ выравнивания обоих типов только через MCP, без прямого вызова HTTP.
- Частичное обновление заголовка доступно для `monetary_claim`. Для `internal_transfer` оно отклоняется HTTP согласно FIN-354.
- Для `monetary_claim` через MCP доступны создание, чтение, список, частичное обновление и удаление строк состава. Для `internal_transfer` доступны чтение и список строк состава; изменение состава после создания отклоняется HTTP согласно FIN-354.
- Последовательность «оплата за другое лицо» выполняется инструментами этой задачи: создание документа со связанной позицией возникновения, чтение и список.
- Последовательность «займ и погашение» выполняется инструментами этой задачи: создание без связи, установка связи строки, добавление строки погашения, частичное обновление заголовка, включая статус.
- Создание, чтение и удаление документа типа `internal_transfer` выполняются теми же инструментами.
- Один вызов пакетного создания может содержать `monetary_claim` и `internal_transfer` одновременно.
- Успешный ответ чтения документа и строки состава содержит сохранённые поля HTTP-записи и не содержит ключи `remainder` и `settled_amount`, если их нет в теле HTTP.
- Доменные ошибки API пробрасываются в ошибку инструмента без потери `error.code`.

#### Контроль реализации

- Поведение обёртки покрыто автотестами на mock API: схема аргументов, обработчик, отсутствие подстановки `document_type`, разбор конверта HTTP и классы ошибок D-08.
- Сценарии с постоянной базой проверяются прогоном функциональной приёмки. Автотесты на mock API этот прогон не заменяют.
- Справочник доступных инструментов MCP описывает двенадцать инструментов этой задачи.
- Метка `mcp-gap` снята с FIN-355 после поставки инструментов.
