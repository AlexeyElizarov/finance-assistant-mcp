# Финансирование фонда в ответах MCP переноса остатка и сверки денежных средств

**Статус:** Утверждено (2026-08-09, rev.2).

## Назначение

* Финансирование фонда доступно по HTTP после FIN-279, но инструменты MCP переноса остатка и сверки денежных средств не отдают исходящее и входящее финансирование.
* Операционные процедуры на пути только через MCP вынуждены читать эти суммы прямым HTTP.

## Критерий приёмки

* Ответ инструмента переноса остатка личного фонда содержит исходящее финансирование на строке члена и блок финансирования фонда согласно целевому поведению.
* Ответ инструмента сверки денежных средств показывает те же суммы финансирования, когда они доступны из пути переноса остатка.
* Сценарий погашения с разными фондами сторон воспроизводится через MCP без прямого HTTP.
* Доменные ошибки HTTP API переноса остатка пробрасываются в ошибку инструмента без потери кода ошибки.
* Поведение покрыто функциональным тестированием.

## Объём и границы

### Входит в объём

#### Возможности

* В объём входит чтение исходящего финансирования на строке члена в ответе `personal_fund_carryover`.
* В объём входит чтение блока финансирования фонда в ответе `personal_fund_carryover`.
* В объём входит проброс строки формулы переноса остатка из ответа HTTP, когда источник расчёта равен API.
* В объём входит чтение исходящего финансирования и блока финансирования фонда в ответе `money_check_report`, когда путь переноса остатка их отдаёт.
* В объём входит проброс предупреждений доменного расчёта финансирования в ответы этих инструментов.

#### Артефакты приёмки

* В объём входят правки модулей `scripts/personal_fund_carryover.py` и `scripts/money_check_report.py`.
* В объём входят функциональные тесты.
* В объём входит обновление справочника доступных инструментов MCP.

### Не входит в объём

#### Зависимости и соседние возможности

* Не входит доменный расчёт финансирования (FIN-278).
* Не входит проектирование HTTP-контракта финансирования (FIN-279).
* Не входит пользовательский интерфейс финансирования (FIN-281).
* Не входят инструменты MCP погашения расхода (FIN-271).
* Не входит применение июля на prod (FOPS-28).
* Не входит отчёт экономической нагрузки фонда (FIN-290).

#### Не планируется

* Не входят новые инструменты MCP только для финансирования.
* Не входит отдельный составной HTTP-путь снимка сверки денежных средств.
* Не входит запись, правка или удаление финансирования через MCP.
* Не входит расширение компактной истории прогонов переноса остатка полями финансирования.
* Не входит пересчёт финансирования на стороне MCP при пути сопоставления контуров.
* Не входит дополнительный dry-run или HTTP-вызов только ради финансирования в сверке денежных средств.
* Не входит изменение семантики авансов, дебиторской задолженности и классификации в сверке денежных средств.

## Факт реализации (до)

| Область | Текущее поведение | Проблема |
| ------- | ----------------- | -------- |
| HTTP | FIN-279 отдаёт `outgoing_financing` и `fund_financing` в ответе переноса остатка | — |
| MCP переноса | Нормализация ответа API отбрасывает поля финансирования; корневой блок не пробрасывается | Ops не видит финансирование через MCP |
| MCP сверки | Собирает строки членов из log или dry-run переноса без полей финансирования | Еженедельная сверка не показывает исходящее и входящее финансирование |
| Формула MCP | Локальная строка формулы без исходящего финансирования | Расходится с HTTP при источнике API |

## Обратная совместимость

* Новые поля аддитивны: существующие ключи ответов `personal_fund_carryover` и `money_check_report` сохраняют имена и семантику.
* Параметры вызова обоих инструментов не меняются.
* Клиенты, которые не читают новые поля, продолжают получать прежние ключи.
* Компактная история прогонов переноса остатка не расширяется полями финансирования.
* Контракт HTTP FIN-279 этой задачей не меняется.
* Единая политика отсутствия данных финансирования в ответе HTTP: отсутствующий ключ на строке члена даёт ноль; отсутствующий корневой блок даёт пустой блок по D-05. Это одна норма обратной совместимости со старыми ответами API, а не два независимых решения.

## Целевое поведение

### Поверхность чтения (D-01)

* Новые инструменты MCP для финансирования не вводятся.
* Единственная поверхность финансирования в MCP — расширение ответов `personal_fund_carryover` и `money_check_report`.
* Остаток личного фонда в смысле FIN-279 читается через `personal_fund_carryover`; отдельный инструмент «residual» не вводится.
* Параметры вызова обоих инструментов не меняются.

### Конвейер переноса остатка (D-02)

```
1. получить сессию API (профиль данных, базовый URL)
2. проверить аргументы MCP до HTTP (как сейчас)
3. выполнить существующий путь расчёта переноса (probe HTTP, иначе сопоставление контуров)
4. при источнике API дополнить нормализованный ответ полями финансирования из тела HTTP
5. при источнике сопоставления контуров заполнить поля финансирования пустыми значениями по норме D-05
6. при успехе вернуть конверт ответа с прежними полями и аддитивными полями финансирования
7. ошибки HTTP и сети — по существующим правилам инструмента
```

* Порядок шагов фиксирован.
* Доменные инварианты финансирования не дублируются в MCP.

### Проброс полей переноса остатка (D-03)

* Успешный ответ `personal_fund_carryover` всегда содержит ключ `outgoing_financing` на каждой строке `partners` и ключ `fund_financing` в корне.

#### Строка члена

* При источнике API значение `outgoing_financing` берётся из соответствующей строки ответа HTTP и округляется так же, как прочие денежные поля строки.
* Если ключ в строке HTTP отсутствует, значение равно нулю (политика обратной совместимости из раздела «Обратная совместимость»).

#### Корневой блок

* При источнике API значение `fund_financing` равно объекту из тела HTTP без пересчёта.
* Если ключ в теле HTTP отсутствует, используется пустой блок по норме D-05 (та же политика обратной совместимости).
* Состав и семантика полей блока совпадают с FIN-279; MCP не переименовывает и не отбрасывает ключи блока.

#### Формула

* При источнике API строка `formula` в ответе MCP равна строке `formula` из тела HTTP.
* При источнике сопоставления контуров строка формулы остаётся локальной канонической строкой инструмента без требования совпадения с FIN-279.

#### Предупреждения

* Предупреждения финансирования из корневого массива `warnings` ответа HTTP входят в массив `warnings` ответа MCP без потери текста.
* Предупреждения внутри `fund_financing.warnings` сохраняются внутри блока.

### Сверка денежных средств (D-04)

* Успешный ответ `money_check_report` всегда содержит ключ `outgoing_financing` на каждой строке `partners` и ключ `fund_financing` в корне.
* Когда источник переноса остатка для сверки равен `dry_run`, значения `outgoing_financing` и `fund_financing` берутся из ответа `personal_fund_carryover` (dry-run) без повторного HTTP.
* Когда источник переноса остатка равен `dry_run`, предупреждения финансирования из ответа dry-run входят в массив `warnings` сверки без потери текста; предупреждения внутри `fund_financing.warnings` сохраняются внутри блока.
* Когда источник переноса остатка равен `log` или `none`, каждая строка члена получает `outgoing_financing` равный нулю, а `fund_financing` заполняется пустым блоком по D-05; дополнительный dry-run или HTTP-вызов только ради финансирования не выполняется.
* Отдельное предупреждение о том, что финансирование не взято из истории прогона, не добавляется: источник переноса уже виден в блоке `carryover`, а нули и пустой блок в этих ветках являются ожидаемым следствием D-05.
* Блок `carryover` и прочие секции сверки сохраняют прежнюю семантику.
* Параметры вызова `money_check_report` не меняются.

### Поведение при отсутствии расчёта финансирования (D-05)

* Пустой блок финансирования фонда — контрактный fallback MCP, когда расчёт финансирования из HTTP недоступен или ключ блока отсутствует в ответе API. MCP не вычисляет `accounting_period` самостоятельно сверх правил ниже.

| Поле | Норма |
| ---- | ----- |
| `accounting_period` | Для `personal_fund_carryover` — строка закрываемого месяца в формате `YYYYMM`, согласованная с `closed_period` ответа. Для `money_check_report` при `log` или `none` — пустая строка как часть того же контрактного fallback, без вывода периода из иных полей сверки |
| `projections` | `[]` |
| `outgoing_by_fund` | `{}` |
| `incoming_by_fund` | `{}` |
| `outgoing_by_member` | `{}` |
| `outgoing_by_analytics` | `[]` |
| `warnings` | `[]` |

* При источнике сопоставления контуров у `personal_fund_carryover` каждая строка члена имеет `outgoing_financing` равный нулю, а `fund_financing` равен пустому блоку.
* MCP не вычисляет финансирование самостоятельно на пути сопоставления контуров.

### История прогонов (D-06)

* Компактная запись и чтение истории прогонов переноса остатка не содержат и не восстанавливают поля финансирования; сверка из `log` заполняет финансирование только по правилу D-04 для источника `log`.

### Ошибки (D-07)

* Ответ HTTP переноса остатка с кодом, отличным от успеха, даёт ошибку инструмента по существующим правилам `personal_fund_carryover`.
* Мягкий ответ вида `{ "ok": false }` без исключения не используется для доменных ошибок API.
* Новых кодов ошибок MCP эта задача не вводит.
* Сетевые сбои пробрасываются без дополнительной обёртки.

### Инварианты (D-08)

* MCP не ослабляет инварианты HTTP FIN-279.
* При источнике API суммы `outgoing_financing` и содержимое `fund_financing` в ответе MCP совпадают с телом HTTP для того же запроса.
* Согласно FIN-279, показатели `balance` и `carryover` на пути API уже учитывают исходящее финансирование; MCP не вычитает финансирование повторно.
