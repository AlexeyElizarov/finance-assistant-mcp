# fin-351-internal-transfer-match-mcp-decision-log

Рабочий реестр решений. Не является нормативным источником; нормы — в спецификации.

Канон: [decision-log.md](../../../PycharmProjects/FinancePlanningProject/standards/specs/form/decision-log.md).

| ID | Вопрос | Итог | Дата |
| -- | ------ | ---- | ---- |
| D-01 | Нужны ли пакетные инструменты, если Goal перечислял только создание, чтение, список и удаление | Полный паритет HTTP FIN-350. MCP не переопределяет домен. Повтор ожидаемых результатов в T не создаёт самостоятельной нормы MCP | 30.08.2026 |
| D-02 | Свой конвейер или общий для справочников | Сначала схема, затем эффективный `profile` и `base`, затем валидация обработчика, затем сессия. Ошибки разрешения сессии наследуются из общего механизма MCP и не преобразуются. Ожидаемый код успеха по операции. Иной `2xx` это ошибка по D-14 | 30.08.2026 |
| D-03 | Где размещать обёртки | Отдельный модуль `scripts/internal_transfer_matches.py` и регистрация в `server.py` | 30.08.2026 |
| D-04 | Кто отклоняет незаявленные поля и пустой пакет | Схема раньше `strip`. `profile` и `base` нормализуются после схемы. Пустой `profile` это `prod`. Пустой `base` это URL по умолчанию профиля. `match_id` и элементы `ids` проверяются на непустоту после `strip`, в HTTP уходит исходная строка | 30.08.2026 |
| D-05 | Как передавать курс, идентификатор и `null` массива | Ключи курса и id не объявляются. `null` обязательного массива отклоняется до HTTP | 30.08.2026 |
| D-06 | Нормализовать ли ответ HTTP | Нет; только конверт. `profile` и `base` не входят в HTTP. `allow_closed` только в query. JSON-тело только поля FIN-350. В успехе `profile` и `base` это эффективные значения. Порядок массивов наследуется из FIN-350 | 30.08.2026 |
| D-07 | Обязателен ли фильтр списка по позиции | Нет; отсутствие ключа даёт список профиля; пустой список успешен; живой прогон на `cand` не требует глобально пустого списка | 30.08.2026 |
| D-08 | Ключ объекта при чтении одной записи | `internal_transfer_match`; тело как HTTP-модель FIN-350 | 30.08.2026 |
| D-09 | Тип массивов сторон и кто считает курс | `array[string]`. Курс считает только HTTP. MCP не переставляет массивы сторон во входном теле | 30.08.2026 |
| D-10 | Какие ключи у элемента пакета | Ровно два ключа `array[string]`. Атомарность из FIN-350. Индекс ошибки пакета только в тексте `RuntimeError` по D-14 | 30.08.2026 |
| D-11 | Возвращать ли `deleted: true` при удалении | Нет; только конверт. Неизменность операций по D-06 | 30.08.2026 |
| D-12 | Тип `ids` пакетного удаления | `array[string]`; семантика UUID, не schema UUID | 30.08.2026 |
| D-13 | Как передавать обход закрытого периода | Нет ключа: параметра нет. Явная ложь: `allow_closed=false`. Чтение ключ отклоняет | 30.08.2026 |
| D-14 | Как MCP отдаёт ошибку HTTP | Тело HTTP целиком как есть. Поля `error.*` обязательны только для ошибочного тела FIN-350. Неожиданный `2xx` их не требует | 30.08.2026 |
