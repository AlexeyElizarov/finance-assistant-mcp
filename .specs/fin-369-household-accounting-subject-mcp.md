# Связанный субъект учёта в инструментах MCP домохозяйства и члена

**Статус:** Утверждено (2026-09-02, rev.5).

## Назначение

- Ответы инструментов списка и записи домохозяйства и члена не отдают связанный субъект учёта; ответ члена по-прежнему отдаёт отображаемое имя на строке членства.
- Оператору на пути только через MCP нужна та же строка домохозяйства и члена, что отдаёт HTTP после FIN-368: связанный субъект учёта явно либо пустое представление, без имени физического лица на строке членства.

## Входит в объём

- Чтение связанного субъекта учёта типа «группа» в успешных ответах списка домохозяйств и записи домохозяйства.
- Чтение связанного субъекта учёта типа «физическое лицо» в успешных ответах списка членов и записи члена.
- Перенос определённого пустого представления, когда представление домохозяйства или соответствие члена отсутствует.
- Отсутствие отображаемого имени физического лица в успешных ответах члена, когда его нет в теле HTTP.
- Необязательность ключа `display_name` в аргументах записи члена: отсутствие ключа не включает его в тело HTTP.
- Отклонение назначения субъекта учёта через аргументы записи домохозяйства и члена.
- Обновление описания этих инструментов в справочнике доступных инструментов MCP.

## Вне объёма

- Не входит проектирование HTTP-контракта домохозяйства и члена (FIN-368).
- Не входит пользовательский интерфейс домохозяйства и члена (FIN-370).
- Не входят слой сохранения члена домохозяйства и удаление колонки отображаемого имени физического лица (FIN-371).
- Не входят инструменты чтения группы по домохозяйству, чтения субъекта учёта по члену, установления и снятия соответствия (FIN-366).
- Не входит изменение способа назначения субъекта учёта типа «группа» и соответствия члена.
- Не входят новый инструмент чтения одного домохозяйства по идентификатору и новый инструмент чтения одного члена по идентификатору.
- Не входят инструменты списка и записи банковского счёта.
- Не входит фильтр списка домохозяйств или списка членов по субъекту учёта.
- Не входит начальное заполнение субъектов учёта на постоянных профилях (FOPS-41).
- Не входят пакетная запись домохозяйства и члена и удаление домохозяйства и члена.

## Текущее поведение

| Область | Текущее поведение | Проблема |
| ------- | ----------------- | -------- |
| HTTP | FIN-368: список и запись отдают `accounting_subject`; ответ члена не содержит `display_name`; при изменении члена ключ `display_name` необязателен | Инструменты MCP этот контракт не отражают |
| MCP список и запись | Тело HTTP переносится как есть, но запись члена всегда требует `display_name` и копирует его в тело | После исключения ключа из ответа нельзя изменить члена, не зная сохранённое имя; назначение субъекта учёта в аргументах молча отбрасывается |
| MCP соответствие | FIN-366: отдельные инструменты чтения и соответствия | Их контракт эта задача не подменяет вложенным полем |

## Целевое поведение

#### Паритет поверхности (D-01)

- Эта задача не добавляет инструменты MCP и не удаляет инструменты MCP.
- Публичной HTTP-поверхности FIN-368 соответствуют следующие четыре инструмента:

| Инструмент MCP | Операция HTTP | Смысл |
| -------------- | ------------- | ----- |
| `list_households` | `GET /api/v1/households` | Список домохозяйств |
| `upsert_household` | `PUT /api/v1/households/{household_id}` | Создание или изменение домохозяйства |
| `list_household_members` | `GET /api/v1/households/{household_id}/members` | Список членов |
| `upsert_household_member` | `PUT /api/v1/households/{household_id}/members/{member_id}` | Создание или изменение члена |

- Отдельный инструмент чтения одного домохозяйства по идентификатору не вводится.
- Отдельный инструмент чтения одного члена по идентификатору не вводится.
- Чтение одной строки после записи выполняется успешным ответом `upsert_household` или `upsert_household_member`.
- Норма полного набора CRUD для нового ресурса к этой задаче не применяется.
- Эта задача расширяет уже существующие инструменты полем уже существующего HTTP-контракта.
- Доменные правила вложенного объекта, пустого представления, отклонения назначения в теле записи и обязательности `display_name` при создании члена принадлежат HTTP FIN-368 редакции 4. MCP эти правила не дублирует и не ослабляет.
- Инструменты `get_household_accounting_subject`, `get_household_member_accounting_subject`, `link_household_member_accounting_subject` и `unlink_household_member_accounting_subject` эта задача не изменяет.

#### Конвейер (D-02)

1. Проверить аргументы по JSON Schema MCP.
2. Определить эффективный `profile`. Если ключ аргумента присутствует, выбранная строка есть значение аргумента. Иначе если значение сессии есть, выбранная строка есть значение сессии, включая пустую строку и строку из одних пробелов. Иначе выбранная строка есть `prod`. К выбранной строке удаляются крайние символы `U+0020 SPACE`. Пустой результат даёт `ValueError` до HTTP. Непустой результат есть эффективное значение. Подстановка `prod` выполняется только при отсутствии значения сессии, не после удаления пробелов.
3. Определить эффективный `base`. Если ключ аргумента присутствует, выбранная строка есть значение аргумента. Иначе если значение сессии есть, выбранная строка есть значение сессии, включая пустую строку и строку из одних пробелов. Иначе возникает ошибка сессии до HTTP. К выбранной строке удаляются крайние символы `U+0020 SPACE`. Пустой результат даёт `ValueError` до HTTP. Непустой результат есть эффективное значение. Класс «Ошибка сессии» для `base` возникает только при отсутствии значения сессии, не после удаления пробелов.
4. Эффективные `profile` и `base` используются при обращении к сессии, в вызове HTTP и в успешном ответе.
5. Выполнить дополнительную проверку обработчика.
6. Собрать путь и тело HTTP.
7. Выполнить вызов метода `GET` или `PUT`.
8. Разобрать результат по D-08.
9. При успехе обернуть коллекцию или сущность в конверт `ok` / `profile` / `base`.
10. Если D-08 не определил успех, вернуть ошибку того класса, который определил D-08.
11. Сетевой сбой пробросить без дополнительной обёртки.

- Порядок шагов фиксирован.
- Успех списка: код HTTP 200 и массив коллекции по D-07.13 или D-07.14. Иной HTTP-результат списка классифицируется по D-08.
- Успех записи определяется кодом HTTP 200 и тем, что тело является объектом. Поля внутри объекта сущности MCP не валидирует.
- Доменные инварианты домохозяйства, члена и субъекта учёта в MCP не дублируются.
- Успешный ответ всегда содержит эффективные `profile` и `base`.

#### Модуль и регистрация (D-03)

- Расширение выполняется в существующем модуле `scripts/households.py`.
- Схемы и обработчики четырёх инструментов обновляются в `server.py`.
- Справочник доступных инструментов обновляется в `mcp-gaps.md`.
- После поставки инструментов метка `mcp-gap` снимается с FIN-369.
- Новый модуль и новые имена инструментов не вводятся.

#### JSON Schema MCP (D-04)

- JSON Schema инструментов `upsert_household` и `upsert_household_member` задаёт `additionalProperties: false` в корне аргументов.
- Незаявленный ключ этих двух инструментов, включая `accounting_subject` и `accounting_subject_id`, даёт ошибку JSON Schema до обработчика. HTTP не вызывается.
- JSON Schema этих двух инструментов проверяет тип корневого объекта и тип каждого переданного заявленного ключа.
- Ключ `display_name` объявлен в схеме `upsert_household_member` с типом `string` и не входит в массив `required`.
- Значение JSON `null` ключа `display_name` схемой не допускается.
- Массив `required` инструмента `upsert_household` остаётся `id`, `name`.
- Массив `required` инструмента `upsert_household_member` становится `household_id`, `member_id`.
- Массив `required` инструмента `list_household_members` остаётся `household_id`.
- Схема `list_households` новых аргументов не получает.
- Эта задача не меняет `additionalProperties` схем `list_households` и `list_household_members`.
- Тип переданного `is_active` остаётся `boolean`. Значение JSON `null` ключа `is_active` схемой не допускается.
- Тип исключения слоя JSON Schema не фиксируется.

#### Запись члена: ключ `display_name` (D-05)

- Если ключ `display_name` в аргументах `upsert_household_member` отсутствует, тело HTTP этот ключ не содержит.
- Отсутствие ключа само по себе ошибкой MCP не является.
- Если строки члена ещё нет, отсутствие ключа в теле HTTP даёт ошибку инструмента по ответу API с кодом HTTP 422 и кодом ошибки `validation_error` согласно FIN-368 D-08 редакции 4.
- Если строка члена уже есть, отсутствие ключа сохраняет прежнее сохранённое значение согласно FIN-368 D-08 редакции 4.
- Если ключ присутствует и значение является строкой, обработчик удаляет только крайние символы `U+0020 SPACE`.
- Если после этого удаления строка пуста, обработчик поднимает `ValueError` до HTTP.
- Если после этого удаления строка непуста, тело HTTP содержит ключ `display_name` с этой строкой.
- Обработчик не удаляет внутренние пробелы и не меняет регистр.
- Если обработчик вызван в обход схемы с ключом `display_name` и значением `null`, обработчик поднимает `ValueError` без вызова HTTP.
- Аргумент `is_active` сохраняет прежнюю семантику: отсутствие ключа не включает его в тело HTTP; присутствие булева значения копирует его в тело.

#### Запись домохозяйства и запрет назначения (D-06)

- Схемы `upsert_household` и `upsert_household_member` не объявляют ключи `accounting_subject` и `accounting_subject_id`.
- Если обработчик вызван в обход JSON Schema и в аргументах присутствует ключ `accounting_subject` или ключ `accounting_subject_id`, в том числе со значением `null`, обработчик поднимает `ValueError` без вызова HTTP.
- Успешная запись домохозяйства не назначает, не заменяет и не очищает представление субъектом учёта типа «группа».
- Успешная запись члена не создаёт, не заменяет и не снимает соответствие субъекту учёта типа «физическое лицо».
- Назначение группы выполняется созданием субъекта учёта типа `group` инструментом `create_accounting_subject`.
- Установление и снятие соответствия выполняются инструментами `link_household_member_accounting_subject` и `unlink_household_member_accounting_subject`.
- Тело `upsert_household` по-прежнему содержит обязательный ключ `name` и копирует `is_active` только при наличии ключа.

#### Разворачивание ответа (D-07)

- MCP не вкладывает HTTP-обёртку коллекции во второй уровень с тем же именем.
- Список домохозяйств: HTTP `{"households": […]}` даёт MCP `{"ok": true, "profile": …, "base": …, "households": […]}`.
- Список членов: HTTP `{"members": […]}` даёт MCP `{"ok": true, "profile": …, "base": …, "members": […]}`.
- Запись домохозяйства: тело HTTP без обёртки списка даёт ключ `household` на верхнем уровне ответа инструмента.
- Запись члена: тело HTTP без обёртки списка даёт ключ `member` на верхнем уровне ответа инструмента.
- MCP не добавляет ключи в объект домохозяйства или члена, не удаляет ключи из него и не переименовывает ключи.
- MCP не подставляет `accounting_subject` со значением JSON `null`, если ключ в объекте HTTP отсутствует.
- MCP не удаляет ключ `display_name` из объекта члена, если ключ в объекте HTTP присутствует.
- Значение ключа `accounting_subject` переносится без изменения полей, регистра, внутренних пробелов и кодировки.
- Пустой массив коллекции является успешным результатом и сохраняет `ok: true`.
- Порядок элементов коллекции MCP не меняет.
- Поля объекта при наличии представления или соответствия и при пустом представлении задаёт HTTP FIN-368 D-02, D-03, D-04 и D-05 редакции 4. MCP их форму не переопределяет.
- Для `list_households` успех требует, что значение ключа `households` есть массив. Иначе применяется класс «неожиданный код или тело HTTP» по D-08.
- Для `list_household_members` успех требует, что значение ключа `members` есть массив. Иначе применяется тот же класс.
- Для записи при коде HTTP 200 и теле-объекте MCP не проверяет наличие ключей внутри объекта сущности, включая `accounting_subject`. Тело HTTP целиком становится значением `household` или `member`.
- Нарушение формы вложенного объекта `accounting_subject` относительно FIN-368 MCP не выделяет отдельным классом ошибки.
- Для списка MCP переносит из корневого HTTP-объекта только значение ключа `households` или `members`. Прочие корневые ключи HTTP, включая `meta`, в ответ MCP не переносятся.

#### Ошибки (D-08)

- Классы ошибок обёртки для операций этой задачи:

| Класс | Условие | HTTP вызывается | Тело |
| ----- | ------- | --------------- | ---- |
| Ошибка JSON Schema | схема аргументов MCP | нет | структура слоя схемы MCP; код ошибки HTTP отсутствует |
| Ошибка обработчика | `ValueError` до HTTP | нет | текст исключения обработчика |
| Ошибка сессии | ключ `base` отсутствует в аргументах и значения сессии нет | нет | ошибка сессии без тела API |
| Ошибка валидации HTTP | код HTTP 422 и в теле есть объект `error` с полем `code` | да | исходное тело ошибки API; `error.code` не заменяется |
| Доменная ошибка HTTP | код HTTP класса 4xx или 5xx, кроме 422, и в теле есть объект `error` с полем `code` | да | исходное тело ошибки API; `error.code` не заменяется |
| Неожиданный код или тело HTTP | любой HTTP-результат, не классифицированный как успех, ошибка валидации HTTP или доменная ошибка HTTP; в том числе иной `2xx`, `1xx`, `3xx`, код HTTP 200 без объекта или без массива коллекции, код класса 4xx или 5xx без объекта `error.code` | да | сообщение с методом, путём, кодом HTTP и телом API |
| Сетевой сбой | транспорт HTTP | вызов начат | исходное исключение сети без обёртки формата API |

- Ссылки на классы D-08 в прочих разделах называют класс по имени из этой таблицы, не по номеру шага алгоритма ниже.
- При нескольких нарушениях одновременно проверка останавливается на первом сработавшем шаге.

1. JSON Schema MCP, включая неизвестный ключ, неверный тип и отсутствие ключей массива `required`.
2. Нормализация выбранной строки `profile` или `base` по D-02 независимо от источника: аргумент или сессия. Пустой результат после удаления крайних символов `U+0020 SPACE` даёт `ValueError`. Отсутствие значения сессии для `base` при отсутствии ключа аргумента даёт ошибку сессии.
3. Проверки обработчика в следующем порядке: непустые сегменты пути; непустой `name` домохозяйства после удаления крайних символов `U+0020 SPACE`; присутствие `accounting_subject` или `accounting_subject_id` по D-06.2; правило D-05 для присутствующего `display_name`; тип `is_active`, если ключ присутствует в обход схемы.
4. Вызов HTTP.
5. Код HTTP 200 и тело-объект: для списка — массив коллекции по D-07.13 или D-07.14, затем успех; для записи — успех с телом как объектом сущности. Иначе класс «неожиданный код или тело HTTP».
6. Код HTTP 422 и в теле есть объект `error` с полем `code`: класс «ошибка валидации HTTP».
7. Код HTTP класса 4xx или 5xx, кроме 422, и в теле есть объект `error` с полем `code`: класс «доменная ошибка HTTP».
8. Любой иной результат HTTP: класс «неожиданный код или тело HTTP».

- MCP не вводит новые значения `error.code`.
- Для ошибки валидации HTTP поле `details` сохраняется, если оно есть в теле API.

```json
{
  "error": {
    "code": "validation_error",
    "message": "Ошибка валидации входных данных.",
    "details": [
      {
        "loc": ["body", "display_name"],
        "msg": "Field required"
      }
    ]
  }
}
```

- Текст `msg` является диагностическим.
- Вызывающая сторона сравнивает код HTTP и `error.code`.

#### Инварианты (D-09)

- MCP не ослабляет инварианты HTTP FIN-368 редакции 4.
- Тело запроса содержит только ключи, явно присутствующие в аргументах после проверок D-04, D-05 и D-06.
- Объекты домохозяйства и члена внутри успешного ответа MCP не нормализуются. Преобразование корневого HTTP-ответа выполняется по D-07.
- Успешная запись домохозяйства оставляет значение `accounting_subject` тем же, что было до вызова: тот же `id` объекта либо JSON `null`.
- Успешная запись члена оставляет значение `accounting_subject` тем же, что было до вызова: тот же `id` объекта либо JSON `null`.
- Если `accounting_subject` в ответе списка или записи равен `null`, вызов `get_household_accounting_subject` или `get_household_member_accounting_subject` для той же строки остаётся ошибкой инструмента с кодом ошибки `subject_not_found`.
- Значение `accounting_subject` равное JSON `null` не даёт ошибку списка или записи.

#### Обратная совместимость (D-10)

- Появление ключа `accounting_subject` в объекте домохозяйства является расширением тела.
- Вызывающие стороны, которые неизвестные ключи объекта домохозяйства игнорируют, продолжают разбирать прежние поля, включая `name`.
- Отсутствие ключа `display_name` в объекте члена несовместимо с вызывающими сторонами, которые читают это поле как имя физического лица.
- Этот разрыв допускается: он повторяет разрыв HTTP FIN-368 D-11 редакции 4.
- Исключение `display_name` из массива `required` схемы `upsert_household_member` обратно совместимо для вызывающих сторон, которые по-прежнему передают ключ.
- Задание `additionalProperties: false` у `upsert_household` и `upsert_household_member` отклоняет ранее молча игнорировавшиеся незаявленные ключи.
- Для присутствующего ключа `display_name` удаление крайних символов `U+0020 SPACE` и отказ пустой строки до HTTP сохраняются.
- Контракт HTTP эта задача не меняет.
- Контракт инструментов банковского счёта эта задача не меняет.

## Предположения, предусловия и ограничения

- На профиле прогона развёрнут HTTP-контракт FIN-368 редакции 4: список и запись домохозяйства и члена отдают ключ `accounting_subject`; успешный ответ члена не содержит ключ `display_name`; запись члена без ключа `display_name` при создании даёт код HTTP 422.
- Конкурентное изменение представления или соответствия между отдельными вызовами инструментов MCP отдельно не нормируется. Наблюдаемое значение относится к ответу данного вызова.

## Критерий приёмки

- Список домохозяйств и успешная запись домохозяйства возвращают связанный субъект учёта типа «группа» либо пустое представление.
- Список членов и успешная запись члена возвращают связанный субъект учёта типа «физическое лицо» либо пустое представление.
- При HTTP-контракте FIN-368 редакции 4 ответы списка членов и успешной записи члена не содержат ключ `display_name` на строке членства. MCP это поле самостоятельно не удаляет.
- Запись существующего члена без ключа `display_name` выполняется и сохраняет прежнее сохранённое имя.
- Запись нового члена без ключа `display_name` отклоняется.
- Запись домохозяйства и запись члена отклоняют аргументы назначения субъекта учёта до вызова HTTP.
- Запись домохозяйства не изменяет представление.
- Запись члена не изменяет соответствие.
- Поведение обёртки MCP покрыто автотестами на mock API: схема аргументов, обработчик и разбор конверта HTTP.
- Сценарии с постоянной базой проверяются прогоном функциональной приёмки. Автотесты на mock API этот прогон не заменяют.
- Справочник доступных инструментов MCP описывает наличие связанного субъекта учёта в ответах этих инструментов.
- Метка `mcp-gap` снята с задачи после поставки.

## Функциональное тестирование

### Предусловия

- Профиль данных: `cand`
- Постоянная база: стандартный путь `finance.db` приложения
- Канал: MCP после `finance_api_connect` с тем же профилем
- На том же профиле развёрнут HTTP-контракт FIN-368 редакции 4
- В профиле уже может быть активное домохозяйство; фикстуры этой задачи создают записи с `is_active` равным `false`
- Идентификаторы фикстуры: домохозяйство без представления `fin369-hh-unlinked`; домохозяйство с представлением `fin369-hh`; домохозяйство без членов `fin369-hh-empty`; член без соответствия `fin369-m-unlinked`; член с соответствием `fin369-m-linked`; идентификатор несоздаваемого члена `fin369-m-create-fail`
- Если записи с этими идентификаторами остались от предыдущего прогона, повторный прогон использует те же идентификаторы: запись домохозяйства обновляет имя; создание группы и установление соответствия не повторяют, если представление или соответствие уже есть; член `fin369-m-unlinked` не связывают с субъектом учёта
- Субъекты учёта, созданные предыдущим прогоном, допустимы как остаточное состояние
- Перед T8 строка члена `fin369-m-create-fail` отсутствует. Идентификатор не создаётся успешным вызовом. Если элемент с этим `id` есть в списке членов `fin369-hh`, T8 получает `BLOCKED`: штатного удаления члена эта задача не даёт
- Профиль `prod` для заполнения факта прогона не использовать без отдельной ops-команды
