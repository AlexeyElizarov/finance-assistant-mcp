# Погашение расхода через MCP

**Статус:** Утверждено (2026-08-09, rev.2).

## Назначение

* Создание, чтение, изменение, удаление и проверка покрытия погашения расхода недоступны через MCP.
* Операционные процедуры вынуждены обходить ограничение прямым вызовом HTTP API.

## Критерий приёмки

* Через MCP можно создать, прочитать, изменить сумму и удалить погашение расхода согласно целевому поведению.
* Через MCP можно прочитать список погашений позиции и состояние покрытия позиции согласно целевому поведению.
* Сценарий июльского полного и частичного покрытия воспроизводится через MCP без прямого HTTP.
* Доменные ошибки HTTP API погашения пробрасываются в ошибку инструмента без потери кода ошибки.
* Поведение покрыто функциональным тестированием.

## Объём и границы

### Входит в объём

#### Возможности

* В объём входит инструмент MCP создания погашения расхода.
* В объём входит инструмент MCP чтения погашения по идентификатору.
* В объём входит инструмент MCP изменения суммы погашения.
* В объём входит инструмент MCP удаления погашения.
* В объём входит инструмент MCP списка погашений по позиции.
* В объём входит инструмент MCP состояния покрытия позиции.
* В объём входит обход защиты закрытого учётного периода на путях записи тем же параметром, что у существующих инструментов записи операции.

#### Артефакты приёмки

* В объём входят обработчики и схемы инструментов в MCP-сервере.
* В объём входит модуль тонких обёрток над каноническими HTTP-путями FIN-273.
* В объём входят функциональные тесты.
* В объём входит обновление справочника доступных инструментов MCP.

### Не входит в объём

#### Зависимости и соседние возможности

* Не входит модель данных и слой сохранения погашения (FIN-269).
* Не входит проектирование HTTP API погашения (FIN-273).
* Не входит пользовательский интерфейс погашения (FIN-275).
* Не входит применение погашений июля на prod (FOPS-25).
* Не входит сопоставление сторон внутреннего перевода `I0001` (FIN-203).
* Не входит применение финансирования фонда из погашений (FIN-278).
* Не входит разделение операции по MCP (FIN-270).

#### Не планируется

* Не входит дублирование доменных инвариантов суммы, сторон и уникальности пары в MCP.
* Не входит изменение сумм, направлений, типов и контировки связанных операций и позиций при вызовах инструментов погашения.
* Не входит вложение массива погашений или полей покрытия в `query_transactions` и в ответ `get_transaction`.
* Не входит изменение семантики существующих инструментов MCP.
* Не входит автоматический подбор пар для погашения.
* Не входит один инструмент MCP с перечислением действия вместо отдельных инструментов.
* Не входит переименование путей `transactions` в `operations`.

## Обратная совместимость

* Шесть новых инструментов добавляются без изменения семантики существующих инструментов MCP.
* Контракт `query_transactions` этой задачей не меняется.
* Контракты `get_transaction` и `get_transaction_lines` этой задачей не меняются.
* Контракт HTTP API FIN-273 этой задачей не меняется.

## Целевое поведение

### Набор инструментов (D-01)

#### Таблица инструментов

| Инструмент MCP | Операция HTTP | Смысл |
| -------------- | ------------- | ----- |
| `create_expense_settlement` | `POST /api/v1/expense-settlements` | Создание погашения |
| `get_expense_settlement` | `GET /api/v1/expense-settlements/{settlement_id}` | Чтение погашения по идентификатору |
| `patch_expense_settlement` | `PATCH /api/v1/expense-settlements/{settlement_id}` | Изменение суммы погашения |
| `delete_expense_settlement` | `DELETE /api/v1/expense-settlements/{settlement_id}` | Удаление погашения |
| `list_expense_settlements` | `GET /api/v1/expense-settlements` | Список погашений по позиции (`line_id`) |
| `get_line_settlement_state` | `GET /api/v1/transaction-lines/{line_id}/settlement-state` | Состояние покрытия позиции |

#### Правила

* Инструменты являются тонкой обёрткой над каноническими путями FIN-273.
* Отдельный инструмент или сущность с именем «clear» / «operation-clear» не вводится: техническое имя Expense Settlement из FIN-269 / FIN-273.
* Покрытие суммы читается через `get_line_settlement_state` и `list_expense_settlements`, а не через поля выборки операций.
* Доменные инварианты не дублируются в MCP.

### Конвейер записи (D-02)

```
1. получить сессию API (профиль данных, базовый URL)
2. проверить аргументы MCP до HTTP
3. сформировать тело запроса (если метод его требует)
4. сформировать путь и параметр обхода закрытого периода
5. выполнить вызов метода POST, PATCH или DELETE
6. при успехе обернуть полезную нагрузку в конверт ok / profile / base и поле результата
7. иначе вернуть ошибку инструмента с телом ответа API
8. сетевые сбои пробросить без дополнительной обёртки
```

* Порядок шагов фиксирован.
* Один вызов MCP соответствует одному вызову канонического HTTP-метода записи.

### Конвейер чтения (D-03)

```
1. получить сессию API (профиль данных, базовый URL)
2. проверить аргументы MCP до HTTP
3. сформировать путь чтения и обязательные query-параметры
4. выполнить вызов метода GET
5. при успехе обернуть полезную нагрузку в конверт ok / profile / base и поле результата
6. иначе вернуть ошибку инструмента с телом ответа API
7. сетевые сбои пробросить без дополнительной обёртки
```

* Один вызов MCP соответствует одному вызову канонического `GET`.

### Модуль и регистрация (D-04)

* Логика обёрток размещается в модулях `scripts/` с именами, соответствующими инструментам (`create_expense_settlement.py`, `get_expense_settlement.py`, `patch_expense_settlement.py`, `delete_expense_settlement.py`, `list_expense_settlements.py`, `get_line_settlement_state.py`).
* Допускается общий вспомогательный модуль для проброса ошибок и конверта ответа, если это не меняет публичные контракты инструментов.
* Обработчики и схемы инструментов регистрируются в `server.py`.

### Валидация до HTTP (D-05)

* Тип аргумента проверяет схема MCP.
* Обработчик не дублирует проверку типов.
* Строковые идентификаторы пути (`settlement_id`, `line_id`) после `strip` непусты.
* Для `create_expense_settlement` поля `compensating_line_id`, `expense_line_id` и `amount` после `strip` непусты.
* Для `patch_expense_settlement` поле `amount` после `strip` непусто.
* Для `list_expense_settlements` параметр `line_id` после `strip` непуст.
* Нарушение правил до HTTP даёт `ValueError` без вызова API.
* Остальные инварианты сторон, суммы, уникальности пары и закрытого периода проверяет только backend.

### Параметр закрытого периода (D-06)

* Параметр обхода защиты закрытого учётного периода (`allow_closed`) необязателен у `create_expense_settlement`, `patch_expense_settlement` и `delete_expense_settlement`.
* Значение по умолчанию равно `false`.
* Семантика совпадает с FIN-273 и с инструментом `put_transaction`.
* Инструменты чтения параметр обхода не принимают.

### Результат успеха создания (D-13)

* Успешный ответ API имеет код HTTP 201.
* При успехе ответ инструмента содержит `ok: true`, профиль данных, базовый URL и объект `settlement`.
* Представление `settlement` совпадает с моделью погашения FIN-273.

```json
{
  "ok": true,
  "profile": "cand",
  "base": "http://127.0.0.1:8004",
  "settlement": {
    "id": "settlement-1",
    "compensating_line_id": "line-funding-1",
    "expense_line_id": "line-expense-55",
    "amount": "55.00"
  }
}
```

### Результат успеха чтения и изменения суммы (D-14)

* Успешный ответ API имеет код HTTP 200.

* Представление совпадает с успешным ответом создания.

### Инварианты (D-18)

* MCP не выполняет повторных попыток после получения доменной ошибки.
* MCP не выполняет поиск пар позиций и не предлагает кандидатов на погашение.
* После успешного вызова суммы, направления и контировка связанных операций и позиций не меняются этим инструментом.
* Состояние и агрегированные суммы покрытия читаются через `get_line_settlement_state`; состав погашений и суммы отдельных связей — через `list_expense_settlements`.

### Ошибки (D-19)

* Ответ API без кода успеха соответствующего пути даёт `RuntimeError` через `format_api_error`.
* Для создания успех — HTTP 201; для чтения, изменения суммы, списка и состояния — HTTP 200; для удаления — HTTP 204.
* Мягкий ответ вида `{ "ok": false }` без исключения не используется.
* Текст ошибки инструмента сохраняет код HTTP и код ошибки API при их наличии.

| Ситуация | Источник | Поведение MCP |
| -------- | -------- | ------------- |
| Пустой идентификатор пути или обязательное строковое поле | до HTTP | `ValueError` |
| Ошибка схемы тела | HTTP 422, `validation_error` | ошибка инструмента |
| Погашение не найдено | HTTP 404, `expense_settlement_not_found` | ошибка инструмента |
| Позиция не найдена | HTTP 404, `line_not_found` | ошибка инструмента |
| Стороны совпадают или принадлежат одной операции | HTTP 422, `invalid_settlement_sides` | ошибка инструмента |
| Компенсирующая позиция не из поступления | HTTP 422, `invalid_compensating_line` | ошибка инструмента |
| Расходная позиция не из списания | HTTP 422, `invalid_expense_line` | ошибка инструмента |
| Сумма погашения не положительна | HTTP 422, `invalid_settlement_amount` | ошибка инструмента |
| Сумма превышает доступный остаток стороны | HTTP 422, `settlement_amount_exceeded` | ошибка инструмента |
| Пара позиций уже имеет погашение | HTTP 422, `duplicate_settlement` | ошибка инструмента |
| Закрытый период без обхода | HTTP 422, `period_closed` | ошибка инструмента |

## Функциональное тестирование

### Предусловия

* Подключение MCP `finance_api_connect` с профилем данных `cand` или `test`.
* На том же профиле доступны пути FIN-273.
* Есть операция списания с позицией расхода и отдельная операция поступления с позицией компенсирующего зачисления в открытом учётном периоде.
* Для частичного покрытия есть разделённая операция списания с позициями `55.00` и `45.00` либо эквивалентный набор (FIN-272 / FIN-270).
* Есть операция в закрытом учётном периоде либо период временно закрыт для шага.
* Профиль `prod` для заполнения факта прогона не использовать без отдельной ops-команды.
