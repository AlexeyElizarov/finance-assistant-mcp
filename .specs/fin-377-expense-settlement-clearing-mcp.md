# Вывод специализированных MCP-инструментов погашения расхода после включения типа в общие инструменты документов выравнивания

**Статус:** Утверждено (2026-09-08, rev.3).

## Назначение

- Специализированные инструменты погашения расхода вызывают HTTP-пути покрытия, которые FIN-376 выводит, поэтому канал MCP остаётся на уничтоженном контракте.
- Нужна одна MCP-поверхность документов выравнивания для типа погашения расхода: те же общие инструменты, без второй семьи покрытия.

## Входит в объём

- Вывод из контракта шести специализированных инструментов погашения расхода.
- Обслуживание типа погашения расхода общими инструментами документов выравнивания.
- Приведение текста спецификации FIN-355, где множество типов ограничено двумя литералами или HTTP FIN-354 редакции 17, к третьему литералу и HTTP FIN-376.
- Обновление справочника доступных инструментов MCP.

## Вне объёма

- Не входят модель данных, DDL и инварианты слоя сохранения погашения расхода (FIN-375).
- Не входит проектирование HTTP-контракта документов выравнивания (FIN-376).
- Не входит изменение конвейера, схем аргументов, разворачивания ответа и классов ошибок обёртки инструментов FIN-355 сверх правок текста о множестве `document_type`.
- Не входит введение новых имён инструментов документов выравнивания сверх FIN-355.
- Не входит заглушка, псевдоним или перенаправление выведенного имени на инструмент FIN-355.
- Не входит переходный период, в котором выведенные имена ещё успешны.
- Не входит пользовательский интерфейс погашения расхода (FIN-275).
- Не входит применение переноса на операционном профиле (FOPS-42).
- Не входит разделение операции через MCP (FIN-270).
- Не входит успешное изменение суммы, заголовка или состава погашения расхода.
- Не входит отдельный инструмент состояния покрытия позиции.
- Не входит автоматический подбор пар для погашения.
- Не входит изменение суммы, валюты, типа или контировки связанных позиций вызовами этой задачи.

## Текущее поведение

| Область | Текущее поведение | Проблема |
| ------- | ----------------- | -------- |
| HTTP | FIN-376 выводит `/api/v1/expense-settlements` и `settlement-state`; тип `expense_settlement` живёт на `/api/v1/clearing-documents` | Специализированные инструменты MCP вызывают отсутствующие пути |
| MCP | Шесть инструментов FIN-271 требуют `amount`, успешно изменяют сумму и ходят на пути погашения расхода | Второй фасад покрытия; после FIN-376 вызовы не к чему привязать |
| MCP документов выравнивания | FIN-355 передаёт `document_type` в HTTP без `enum`; литералы проверяет HTTP | Текст FIN-355 описывает два типа FIN-354 редакции 17 |

## Целевое поведение

#### Выведенные имена (D-01)

- Выведенные имена этой задачи есть `create_expense_settlement`, `get_expense_settlement`, `patch_expense_settlement`, `delete_expense_settlement`, `list_expense_settlements` и `get_line_settlement_state`.
- MCP-сервер не регистрирует ни одно выведенное имя.
- MCP-сервер не регистрирует заглушку, псевдоним, перечисление действия и перенаправление выведенного имени на инструмент FIN-355.
- MCP-сервер не вводит новое специализированное имя покрытия расхода.
- Все операции MCP над документами типа `expense_settlement` выполняются только инструментами FIN-355.
- Это переопределяет FIN-271 D-01: шесть инструментов больше не являются контрактом MCP.

#### Исход вызова выведенного имени (D-02)

- Вызов выведенного имени MCP-сервер обрабатывает так же, как вызов любого имени, которое MCP-сервер не регистрирует.
- MCP-сервер не разбирает аргументы выведенного имени.
- MCP-сервер не получает сессию API и не вызывает HTTP на вызове выведенного имени.
- MCP-сервер не задаёт отдельное тело ошибки выведенного имени сверх ошибки незарегистрированного имени сервера.
- MCP-сервер не возвращает на вызове выведенного имени код ошибки HTTP и не возвращает `error.code` API.
- Норма D-02 действует для каждого выведенного имени по отдельности и для любого набора аргументов, включая пустой объект.
- На вызове выведенного имени MCP-сервер не вызывает HTTP, включая пути `/api/v1/expense-settlements`, `/api/v1/expense-settlements/{settlement_id}` и `/api/v1/transaction-lines/{line_id}/settlement-state`.

#### Регистрация и справочник (D-03)

- Схемы и обработчики выведенных имён не регистрируются в `server.py`.
- Наблюдаемый контракт модуля `scripts/expense_settlements.py` — недоступность его обработчиков как инструментов MCP. Наличие или отсутствие файла после снятия регистрации эта задача не нормирует.
- Справочник `mcp-gaps.md` не содержит ни одно выведенное имя.
- Справочник `mcp-gaps.md` сохраняет инструменты FIN-355, существовавшие на момент реализации этой задачи, без изменения смысла строк.
- После поставки метка `mcp-gap` снимается с FIN-377 при переводе задачи в Done и не входит в критерий функциональной приёмки.

#### Обратная совместимость (D-04)

- MCP-сервер допускает разрыв обратной совместимости с шестью инструментами FIN-271.
- Разрыв действует для каждого вызова выведенного имени после поставки этой задачи.
- MCP-сервер не сохраняет переходный период, в котором выведенные имена ещё успешны.
- Разрыв допускается: отдельный инструмент состояния покрытия позиции отсутствует.
- Клиенты, которые вызывали специализированные инструменты, переходят на инструменты FIN-355 и HTTP-модель документа выравнивания FIN-376 D-02.
- Универсальные инструменты FIN-355 сохраняют имена.
- Прочие существующие инструменты MCP эта задача не изменяет, кроме выведенных имён D-01.
- Допустимое состояние выпуска задаёт раздел «Вехи и контрольные точки выпуска».

#### Канал погашения расхода через MCP (D-05)

- Создание, чтение, список, пакетное создание, удаление и пакетное удаление типа `expense_settlement` через MCP выполняются инструментами FIN-355 по контракту FIN-355.
- Эта задача не задаёт конвейер, JSON Schema, `profile` и `base`, разворачивание ответа и классы ошибок обёртки FIN-355.
- Тело создания типа `expense_settlement` есть тело ветви FIN-376 D-03: ключи корня `document_type` и `items`; в каждом элементе `items` ключи `debit_credit_indicator` и `line_id`. Обработчик FIN-355 передаёт это тело в HTTP без `ValueError`, как тело типа `internal_transfer` с теми же ключами элемента.
- MCP-сервер не подставляет ключи `amount`, `compensating_line_id` и `expense_line_id` и не принимает их как заявленные поля инструментов FIN-355.
- Успешный объект `clearing_document` содержит модель HTTP FIN-376 D-02. Ключи `compensating_line_id`, `expense_line_id` и `amount` в этом объекте отсутствуют, если их нет в теле HTTP.
- Список по позиции выполняется инструментом `list_clearing_documents` с `line_id` и при необходимости `document_type` равным `expense_settlement`. Пустой массив `clearing_documents` для существующей позиции без документа этого типа является успешным результатом FIN-355.
- Список без фильтра `document_type` включает документы типа `expense_settlement` наряду с иными типами, которые вернул HTTP FIN-376 D-05.
- Чтение списка строк состава документа типа `expense_settlement` выполняется инструментом `list_clearing_document_items` и при успехе HTTP даёт успех FIN-355.
- Вызов `patch_clearing_document`, `create_clearing_document_item`, `patch_clearing_document_item` или `delete_clearing_document_item` для документа типа `expense_settlement` пробрасывает отказ HTTP FIN-376 D-06 без смены `error.code`.
- Смешанное пакетное создание и смешанное пакетное удаление типов, которые допускает HTTP FIN-376 D-04, MCP-сервер не запрещает.
- Коды HTTP FIN-376 D-08, включая `line_in_expense_settlement`, `invalid_compensating_line`, `invalid_expense_line`, `invalid_settlement_sides`, `invalid_settlement_currency`, `invalid_settlement_amount`, `invalid_settlement_overflow`, `period_closed`, `line_not_found`, `clearing_document_not_found`, `invalid_clearing_document_operation`, `validation_error` и `clearing_document_store_busy`, обработчик FIN-355 не переименовывает.
- MCP-сервер не возвращает код `expense_settlement_not_found` как собственный перевод.
- Наличие покрытия позиции читается списком документов FIN-355 с фильтром `line_id` и `document_type` равным `expense_settlement`. Отдельный инструмент состояния покрытия позиции не регистрируется.
- Связанные операции и позиции вызовами этой задачи MCP-сервер не изменяет, кроме изменений, которые выполняет сам HTTP-запрос.

#### Текст спецификации FIN-355 (D-06)

- Имена, схемы и обработчики двенадцати инструментов FIN-355 эта задача не меняет.
- Нормативные утверждения FIN-355, которые фиксируют ровно два литерала `document_type` или HTTP FIN-354 редакции 17 как единственный источник множества литералов, переопределяются: допустимые литералы `document_type` задаёт HTTP FIN-376, включая `expense_settlement`.
- Это переопределяет FIN-355 D-01 в части принадлежности доменных правил ветвей `document_type` только HTTP FIN-354 редакции 17: для литерала `expense_settlement` действует HTTP FIN-376.
- Это переопределяет FIN-355 D-12 в части фразы «документы обоих типов»: список без фильтра `document_type` включает записи всех типов, которые вернул HTTP, включая `expense_settlement`.
- Это переопределяет предусловие продуктового поведения FIN-355 «HTTP-контракт FIN-354» в части «оба значения `document_type`»: на профиле совместного выпуска развёрнут HTTP FIN-376 с тремя литералами.
- JSON Schema FIN-355 по-прежнему не задаёт `enum` для `document_type`.
- Файл спецификации FIN-355 при реализации этой задачи приводится к этим переопределениям. Имена инструментов и таблицы входа FIN-355 не меняются.

## Предположения, предусловия и ограничения

- HTTP FIN-376. На профиле прогона развёрнут HTTP-контракт FIN-376, включая третий литерал `document_type` и отсутствие путей погашения расхода.
- Схема версии 39. Слой сохранения FIN-375 уже применён; таблица `expense_settlements` отсутствует.
- Универсальные инструменты. На профиле прогона доступны инструменты FIN-355 по контракту FIN-355 с переопределениями D-06.
- Канонический идентификатор. Каждый заголовок типа `expense_settlement` в профиле приёмки имеет идентификатор канонического UUID по предусловию продуктового поведения FIN-376 «Канонический идентификатор погашения расхода».

## Критерий приёмки

#### Продуктовый результат

- Шесть специализированных имён погашения расхода отсутствуют в наборе инструментов MCP.
- Вызов каждого выведенного имени неотличим от вызова незарегистрированного имени; сессия API и HTTP не используются.
- Погашение расхода создаётся, читается, перечисляется по позиции и удаляется через универсальные инструменты документов выравнивания с типом `expense_settlement`.
- Состояние покрытия позиции определяется наличием документа типа `expense_settlement` в списке по `line_id`; отдельный инструмент состояния покрытия отсутствует.
- Частичное обновление заголовка и запись строк состава документа погашения расхода отклоняются кодом ошибки HTTP без смены `error.code`.
- Позиция, входящая в документ иного вида, принимается в погашение расхода, если инварианты HTTP выполнены.
- Универсальные инструменты документов выравнивания сохраняют прежние имена.
- Текст спецификации FIN-355 допускает третий литерал `expense_settlement` и не утверждает, что допустимы только два типа.

#### Контроль реализации

- Поведение, допускающее автоматизированную функциональную проверку, покрыто функциональными тестами.
- Автотесты проверяют отсутствие выведенных имён в регистрации и отсутствие получения сессии API и HTTP-вызова при попытке вызова каждого выведенного имени.
- Автотесты проверяют, что создание типа `expense_settlement` вызывает путь `/api/v1/clearing-documents` и не вызывает пути `/api/v1/expense-settlements`.
- Автотесты, которые проверяют регистрацию или успешный вызов выведенных инструментов FIN-271, удаляются либо актуализируются в соответствии с D-01. После изменения полный набор актуальных тестов каталога `tests/` не содержит ожиданий успешного вызова выведенных имён.
- Справочник доступных инструментов MCP не содержит выведенные имена и сохраняет инструменты FIN-355, существовавшие на момент реализации этой задачи.
