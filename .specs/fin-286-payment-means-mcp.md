# MCP-инструменты платёжных инструментов и сопоставлений средства с фондом

**Статус:** Утверждено (2026-08-09, rev.3).

## Назначение

* HTTP API платёжных инструментов и сопоставлений средства с фондом уже есть, но ops на MCP-only пути не могут вести эти справочники без прямого HTTP.
* Нужен MCP-доступ к обеим публичным поверхностям FIN-285 без raw HTTP.

## Критерий приёмки

* Справочник платёжных инструментов доступен через MCP для всех операций публичной HTTP API-поверхности инструментов согласно целевому поведению.
* Справочник сопоставлений платёжного средства с фондом доступен через MCP для всех операций публичной HTTP API-поверхности сопоставлений согласно целевому поведению.
* Доменные ошибки API пробрасываются в ошибку инструмента без потери кода ошибки.
* Поведение покрыто функциональным тестированием.
* Справочник доступных инструментов MCP обновлён.

## Объём и границы

### Входит в объём

#### Возможности

* В объём входят инструменты MCP списка платёжных инструментов профиля (с необязательными фильтрами).
* В объём входят инструменты MCP чтения платёжного инструмента по идентификатору.
* В объём входят инструменты MCP создания одного платёжного инструмента.
* В объём входят инструменты MCP пакетного создания платёжных инструментов.
* В объём входят инструменты MCP частичного обновления платёжного инструмента по идентификатору.
* В объём входят инструменты MCP пакетного частичного обновления платёжных инструментов.
* В объём входят инструменты MCP удаления платёжного инструмента по идентификатору.
* В объём входят инструменты MCP пакетного удаления платёжных инструментов.
* В объём входят инструменты MCP списка сопоставлений средства с фондом (с необязательными фильтрами).
* В объём входят инструменты MCP чтения сопоставления по идентификатору.
* В объём входят инструменты MCP создания одного сопоставления.
* В объём входят инструменты MCP пакетного создания сопоставлений.
* В объём входят инструменты MCP частичного обновления интервала сопоставления по идентификатору.
* В объём входят инструменты MCP пакетного частичного обновления сопоставлений.
* В объём входят инструменты MCP удаления сопоставления по идентификатору.
* В объём входят инструменты MCP пакетного удаления сопоставлений.

#### Артефакты приёмки

* В объём входят обработчики и схемы инструментов в MCP-сервере.
* В объём входит модуль тонких обёрток над HTTP API обеих поверхностей.
* В объём входят функциональные тесты.
* В объём входит обновление справочника доступных инструментов MCP.

### Не входит в объём

#### Зависимости и соседние возможности

* Не входят модель и слой сохранения платёжного инструмента (FIN-283).
* Не входят модель и слой сохранения сопоставлений (FIN-284).
* Не входит HTTP API обеих поверхностей (FIN-285).
* Не входит пользовательский интерфейс (FIN-287).
* Не входит привязка полей источника и инструмента на операции (FIN-288).
* Не входит подсказка фонда позиции операции (FIN-289).
* Не входит начальное заполнение каталога на cand / prod (FOPS-29).
* Не входит отчёт дерева банковской инфраструктуры (FIN-295).

#### Не планируется

* Не входит один инструмент MCP с перечислением действия вместо отдельных инструментов.
* Не входит термин «основной фонд» и поле `primary_fund_id`.
* Не входит колонка `fund_id` на счёте или инструменте.
* Не входит пагинация и клиентская сортировка списков.
* Не входит собственная доменная валидация тел сверх проверок до HTTP (формат UUID, overlap, RESTRICT — только backend).

## Обратная совместимость

* Шестнадцать новых инструментов добавляются без изменения семантики существующих инструментов MCP.
* Контракт HTTP API FIN-285 этой задачей не меняется.

## Целевое поведение

### Паритет поверхности платёжных инструментов (D-01)

Для публичной API-поверхности платёжных инструментов FIN-285 MCP предоставляет однозначно соответствующую поверхность: каждой операции HTTP API соответствует отдельный MCP-инструмент с той же функциональной семантикой. MCP не исключает и не добавляет самостоятельные операции предметной области.

Норма совпадает с проектным соглашением «Паритет HTTP API и MCP» в `standards/product/mcp-conventions.md`.

#### Таблица инструментов

| Инструмент MCP | Операция HTTP | Смысл |
| -------------- | ------------- | ----- |
| `list_payment_instruments` | `GET /api/v1/payment-instruments` | Список |
| `get_payment_instrument` | `GET /api/v1/payment-instruments/{instrument_id}` | Чтение по идентификатору |
| `create_payment_instrument` | `POST /api/v1/payment-instruments` | Создание одной записи |
| `create_payment_instruments` | `POST /api/v1/payment-instruments/batch` | Пакетное создание |
| `patch_payment_instrument` | `PATCH /api/v1/payment-instruments/{instrument_id}` | Частичное обновление по идентификатору |
| `patch_payment_instruments` | `PATCH /api/v1/payment-instruments` | Пакетное частичное обновление |
| `delete_payment_instrument` | `DELETE /api/v1/payment-instruments/{instrument_id}` | Удаление по идентификатору |
| `delete_payment_instruments` | `DELETE /api/v1/payment-instruments` | Пакетное удаление |

#### Общие правила набора (D-01 и D-02)

* Создание, изменение и удаление разведены по разным инструментам; индивидуальные и пакетные операции — тоже.
* Идентификатор сущности при создании задаёт слой сохранения; клиент MCP поле идентификатора при создании не передаёт.
* Один инструмент с перечислением действия не используется.
* Доменные правила тел, фильтров и кодов ошибок наследуются из FIN-285 без дублирования в MCP.
* Атомарность пакетов (целиком или никак при ошибке любого элемента) наследуется из FIN-285 (раздел «Пакетная атомарность»); MCP не реализует собственную атомарность и не агрегирует ошибки.

Для публичной API-поверхности сопоставлений средства с фондом FIN-285 MCP предоставляет однозначно соответствующую поверхность по общим правилам набора D-01 / D-02.

| `create_payment_means_fund_assignment` | `POST /api/v1/payment-means-fund-assignments` | Создание одной записи |
| `create_payment_means_fund_assignments` | `POST /api/v1/payment-means-fund-assignments/batch` | Пакетное создание |

| `delete_payment_means_fund_assignments` | `DELETE /api/v1/payment-means-fund-assignments` | Пакетное удаление |

### Общий конвейер (D-03)

```
1. получить сессию API (профиль данных, базовый URL)
2. проверить аргументы MCP до HTTP
3. собрать путь, параметры запроса и тело
4. выполнить вызов метода GET, POST, PATCH или DELETE
5. для успешных кодов ответа выполнить обработку согласно контракту FIN-285:
   - 200 / 201 — ожидать тело и обернуть сущность или коллекцию в конверт ok / profile / base
   - 204 — тело отсутствует; вернуть только конверт ok / profile / base
6. иначе вернуть ошибку инструмента с телом ответа API
7. сетевые сбои пробросить без дополнительной обёртки
```

* Успех операции определяется кодом HTTP, а не наличием или отсутствием тела в ответе.
* Доменные инварианты FIN-283 / FIN-284 / FIN-285 не дублируются в MCP.

### Модуль и регистрация (D-04)

* Логика тонких HTTP-обёрток обеих поверхностей размещается в одном модуле `scripts/payment_means.py` (как `scripts/banks.py` в FIN-293).
* Обработчики и схемы инструментов регистрируются в `server.py`.
* Справочник доступных инструментов обновляется в `mcp-gaps.md`.

### Валидация до HTTP (D-05)

* Тип аргумента проверяет схема MCP; обработчик не дублирует проверку типов.
* После `strip` должны быть непустыми: обязательные строковые параметры, строковые идентификаторы пути и элементов пакета, а также переданные строковые фильтры списка.
* Необязательные строковые поля тела (например `payment_network`, `holder_id`, `valid_to`), если переданы, этим правилом непустой строки не ограничиваются; пустая строка уходит в API как есть (без преобразования в `null`, см. D-06).
* Для частичного обновления одного инструмента присутствует хотя бы один из ключей: `display_name`, `payment_network`, `holder_id`, `valid_from`, `valid_to`.
* Для частичного обновления одного сопоставления присутствует хотя бы один из ключей `valid_from` или `valid_to`.
* Для пакетного создания инструментов / сопоставлений присутствует непустой список элементов (`payment_instruments` / `payment_means_fund_assignments`).
* Для пакетного обновления присутствует непустой список элементов; у каждого элемента после `strip` непуст `id`.
* Для пакетного удаления присутствует непустой список `ids`.
* Для списка сопоставлений совместность фильтров (`means_type` / `means_id` / `fund_id`) не проверяется в MCP (проверяет API).
* Нарушение правил до HTTP даёт `ValueError` без вызова API.
* Формат UUID, неизвестные поля HTTP, атомарность пакета и доменные инварианты проверяет только backend.

### Отсутствие ключа и явное обнуление (D-06)

* Ключ, отсутствующий в аргументах MCP, не попадает в JSON тела запроса и не попадает в query-параметры.
* Правило передачи `null` в HTTP действует только для полей, у которых `null` допустим по контракту FIN-285.
* Для таких полей ключ, переданный со значением `null`, уходит в JSON как `null` (например, `payment_network`, `holder_id`, `valid_to` у инструмента; `valid_to` у сопоставления).
* Пустая строка не преобразуется в `null`.
* Значение по умолчанию параметра в коде не смешивает «ключ не передан» и «ключ передан со значением `null`».
* Построение тела опирается на набор реально переданных полей аргументов.

### Инварианты (D-07)

* MCP не ослабляет инварианты HTTP API FIN-285.
* Тело запроса содержит только явно переданные ключи аргументов.
* Ответ REST не нормализуется: только конверт `ok` / `profile` / `base` и ключ сущности или коллекции; при коде HTTP 204 ключ сущности отсутствует.
