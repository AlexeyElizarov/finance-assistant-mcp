# Универсальное частичное обновление полей операции через MCP

**Статус:** Утверждено (2026-08-07, rev.5)

## Назначение

* Поля операции нельзя частично обновлять через MCP по полному каноническому контракту HTTP.
* Идентификатор фонда на операции нельзя назначить или сбросить через MCP.
* Операционные процедуры вынуждены обходить ограничение прямым вызовом HTTP API или узкими инструментами записи.

## Критерий приёмки

* Через MCP можно частично обновить объявленный набор полей одной операции согласно целевому поведению.
* Через MCP можно назначить и сбросить идентификатор фонда на операции в том же инструменте.
* Смешанное обновление классификации, проекта и фонда одним вызовом доступно согласно целевому поведению.
* Доменные ошибки HTTP API частичного обновления операции пробрасываются в ошибку инструмента без потери кода ошибки.
* Поведение покрыто функциональным тестированием.

## Объём и границы

### Входит в объём

#### Возможности

* В объём входит инструмент MCP универсального частичного обновления полей одной операции.
* В объём входят все поля канонического HTTP-контракта частичного обновления: классификация, проект и идентификатор фонда.
* В объём входит обход защиты закрытого учётного периода тем же параметром, что у существующих инструментов записи операции.

#### Артефакты приёмки

* В объём входят обработчик и схема инструмента в MCP-сервере.
* В объём входит модуль тонкой обёртки над каноническим HTTP-путём частичного обновления операции.
* В объём входят функциональные тесты.
* В объём входит обновление справочника доступных инструментов MCP.

### Не входит в объём

#### Зависимости и соседние возможности

* Не входит универсальное частичное обновление полей операции по HTTP (FIN-258).
* Не входит чтение идентификатора фонда в выборке операций через MCP (FIN-256).
* Не входят начальное заполнение и миграция идентификатора фонда на операциях (FOPS-19).
* Не входит назначение фондов на операции июля (FOPS-18).
* Не входит назначение фонда на операцию в пользовательском интерфейсе (FIN-243).
* Не входит удаление колонки владельца операции (FIN-255).
* Не входит удаление HTTP-фасадов классификации и проекта (FIN-261, FIN-262).

#### Не планируется

* Не входит удаление или переписывание инструмента `put_transaction_category` в этой задаче.
* Не входит массовое частичное обновление нескольких операций одним вызовом.
* Не входит отдельный HTTP-путь только для идентификатора фонда.
* Не входит расширение поверхности классификации операции полем идентификатора фонда.
* Не входит фильтр выборки операций по идентификатору фонда.
* Не входит дублирование доменных правил классификации, проекта и фонда в MCP.

## Обратная совместимость

* Новый инструмент добавляется без изменения семантики существующих инструментов MCP.
* Инструмент `put_transaction_category` сохраняет прежнее поведение и по-прежнему вызывает фасад классификации.
* Существующие функциональные тесты прочих инструментов не регрессируют.

## Целевое поведение

### Инструмент (D-01)

* Инструмент MCP называется `put_transaction`.
* Инструмент является канонической MCP-поверхностью записи полей операции.
* Инструмент вызывает только канонический путь частичного обновления операции.
* Метод запроса равен `PATCH`.
* Путь запроса равен `/api/v1/transactions/{transaction_id}`.
* Набор полей тела совпадает с FIN-258.
* Поверхности `/category` и `/project` этим инструментом не вызываются.
* Отдельные флаги сброса полей не вводятся.

### Конвейер (D-02)

```
1. получить сессию API (профиль данных, базовый URL)
2. проверить аргументы MCP до HTTP
3. сформировать тело только из присутствующих ключей объявленного набора полей (D-07)
4. сформировать путь и параметр обхода закрытого периода
5. выполнить вызов метода PATCH
6. при успехе обернуть полезную нагрузку в конверт ok / profile / base / transaction
7. иначе вернуть ошибку инструмента с телом ответа API
8. сетевые сбои пробросить без дополнительной обёртки
```

* Порядок шагов фиксирован.
* Доменные инварианты классификации, проекта и фонда не дублируются в MCP.

### Модуль и регистрация (D-03)

* Логика обёртки размещается в `scripts/put_transaction.py`.
* Обработчик и схема инструмента регистрируются в `server.py`.

### Валидация до HTTP (D-04)

* Тип аргумента проверяет схема MCP.
* Обработчик не дублирует проверку типов.
* Идентификатор операции (`transaction_id`) после `strip` непуст.
* В аргументах присутствует хотя бы один ключ из объявленного набора полей (D-07).
* Нарушение правил до HTTP даёт `ValueError` без вызова API.
* Сочетаемость полей классификации и проекта, валидность фонда и защиту закрытого периода проверяет только backend.

### Отсутствие ключа и явное обнуление (D-05)

* Ключ, отсутствующий в аргументах MCP, не попадает в JSON тела запроса.
* Ключ, переданный со значением `null`, уходит в JSON как `null`.
* Пустая строка не преобразуется в `null` на стороне MCP.
* Значение по умолчанию параметра в коде не смешивает «ключ не передан» и «ключ передан со значением `null`».
* Построение тела опирается на набор реально переданных полей аргументов.
* Семантика omit / сброс / назначение для каждого поля определяется только FIN-258.

### Параметр закрытого периода (D-06)

* Параметр обхода защиты закрытого учётного периода (`allow_closed`) необязателен.
* Значение по умолчанию равно `false`.
* Семантика совпадает с FIN-258 и с инструментом записи классификации операции.

### Вход (D-07)

* Под объявленным набором полей понимаются поля тела запроса, перечисленные в таблице «Поля тела» ниже.

#### Параметры вызова

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; по умолчанию из сессии или `prod` |
| `base` | string | нет | Базовый URL API; по умолчанию из сессии |
| `transaction_id` | string | да | Идентификатор операции в пути |
| `allow_closed` | bool | нет | Обход защиты закрытого учётного периода; по умолчанию `false` |

#### Поля тела

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `transaction_category` | string \| null | нет | Категория операции |
| `category_source` | string \| null | нет | Источник категории |
| `reconciliation_note` | string \| null | нет | Примечание сверки |
| `transaction_type` | string \| null | нет | Тип операции |
| `expense_owner` | string \| null | нет | Владелец операции |
| `project` | string \| null | нет | Проект |
| `project_source` | string \| null | нет | Источник проекта |
| `fund_id` | string \| null | нет | Идентификатор фонда |

* В схеме MCP обязателен только `transaction_id`.
* Условная обязательность «хотя бы одно поле из объявленного набора» проверяется в конвейере до HTTP.
* Допускаются запросы только с фондом, только с классификацией, только с проектом, только с владельцем операции и смешанные тела.

### Результат успеха (D-08)

* Успешный ответ API имеет код HTTP 200 (как FIN-258).
* При успехе ответ инструмента содержит `ok: true`, профиль данных, базовый URL и объект `transaction`.
* Объект `transaction` содержит идентификатор операции (`id`) и все поля объявленного набора (D-07).
* Если соответствующее поле отсутствует в ответе API, инструмент возвращает его со значением `null`.

```json
{
  "ok": true,
  "profile": "cand",
  "base": "http://127.0.0.1:8001",
  "transaction": {
    "id": "<uuid>",
    "transaction_type": "C",
    "transaction_category": "C0003",
    "category_source": "manual",
    "reconciliation_note": "",
    "expense_owner": "nikolai",
    "project": "PR005",
    "project_source": "manual",
    "fund_id": "personal.elizarov.2026-08"
  }
}
```

### Инварианты (D-09)

* Тело HTTP-запроса содержит только ключи объявленного набора полей (D-07), реально переданные в аргументах.
* Один вызов MCP соответствует одному вызову канонического `PATCH` API.
* MCP не выполняет повторных попыток после получения доменной ошибки.
* MCP не выполняет поиск фонда, категории, проекта или члена домохозяйства до вызова HTTP API.

### Ошибки (D-10)

* Ответ API без кода HTTP 200 (успех по FIN-258) даёт `RuntimeError` через `format_api_error`.
* Мягкий ответ вида `{ "ok": false }` без исключения не используется.
* Текст ошибки инструмента сохраняет код HTTP и код ошибки API при их наличии.

| Ситуация | Источник | Поведение MCP |
| -------- | -------- | ------------- |
| Пустой идентификатор операции | до HTTP | `ValueError` |
| Нет ни одного ключа объявленного набора полей (D-07) | до HTTP | `ValueError` |
| Операция не найдена | HTTP 404 | ошибка инструмента |
| Пустое тело или неизвестный ключ на API | HTTP 422, `validation_error` | ошибка инструмента |
| Ошибки классификации / типа / примечания / владельца | HTTP 422, коды FIN-258 | ошибка инструмента |
| Ошибки проекта | HTTP 422, коды FIN-118 | ошибка инструмента |
| Неизвестный фонд | HTTP 404, `unknown_fund` | ошибка инструмента |
| Фонд не принадлежит активному домохозяйству | HTTP 422, `fund_not_in_active_household` | ошибка инструмента |
| Дата операции вне интервала фонда | HTTP 422, `fund_not_valid_for_transaction_date` | ошибка инструмента |
| Закрытый период без обхода | HTTP 422, `period_closed` | ошибка инструмента |

## Функциональное тестирование

### Предусловия

* Подключение MCP `finance_api_connect` с профилем данных `cand` или `test`.
* На том же профиле доступен канонический путь частичного обновления операции.
* В справочнике есть фонд активного домохозяйства с интервалом, покрывающим дату выбранной операции.
* Есть операция без назначенного фонда и операция, пригодная для правки классификации или проекта.
* Профиль `prod` для заполнения факта прогона не использовать без отдельной ops-команды.
