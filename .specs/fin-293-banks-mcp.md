# MCP-инструменты справочника банков и ссылки счёта на банк

**Статус:** Утверждено (2026-08-09, rev.4).

## Назначение

* Нужен MCP-доступ к справочнику банков профиля и к ссылке банковского счёта на банк без прямого вызова HTTP API.

## Критерий приёмки

* Справочник банков доступен через MCP для всех операций публичной HTTP API-поверхности банков согласно целевому поведению.
* Запись банковского счёта через MCP принимает и передаёт обязательную ссылку на банк.
* Чтение списка банковских счетов через MCP всегда содержит ключ ссылки на банк.
* При наличии ссылки на банк в ответе HTTP API счёта значение в ответе MCP совпадает с ответом API.
* Если в ответе HTTP API ключ ссылки на банк отсутствует, в ответе MCP значение равно `null`.
* Доменные ошибки API банков и счетов пробрасываются в ошибку инструмента без потери кода ошибки.
* Поведение покрыто функциональным тестированием.

## Объём и границы

### Входит в объём

#### Возможности

* В объём входят инструменты MCP списка банков профиля.
* В объём входят инструменты MCP чтения банка по идентификатору.
* В объём входят инструменты MCP создания одного банка.
* В объём входят инструменты MCP пакетного создания банков.
* В объём входят инструменты MCP частичного обновления банка по идентификатору.
* В объём входят инструменты MCP пакетного частичного обновления банков.
* В объём входят инструменты MCP удаления банка по идентификатору.
* В объём входят инструменты MCP пакетного удаления банков.
* В объём входит обязательная ссылка на банк при записи банковского счёта через существующий инструмент upsert.
* В объём входит чтение ссылки на банк в списке банковских счетов через существующий инструмент списка.

#### Артефакты приёмки

* В объём входят обработчики и схемы инструментов справочника в MCP-сервере.
* В объём входит модуль тонких обёрток над HTTP API банков.
* В объём входит расширение существующего модуля счетов полем ссылки на банк.
* В объём входят функциональные тесты.
* В объём входит обновление справочника доступных инструментов MCP.

### Не входит в объём

#### Зависимости и соседние возможности

* Не входят модель и слой сохранения банка (FIN-291).
* Не входит HTTP API банков и поле ссылки на банк на счетах (FIN-292).
* Не входит ведение банков и банка на счёте в пользовательском интерфейсе (FIN-294).
* Не входит начальное заполнение банков и ссылок на существующих счетах (FOPS-31).
* Не входят инструменты MCP платёжных инструментов (FIN-286).
* Не входит основной фонд на счёте или инструменте (FIN-284).
* Не входит отчёт дерева банковской инфраструктуры (FIN-295).

#### Не планируется

* Не входит один инструмент MCP с перечислением действия вместо отдельных инструментов.
* Не входит отдельное чтение банковского счёта по идентификатору.
* Не входит смена модели идентификатора банковского счёта.
* Не входит подмена канала импорта ссылкой на банк или вывод одного из другого.

## Факт реализации (до)

| Область | Текущее поведение | Проблема |
| ------- | ----------------- | -------- |
| MCP банков | Инструментов справочника банков нет | Ops не ведут банки без raw HTTP |
| MCP счетов | `list_bank_accounts` / `upsert_bank_account` по FIN-240 без ссылки на банк | После FIN-292 запись счёта без ссылки на банк отклоняется API; MCP не передаёт поле |
| HTTP | FIN-292: восемь операций банков (list / get / create / create-batch / patch / patch-batch / delete / delete-batch) и обязательная ссылка на банк на `PUT` счёта | Нужна MCP-поверхность с полным паритетом |

## Обратная совместимость

* Восемь новых инструментов справочника банков добавляются без изменения семантики прочих существующих инструментов MCP, кроме перечисленных ниже.
* Инструмент `upsert_bank_account` становится обязательным по полю ссылки на банк: вызов без этого поля даёт ошибку до HTTP или ошибку инструмента по ответу API.
* Инструмент `list_bank_accounts` добавляет ключ ссылки на банк в элементы списка без изменения существующих полей счёта.
* Контракт HTTP API банков и счетов этой задачей не меняется.
* Канал импорта на счёте остаётся отдельным обязательным полем и не подменяется ссылкой на банк.

## Целевое поведение

### Паритет поверхности банков (D-01)

Для публичной банковской API-поверхности FIN-292 MCP предоставляет однозначно соответствующую поверхность: каждой операции HTTP API соответствует отдельный MCP-инструмент с той же функциональной семантикой. MCP не исключает и не добавляет самостоятельные операции предметной области.

Норма совпадает с проектным соглашением «Паритет HTTP API и MCP» в `standards/product/mcp-conventions.md`.

#### Таблица инструментов

| Инструмент MCP | Операция HTTP | Смысл |
| -------------- | ------------- | ----- |
| `list_banks` | `GET /api/v1/banks` | Список |
| `get_bank` | `GET /api/v1/banks/{bank_id}` | Чтение по идентификатору |
| `create_bank` | `POST /api/v1/banks` | Создание одной записи |
| `create_banks` | `POST /api/v1/banks/batch` | Пакетное создание |
| `patch_bank` | `PATCH /api/v1/banks/{bank_id}` | Частичное обновление по идентификатору |
| `patch_banks` | `PATCH /api/v1/banks` | Пакетное частичное обновление |
| `delete_bank` | `DELETE /api/v1/banks/{bank_id}` | Удаление по идентификатору |
| `delete_banks` | `DELETE /api/v1/banks` | Пакетное удаление |

#### Правила набора

* Создание, изменение и удаление разведены по разным инструментам; индивидуальные и пакетные операции — тоже.
* Идентификатор банка при создании задаёт слой сохранения; клиент MCP поле идентификатора при создании не передаёт.
* Один инструмент с перечислением действия не используется.
* Доменные правила тел, атомарности пакетов и кодов ошибок наследуются из FIN-292 без дублирования в MCP.

### Общий конвейер справочника (D-02)

```
1. получить сессию API (профиль данных, базовый URL)
2. проверить аргументы MCP до HTTP
3. собрать путь, параметры запроса и тело
4. выполнить вызов метода GET, POST, PATCH или DELETE
5. при коде HTTP 200 или 201 ожидать тело ответа и обернуть сущность или коллекцию в конверт ok / profile / base
6. при коде HTTP 204 не ожидать тела ответа и вернуть только конверт ok / profile / base
7. иначе вернуть ошибку инструмента с телом ответа API
8. сетевые сбои пробросить без дополнительной обёртки
```

* Порядок шагов фиксирован.
* Успех операции определяется кодом HTTP, а не наличием или отсутствием тела в ответе.
* Доменные инварианты банка не дублируются в MCP.

### Модуль и регистрация (D-03)

* Логика обёрток справочника банков размещается в `scripts/banks.py`.
* Расширение записи и чтения ссылки на банк на счетах выполняется в существующем `scripts/households.py`.
* Обработчики и схемы инструментов регистрируются в `server.py`.
* Справочник доступных инструментов обновляется в `mcp-gaps.md`.

### Валидация до HTTP (D-04)

* Проверяется только строковое значение после `strip`.
* Тип аргумента проверяет схема MCP; обработчик не дублирует проверку типов.
* Обязательные строковые идентификаторы пути после `strip` непусты.
* Для создания одной записи обязательны непустые после `strip` отображаемое имя.
* Для частичного обновления одной записи присутствует хотя бы один ключ отображаемого имени или банковского идентификационного кода.
* Для пакетного создания присутствует непустой список элементов `banks`.
* Для пакетного обновления присутствует непустой список элементов `banks`; у каждого элемента после `strip` непуст идентификатор.
* Для пакетного удаления присутствует непустой список идентификаторов `ids`; каждый элемент после `strip` непуст.
* Для записи счёта обязательна непустая после `strip` ссылка на банк.
* Нарушение правил до HTTP даёт `ValueError` без вызова API.
* Формат UUID, неизвестные поля HTTP, атомарность пакета и доменные инварианты FIN-291 / FIN-292 проверяет только backend.

### Отсутствие ключа и явное обнуление (D-05)

* Ключ, отсутствующий в аргументах MCP, не попадает в JSON тела запроса.
* Правило передачи `null` в HTTP действует только для полей, у которых `null` допустим по контракту инструмента.
* Для таких полей ключ, переданный со значением `null`, уходит в JSON как `null` (например, `bic` при создании и частичном обновлении банка).
* Для полей, у которых `null` по контракту инструмента недопустим (например, `bank_id` при записи счёта), явная передача `null` отклоняется до HTTP по норме соответствующего раздела (D-12).
* Пустая строка не преобразуется в `null`.
* Значение по умолчанию параметра в коде не смешивает «ключ не передан» и «ключ передан со значением `null`».
* Построение тела опирается на набор реально переданных полей аргументов.

### Инварианты (D-06)

* MCP не ослабляет инварианты HTTP API банков и счетов.
* Тело запроса содержит только явно переданные ключи аргументов.
* Ответ REST не нормализуется: только конверт `ok` / `profile` / `base` и ключ сущности или коллекции; при коде HTTP 204 ключ сущности отсутствует.

### Ошибки справочника банков (D-11)

* Ответ API с кодом, отличным от успеха операции, даёт `RuntimeError` через `format_api_error`.
* Мягкий ответ вида `{ "ok": false }` без исключения не используется.
* Все доменные ошибки полностью наследуются из FIN-292; MCP не вводит собственных кодов ошибок справочника банков.

### Ссылка на банк при записи счёта (D-12)

#### Вход `upsert_bank_account`

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| поля FIN-240 | … | … | Без изменения смысла |
| `bank_id` | string | да | Ссылка на банк; UUID существующего банка профиля |

#### Правила

* Поле `bank_id` обязательно при каждом успешном вызове `upsert_bank_account`.
* Отсутствие ключа `bank_id` или пустая строка после `strip` даёт `ValueError` до HTTP.
* Значение `null` для `bank_id` не допускается на стороне MCP: при явной передаче `null` — `ValueError` до HTTP.
* Канал импорта (`provider`) остаётся обязательным и независимым от `bank_id`.
* Успех соответствует ответу API с кодом HTTP 200; в объекте `bank_account` присутствует тот же `bank_id`.
* Неизвестный банк даёт ошибку инструмента по ответу API с кодом HTTP 404 и кодом ошибки `bank_not_found`.
* Невалидный UUID даёт ошибку инструмента по ответу API с кодом HTTP 422 и кодом ошибки `validation_error`.

### Ссылка на банк при чтении счетов (D-13)

* Каждый элемент коллекции `bank_accounts` в ответе `list_bank_accounts` всегда содержит ключ `bank_id`.
* Значение берётся из ответа HTTP API счёта.
* Отсутствующий ключ в ответе API даёт значение `null` в элементе MCP.
* Для унаследованных строк до начального заполнения значение может быть `null`.

## Функциональное тестирование

### Предусловия

* Подключение MCP `finance_api_connect` с профилем данных `cand` или `test`.
