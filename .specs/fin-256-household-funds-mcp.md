# Поддержка справочника фондов и идентификатора фонда на операции в MCP

**Статус:** Утверждено (2026-08-07, rev.10)

## Назначение

* Справочник фондов нельзя читать и вести через MCP.
* Идентификатор фонда на операции нельзя читать и назначать через MCP.
* Операционные процедуры вынуждены обходить ограничение прямым вызовом HTTP API.

## Критерий приёмки

* Справочник фондов доступен через MCP для списка, чтения, создания и частичного обновления согласно целевому поведению.
* Неагрегированная выборка операций через MCP всегда содержит ключ идентификатора фонда (`fund_id`).
* При наличии идентификатора фонда в HTTP API операции значение в строке MCP совпадает с ответом API.
* Если в ответе HTTP API ключ идентификатора фонда отсутствует, в строке MCP значение равно `null`.
* Доменные ошибки API справочника пробрасываются в ошибку инструмента без потери кода ошибки.
* Поведение покрыто функциональным тестированием.

## Объём и границы

### Входит в объём

#### Возможности

* В объём входят инструменты MCP списка фондов домохозяйства.
* В объём входят инструменты MCP чтения фонда по идентификатору.
* В объём входят инструменты MCP создания фонда.
* В объём входят инструменты MCP частичного обновления фонда (переименование и закрытие либо сужение интервала).
* В объём входит чтение идентификатора фонда в неагрегированной выборке операций через MCP (`query_transactions`).

#### Артефакты приёмки

* В объём входят обработчики и схемы инструментов справочника в MCP-сервере.
* В объём входит модуль тонких обёрток над HTTP API справочника.
* В объём входит дополнительное поле идентификатора фонда в строках `query_transactions`.
* В объём входят функциональные тесты.
* В объём входит обновление справочника доступных инструментов MCP.

### Не входит в объём

#### Зависимости и соседние возможности

* Не входят модель и слой сохранения фонда (FIN-251).
* Не входит HTTP API справочника фондов (FIN-253).
* Не входит универсальное частичное обновление полей операции по HTTP (FIN-258).
* Не входит назначение и сброс идентификатора фонда на операции через MCP (FIN-258).
* Не входит идентификатор фонда в HTTP-представлении операции (FIN-259).
* Полная реализация этой задачи выполняется после FIN-259: сначала HTTP-ответ операции с `fund_id`, затем FIN-256 целиком (справочник и чтение в выборке).
* Не входят начальное заполнение и миграция идентификатора фонда на операциях (FOPS-19).
* Не входит назначение фондов на операции июля (FOPS-18).
* Не входит назначение фонда на операцию в пользовательском интерфейсе (FIN-243).
* Не входит ведение справочника фондов в пользовательском интерфейсе (FIN-257).
* Не входит удаление колонки владельца операции (FIN-255).
* Не входит снятие маппинга контура (FOPS-14, FIN-153).

#### Не планируется

* Не входит удаление фонда через MCP.
* Не входит обновление при повторном создании (создание только если записи ещё нет).
* Не входит фильтр выборки операций по идентификатору фонда в первой версии.
* Не входит один инструмент MCP с перечислением действия вместо отдельных инструментов.

## Обратная совместимость

* Четыре новых инструмента справочника добавляются без изменения семантики существующих инструментов MCP.
* Повторный вызов создания с тем же идентификатором фонда даёт ошибку инструмента по ответу API с кодом HTTP 409 и кодом ошибки `fund_already_exists`.
* Поле `fund_id` в строках `query_transactions` добавляется без изменения существующих полей; вызовы без опоры на него не ломаются.
* Контракт HTTP API справочника фондов не меняется этой задачей.
* Расширение `PATCH …/category` полем `fund_id` не выполняется.

## Целевое поведение

### Набор инструментов справочника (D-01)

#### Таблица инструментов

| Инструмент MCP | Операция HTTP | Смысл |
| -------------- | ------------- | ----- |
| `list_household_funds` | `GET /api/v1/households/{household_id}/funds` | Список |
| `get_household_fund` | `GET /api/v1/households/{household_id}/funds/{fund_id}` | Чтение по идентификатору |
| `create_household_fund` | `PUT /api/v1/households/{household_id}/funds/{fund_id}` | Создание (идентификатор задаёт клиент в пути) |
| `patch_household_fund` | `PATCH /api/v1/households/{household_id}/funds/{fund_id}` | Переименование и/или закрытие либо сужение интервала |

#### Правила набора

* Создание и изменение разведены по разным инструментам.
* Повторное создание поверх существующей записи через `create_household_fund` запрещено на стороне API и даёт ошибку инструмента.
* Один инструмент с перечислением действия не используется.

### Общий конвейер справочника (D-02)

```
1. получить сессию API (профиль данных, базовый URL)
2. проверить аргументы MCP до HTTP
3. собрать путь, параметры запроса и тело
4. выполнить вызов метода GET, PUT или PATCH
5. при успехе обернуть полезную нагрузку ответа API в конверт ok / profile / base
6. иначе вернуть ошибку инструмента с телом ответа API
7. сетевые сбои пробросить без дополнительной обёртки
```

* Порядок шагов фиксирован.
* Доменные инварианты фонда не дублируются в MCP.

### Модуль и регистрация (D-03)

* Логика обёрток размещается в `scripts/household_funds.py`.
* Обработчики и схемы инструментов регистрируются в `server.py`.

### Валидация до HTTP (D-04)

* Проверяется только строковое значение после `strip`.
* Тип аргумента проверяет схема MCP; обработчик не дублирует проверку типов.
* Обязательные строковые идентификаторы пути после `strip` непусты.
* Для создания обязательны непустые после `strip` отображаемое имя (`name`), правило распределения (`allocation_rule`) и начало интервала действия (`valid_from`).
* Для частичного обновления присутствует хотя бы один ключ отображаемого имени (`name`) или конца интервала действия (`valid_to`).
* Нарушение правил до HTTP даёт `ValueError` без вызова API.
* Формат дат, сочетание `equal_share` с членом домохозяйства и пересечения интервалов проверяет только backend.

### Отсутствие ключа и явное обнуление (D-05)

* Ключ, отсутствующий в аргументах MCP, не попадает в JSON тела запроса.
* Ключ, переданный со значением `null`, уходит в JSON как `null`.
* Пустая строка не преобразуется в `null`.
* Значение по умолчанию параметра в коде не смешивает «ключ не передан» и «ключ передан со значением `null`».
* Построение тела опирается на набор реально переданных полей аргументов.

### Инварианты справочника (D-06)

* MCP не ослабляет инварианты HTTP API справочника фондов.
* Тело запроса содержит только явно переданные ключи аргументов.

### Список фондов (D-07)

#### Вход

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; по умолчанию `prod` |
| `base` | string | нет | Базовый URL API; по умолчанию из сессии |
| `household_id` | string | да | Идентификатор домохозяйства в пути |
| `applicable_on` | string | нет | Локальная дата `YYYY-MM-DD` для фильтра применимости |

#### Результат

* При успехе ответ инструмента содержит `ok: true`, профиль, базовый URL и коллекцию `funds`.
* Пустой список фондов допустим и сохраняет `ok: true`.
* Неверный `applicable_on` даёт ошибку инструмента по ответу API с кодом HTTP 422.

### Чтение фонда (D-08)

#### Вход

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; по умолчанию `prod` |
| `base` | string | нет | Базовый URL API; по умолчанию из сессии |
| `household_id` | string | да | Идентификатор домохозяйства в пути |
| `fund_id` | string | да | Идентификатор фонда в пути |

#### Результат

* При успехе ответ инструмента содержит `ok: true` и объект `fund`.
* Отсутствие фонда или фонд другого домохозяйства даёт ошибку инструмента по ответу API с кодом HTTP 404 и кодом ошибки `unknown_fund`.

### Создание фонда (D-09)

#### Вход

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; по умолчанию `prod` |
| `base` | string | нет | Базовый URL API; по умолчанию из сессии |
| `household_id` | string | да | Идентификатор домохозяйства в пути |
| `fund_id` | string | да | Идентификатор фонда в пути |
| `name` | string | да | Отображаемое имя |
| `allocation_rule` | string | да | `before_split` или `equal_share` |
| `valid_from` | string | да | Начало интервала действия `YYYY-MM-DD` |
| `member_id` | string \| null | нет | Идентификатор члена домохозяйства; отсутствие или `null` означает субъект «домохозяйство» |
| `valid_to` | string \| null | нет | Конец интервала действия; отсутствие или `null` означает открытый интервал |

#### Результат

* Успешное создание соответствует ответу API с кодом HTTP 201.
* При успехе ответ инструмента содержит `ok: true` и объект `fund`.
* Занятый идентификатор фонда в профиле даёт ошибку инструмента по ответу API с кодом HTTP 409 и кодом ошибки `fund_already_exists`.

### Частичное обновление фонда (D-10)

#### Вход

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; по умолчанию `prod` |
| `base` | string | нет | Базовый URL API; по умолчанию из сессии |
| `household_id` | string | да | Идентификатор домохозяйства в пути |
| `fund_id` | string | да | Идентификатор фонда в пути |
| `name` | string | условно | Новое отображаемое имя |
| `valid_to` | string \| null | условно | Новый конец интервала действия |

* Хотя бы одно из полей `name` или `valid_to` должно присутствовать в аргументах.

#### Результат

* Успешное обновление соответствует ответу API с кодом HTTP 200.
* При успехе ответ инструмента содержит `ok: true` и объект `fund`.
* Повторное открытие интервала (`valid_to: null`) даёт ошибку инструмента по коду ошибки `fund_validity_extension_forbidden`.

### Ошибки справочника (D-11)

* Ответ API с кодом, отличным от успеха операции, даёт `RuntimeError` через `format_api_error`.
* Мягкий ответ вида `{ "ok": false }` без исключения не используется.
* Коды доменных ошибок совпадают с HTTP API справочника фондов и моделью фонда.

### Чтение идентификатора фонда в выборке операций (D-12)

* Неагрегированная строка `query_transactions` всегда содержит ключ `fund_id`.
* Значение берётся из ответа HTTP API операции.
* Отсутствующий ключ в ответе API даёт значение `null` в строке MCP.
* Агрегация по месяцу не меняется.
* Фильтр выборки по идентификатору фонда в первой версии не вводится.

### Граница записи идентификатора фонда (D-13)

* Назначение и сброс идентификатора фонда на операции через MCP не входят в объём этой задачи.
* Будущая MCP-запись опирается на универсальное частичное обновление операции (FIN-258).
* Поверхность `PATCH …/category` для идентификатора фонда не расширяется.
* Отдельный HTTP-путь только для идентификатора фонда не вводится.
* Фонд является самостоятельным свойством операции, а не частью категории.

### Независимость чтения от записи (D-14)

* Идентификатор фонда в HTTP-представлении операции добавляется отдельно от пути записи (FIN-259).
* Чтение через `query_transactions` не зависит от FIN-258.
* Чтение отражает фактическое состояние операции, в том числе после миграции или назначения вне MCP.
