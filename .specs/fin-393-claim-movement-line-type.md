# Чтение и запись типа «движение по требованию» через MCP

**Статус:** Утверждено (2026-09-11, rev.4).

## Назначение

- HTTP API операций принимает и возвращает тип позиции `R` без категории, а инструменты MCP замены позиций, канонического частичного обновления и выборки не обещают этот тип и не передают фильтр списка по нему.
- Через MCP нужно создать, заменить, частично обновить, прочитать и отфильтровать позицию с типом `R` без категории, не вызывая HTTP в обход универсальных инструментов.

## Входит в объём

- Запись типа «движение по требованию» без категории через замену позиций и каноническое частичное обновление, включая пакет.
- Чтение этого типа в ответе замены, в чтении позиций, в чтении операции и в строке списка операций.
- Фильтр списка операций по типу первой позиции со значением `R`.
- Отказ записи типа `R` с непустой категорией или происхождением `derived` как ошибка инструмента без частичной записи этого вызова.
- Сохранение прежнего поведения типов `P`, `C`, `S` и `I` на универсальных путях записи без участия `R`.

## Вне объёма

- Не входит пользовательский интерфейс типа «движение по требованию».
- Не входит назначение типа `R` классификатором.
- Не входит формирование операций из первичных данных и запись типа при импорте.
- Не входит связывание позиции с денежным требованием (FIN-353, FIN-354).
- Не входит запись типа `R` через `put_transaction_category`.
- Не входит расширение `put_transaction_category` новыми возможностями классификации, включая полную поверхность фасада (FIN-215).
- Не входят пометка, вывод и удаление `put_transaction_category` (FIN-263).
- Не входит новый инструмент MCP и не входит инструмент вариантов фильтра `filter-choices`.
- Не входит фильтр удаления операций по типу.
- Не входит интерфейс командной строки скрипта выборки.
- Не входит изменение HTTP-контракта, доменных инвариантов и слоя сохранения типа `R` (FIN-384).
- Не входит переименование путей `transactions` в `operations`.

## Текущее поведение

| Область | Текущее поведение | Проблема |
| ------- | ----------------- | -------- |
| HTTP | FIN-384 допускает `R` без категории на замене позиций и на частичном обновлении, включая фасад; фильтр списка по `R` относится к первой позиции | Канал MCP этот контракт не экспонирует на универсальных инструментах |
| Фасад `put_transaction_category` | Обработчик требует `transaction_type` и `transaction_category` совместно; ключ `category_source` запрещён | Специализированный путь дублирует `put_transaction`; новые возможности через него не добавляются |
| Замена `put_transaction_lines` | Поля `assignment.type` и `assignment.category` передаются в HTTP без пары тип–категория | Описание схемы не обещает `R`; отказ HTTP не зафиксирован как контракт этого инкремента |
| Канонический `put_transaction` | Omit-keep полей тела; пары тип–категория обработчик не проверяет | Успех `R` без категории и отказ `R` с категорией не входят в MCP-контракт |
| Выборка `query_transactions` | Строка содержит `transaction_type`; аргумента фильтра `transaction_type` нет; FIN-27 D-06 исключает этот фильтр | Нельзя отфильтровать список по `R` без обхода MCP |

## Целевое поведение

#### Набор инструментов (D-01)

- Эта задача не вводит новое имя инструмента MCP.
- MCP-сервер экспонирует тип `R` существующими универсальными инструментами:

| Инструмент MCP | Операция HTTP |
| -------------- | ------------- |
| `put_transaction_lines` | `PUT /api/v1/transactions/{transaction_id}/lines` |
| `get_transaction_lines` | `GET /api/v1/transactions/{transaction_id}/lines` |
| `get_transaction` | `GET /api/v1/transactions/{transaction_id}` |
| `put_transaction` | `PATCH /api/v1/transactions/{transaction_id}` |
| `put_transactions` | последовательные вызовы того же пути, что у `put_transaction` |
| `query_transactions` | `GET /api/v1/transactions` |

- MCP-сервер не регистрирует инструмент для `GET /api/v1/transactions/filter-choices`.
- Инструмент `put_transaction_category` не входит в поверхность записи типа `R` этой задачи. Паритет HTTP-фасада `PATCH /api/v1/transactions/{transaction_id}/category` для типа `R` этой задачей не добавляется; вывод фасада MCP задаёт FIN-263.
- Доменный словарь типа, правило отсутствия категории для `R`, происхождение `manual` / `derived`, полнота контировки, фильтр по первой позиции и коды ошибок записи принадлежат HTTP FIN-384. MCP-сервер эти нормы не дублирует и не ослабляет.
- JSON Schema инструментов D-01 не задаёт `enum` для типа позиции и для фильтра типа.

#### Фасад классификации не развивается (D-02)

- Инструмент `put_transaction_category` рассматривается этой спецификацией как legacy-путь и не развивается.
- MCP-сервер не добавляет через `put_transaction_category` новые возможности классификации, включая тип `R`.
- Изменение типа и категории операции выполняется через `put_transaction`.
- Обработчик, схема и локальная валидация `put_transaction_category` сохраняют контракт FIN-211 без изменений.
- Существующие вызовы `put_transaction_category` с типами `P`, `C`, `S` и `I` сохраняют прежний успех и прежние отказы FIN-211.
- Вызов `put_transaction_category` с типом `R` без непустой категории сохраняет отказ класса «Ошибка локальной валидации обработчика» без вызова HTTP.
- Фактическая маркировка `deprecated`, вывод и удаление `put_transaction_category` выполняются FIN-263. Эта задача не меняет схему, описание и регистрацию этого инструмента.

#### Замена позиций и каноническое частичное обновление (D-03)

- Обработчик `put_transaction_lines` передаёт элемент `lines` в тело HTTP без добавления пары тип–категория и без исключения значения `R` в `assignment.type`.
- Обработчик `put_transaction_lines` не нормализует `assignment.type`, `assignment.category` и `assignment.source` сверх действующего контракта FIN-270.
- Обработчик `put_transaction` сохраняет omit-keep полей тела FIN-260. Вызов с `transaction_type` равным `R` без ключа `transaction_category` формирует тело HTTP только из присутствующих ключей объявленного набора.
- Обработчик `put_transactions` не меняет семантику пакета FIN-265. Элемент пакета с `transaction_type` равным `R` без ключа `transaction_category` обрабатывается тем же построением тела, что у `put_transaction`.
- JSON Schema `put_transaction_lines` сохраняет для `assignment.type` и `assignment.category` типы строки или JSON `null`. JSON Schema `put_transaction` сохраняет для `transaction_type` и `transaction_category` типы строки или JSON `null`.
- Отклонение непустой категории при типе `R` и отклонение происхождения `derived` при типе `R` на этих путях выполняет HTTP FIN-384.
- Допустимые аргументы замены позиций без категории и без `source`:

```json
{
  "transaction_id": "accept-fin393-t1-tx",
  "allow_closed": true,
  "lines": [
    {
      "id": "accept-fin393-t1-line",
      "line_no": 1,
      "amount": "100.00",
      "assignment": {
        "type": "R",
        "fund_id": "personal.elizarov"
      }
    }
  ]
}
```

- Допустимые аргументы канонического частичного обновления без категории:

```json
{
  "transaction_id": "accept-fin393-t2-tx",
  "transaction_type": "R",
  "allow_closed": true
}
```

- Допустимые аргументы пакета из одного элемента без категории:

```json
{
  "allow_closed": true,
  "items": [
    {
      "transaction_id": "accept-fin393-t4-tx",
      "transaction_type": "R"
    }
  ]
}
```

#### Чтение и round-trip (D-04)

- После успешной записи типа `R` без категории последующий вызов `get_transaction_lines` для той же операции при коде HTTP 200 возвращает в массиве `lines` позицию с `assignment.type` равным `R` и `assignment.category` равным JSON `null`.
- После той же записи последующий вызов `get_transaction` при коде HTTP 200 возвращает ту же позицию в массиве `lines` объекта `transaction` с `assignment.type` равным `R`.
- После той же записи, если тип записан на позиции с `line_no` равным 1, успешный ответ `put_transaction_lines` содержит эту позицию с `assignment.type` равным `R` и `assignment.category` равным JSON `null`.
- После успешной записи типа `R` без категории через `put_transaction` или через одноэлементный `put_transactions` объект `transaction` последующего `get_transaction` содержит `transaction_type` равный `R`. Значение категории в этом объекте пусто в сериализации HTTP FIN-384 для плоской строки операции: пустая строка либо JSON `null`, если HTTP вернул JSON `null`.
- Обработчик `put_transaction_lines` принимает повтор того же допустимого тела замены с `assignment.type` равным `R` и без ключа `category`. Поля ответа чтения, которых нет во входной схеме замены, в том числе `budget_amount`, во вход замены не входят.
- Обработчики чтения не пересчитывают тип, категорию и состояние полноты контировки. Состав объекта совпадает с телом HTTP после существующего разворачивания конверта инструмента.
- Конверт успеха `put_transaction_lines` и `get_transaction_lines` сохраняет ключи `ok`, `profile`, `base` и `lines`. Конверт успеха `get_transaction` и `put_transaction` сохраняет ключи `ok`, `profile`, `base` и `transaction`. Конверт успеха `query_transactions` сохраняет ключи `profile`, `base`, `row_count` и `rows` для неагрегированной выборки.

#### Фильтр выборки (D-05)

- Это переопределяет FIN-27 D-06: инструмент `query_transactions` принимает необязательный аргумент `transaction_type`.
- Обработчик `query_transactions` нормализует аргумент `transaction_type` тем же правилом строковых фильтров FIN-27: удаление крайних пробельных символов; пустая строка после этой нормализации означает отсутствие фильтра; регистр не изменяется.
- Если после нормализации фильтр активен, обработчик включает query-параметр `transaction_type` в вызов `GET /api/v1/transactions` со значением после нормализации.
- Если ключ `transaction_type` отсутствует либо после нормализации пуст, обработчик не включает этот query-параметр.
- Публичная JSON Schema `query_transactions` задаёт для `transaction_type` тип строки и отклоняет JSON `null`. При вызове обработчика в обход схемы JSON `null` и значение не-строки обрабатываются правилом строковых фильтров FIN-27: `null` означает отсутствие фильтра; иное значение приводится к строке и затем нормализуется.
- Активный фильтр `transaction_type` считается активным фильтром выборки: вызов только с этим фильтром допустим, если после нормализации значение непусто.
- MCP-сервер не отфильтровывает строки ответа после HTTP. Соответствие фильтру `R` первой позиции принадлежит HTTP FIN-384.
- Неагрегированная строка `query_transactions` по-прежнему содержит ключ `transaction_type`. После успешной записи `R` на первой позиции значение этого ключа у строки операции равно `R`.
- Агрегированная выборка с `group_by` равным `month` не получает ключ `transaction_type` в элементе группы и не меняет семантику агрегации.
- JSON Schema `query_transactions` объявляет `transaction_type` как строку без `enum` и не делает ключ обязательным.

#### Ошибки и порядок (D-06)

- MCP-сервер не вводит собственных кодов ошибок типа `R`.
- Форма ошибки инструмента для ответа API включает код HTTP, `error.code` и исходное тело ответа API либо его эквивалент в действующем формате `format_api_error`. MCP-сервер не переименовывает `error.code`.

| Ситуация | Класс | HTTP вызывается | Исход |
| -------- | ----- | --------------- | ----- |
| Неверный тип JSON или неизвестный ключ там, где схема запрещает неизвестные ключи | Ошибка схемы MCP | нет | отказ схемы до обработчика |
| Пустой `transaction_id`; пустой массив `lines`; отсутствие полей тела `put_transaction` | Ошибка локальной валидации обработчика | нет | `ValueError` |
| Неразрешённые `profile` или `base` | Ошибка сессии | нет | как у действующих инструментов |
| Тип `R` с непустой после нормализации HTTP категорией | Ошибка валидации HTTP | да | ошибка инструмента; `error.code` равен `validation_error`; состояние операции не меняется этим вызовом |
| Тип `R` с происхождением `derived` | Ошибка валидации HTTP | да | ошибка инструмента; `error.code` равен `validation_error`; состояние операции не меняется этим вызовом |
| Операция не найдена | Доменная ошибка HTTP | да | ошибка инструмента; `error.code` равен `transaction_not_found` |
| Закрытый период без `allow_closed` | Доменная ошибка HTTP | да | ошибка инструмента; `error.code` равен `period_closed` |
| Тип позиции заблокирован документом выравнивания | Доменная ошибка HTTP | да | ошибка инструмента; `error.code` равен `clearing_document_item_locked` |
| Ожидаемый успех с телом не-объектом; иной `2xx`; `1xx`; `3xx`; `4xx` или `5xx` без конверта ошибки; `5xx` с конвертом ошибки | Неожиданный код HTTP | да | ошибка инструмента; HTTP-статус в тексте ошибки |
| Сетевой сбой транспорта | Сетевой сбой | вызов начат | исключение транспорта без дополнительной обёртки MCP |

- Порядок останавливающих отказов одного вызова:

1. Ошибка схемы MCP.
2. Ошибка сессии.
3. Ошибка локальной валидации обработчика.
4. Сетевой сбой транспорта.
5. Классификация HTTP-исхода D-08.

- При нескольких нарушениях HTTP, которые FIN-384 упорядочивает на своём слое, MCP-сервер не задаёт иной порядок и не выполняет второй HTTP-вызов, чтобы выбрать другой код.
- Один вызов `put_transaction_lines` или `put_transaction` соответствует одному HTTP-запросу. Одноэлементный вызов `put_transactions` соответствует одному HTTP-запросу по FIN-265. MCP-сервер не записывает часть тела после отказа HTTP.
- Атомарность замены набора позиций и частичного обновления принадлежит HTTP. Эта задача не открывает отдельную транзакцию записи на слое MCP и не отклоняется от платформенного умолчания атомарности HTTP-запроса. После отказа обёртки чтение той же позиции показывает значения, которые были до вызова. Отдельный MCP-тест внутренней границы HTTP не вводится.

#### Обратная совместимость (D-07)

- Вызов `put_transaction_category` сохраняет контракт FIN-211. Эта задача не меняет схему, обработчик и описание этого инструмента.
- Вызов `query_transactions` без ключа `transaction_type` сохраняет прежние фильтры, поля неагрегированной строки и семантику `group_by`.
- Разрыв допускается: если вызывающая сторона ранее передавала незаявленный ключ `transaction_type` в `query_transactions`, обработчик больше не игнорирует этот ключ и передаёт его в HTTP как фильтр.
- Вызов `put_transaction_lines` и `put_transaction` без значения типа `R` сохраняет прежние контракты FIN-270 и FIN-260.
- Вызов `put_transaction` с типами `P`, `C`, `S` или `I` без непустой категории сохраняет отказ HTTP FIN-384 / FIN-202.
- Эта задача не меняет обязательность хотя бы одного активного фильтра выборки, кроме того что активный `transaction_type` сам является таким фильтром.
- Контракт HTTP FIN-384 эта задача не меняет.

#### Конвейер и исходы HTTP (D-08)

- Конвейер записи `put_transaction_lines`, `put_transaction` и `put_transactions` сохраняет порядок: сессия; проверка аргументов MCP; построение тела; HTTP-вызов; разворачивание успеха либо ошибка инструмента. Эта задача не добавляет шаг поиска категории, фонда или требования и не добавляет повтор вызова после доменного отказа.
- Конвейер `query_transactions` сохраняет порядок: сессия; нормализация фильтров; проверка наличия активного фильтра; HTTP-вызов; разворачивание строк. Эта задача добавляет только передачу активного `transaction_type` в query-строку.
- Эта задача не вводит нормализацию типа `R` на слое MCP сверх уже действующей нормализации аргументов каждого инструмента D-01. Неканоническое значение, которое должен отклонить HTTP, MCP-сервер не исправляет.
- Классификация HTTP-исхода каждого вызова адаптера, который эта задача использует, фиксирована:

1. Сетевой сбой транспорта — класс «Сетевой сбой».
2. Ожидаемый успешный код HTTP 200 и тело-объект — успех инструмента.
3. Ожидаемый успешный код HTTP 200 и тело не-объект — класс «Неожиданный код HTTP».
4. Иной `2xx` — класс «Неожиданный код HTTP».
5. `4xx` с конвертом ошибки, включая `422` — класс «Ошибка валидации HTTP» либо «Доменная ошибка HTTP» по `error.code` без смены кода.
6. `4xx` без конверта ошибки — класс «Неожиданный код HTTP».
7. `5xx` с конвертом ошибки — класс «Неожиданный код HTTP»; `error.code` сохраняется в тексте ошибки, если конверт его содержит.
8. `5xx` без конверта — класс «Неожиданный код HTTP».
9. `1xx` и `3xx` — класс «Неожиданный код HTTP».

- Ожидаемый успешный код для каждой операции этой задачи равен 200. Иной `2xx` не считается успехом.
- Конкурентное изменение операции между последовательными вызовами инструментов явно не нормируется сверх FIN-384.

#### Инварианты (D-09)

- После успешной записи `R` без категории чтение через `get_transaction_lines` не возвращает непустую категорию этой позиции и не требует категории для признания вызова успешным.
- После отказа HTTP на вызове с типом `R` и непустой категорией либо с происхождением `derived` сохранённые тип и категория этой позиции равны значениям до вызова.
- MCP-сервер не назначает типу `R` категорию и не подставляет происхождение `derived`.
- MCP-сервер не считает чтение или запись успешными при коде HTTP, отличном от 200.
- Справочник `mcp-gaps.md` после поставки указывает у инструментов D-01 поддержку типа `R` со ссылкой на FIN-393. Метка `mcp-gap` снимается с FIN-393 при переводе задачи в Done и не входит в критерий функциональной приёмки.

## Предположения, предусловия и ограничения

- HTTP FIN-384. На профиле прогона развёрнут HTTP-контракт FIN-384: запись, чтение и фильтр типа `R` уже работают.
- Существующие инструменты. На профиле прогона доступны инструменты D-01 по контрактам FIN-260, FIN-265, FIN-270 и FIN-27 с переопределениями этой спецификации.
- Фасад без изменений. Инструмент `put_transaction_category` доступен по контракту FIN-211 и этой задачей не изменяется.
- Активный профиль. Операции, фильтры и сессия MCP относятся к профилю, выбранному в вызове.
- Открытый период записи. Запись без `allow_closed` выполняется в учётном периоде, который не закрыт, либо передаётся `allow_closed` по действующему контракту инструментов записи.

## Критерий приёмки

#### Продуктовый результат

- Через MCP можно заменить позиции операции типом `R` без категории и прочитать этот тип в ответе замены, в позициях и в операции.
- Через MCP можно записать тип `R` без категории каноническим частичным обновлением, в том числе пакетом из одного элемента.
- Список операций через MCP с фильтром типа `R` возвращает операцию, у которой тип первой позиции равен `R`, и не возвращает операцию, у которой `R` только на позиции с `line_no` больше 1.
- Вызов списка операций только с фильтром типа, без других фильтров, допустим.
- Запись `R` с непустой категорией или с происхождением `derived` на путях замены позиций и канонического частичного обновления даёт ошибку инструмента с кодом ошибки HTTP и не меняет сохранённые тип и категорию этим вызовом.
- Инструмент `put_transaction_category` сохраняет прежний контракт и не принимает тип `R` без категории.
- Каноническое частичное обновление типа `C` без категории сохраняет отказ HTTP и не меняет исходные тип и категорию.

#### Контроль реализации

- Поведение, допускающее автоматизированную функциональную проверку, покрыто функциональными тестами.
- Автотесты проверяют передачу `R` без категории в теле замены позиций, канонического частичного обновления и одноэлементного пакета, неизменность `put_transaction_category`, признание одиночного `transaction_type` активным фильтром, передачу фильтра в query-строку и проброс HTTP `validation_error` без вызова второго запроса записи.
- Справочник доступных инструментов MCP указывает поддержку типа `R` на инструментах D-01.
