  # Мультивалютный факт операций и плана-факта в MCP

  **Статус:** Утверждено (2026-08-25, rev.3).

  ## Назначение

  - Операторы не видят сохранённую валюту операции, валюту бюджета на операции, плановый курс на операции и сумму позиции в валюте бюджета в выборке операций и в плане и факте через MCP.
  - Нужно отдавать сохранённые поля HTTP без подстановки евро и строить факт плана и факта из сохранённых сумм в валюте бюджета.
  - На пути записи нужны явные ошибки курса и валюты без молчаливой подстановки.

  ## Критерий приёмки

  - Чтение операций через MCP возвращает сохранённые валюту операции, валюту бюджета на операции, плановый курс на операции и сумму позиции в валюте бюджета согласно целевому поведению.
  - План и факт через MCP берёт сумму факта из сохранённых сумм позиций в валюте бюджета и не подставляет евро.
  - Ошибки записи с кодами `fx_rate_missing`, `budget_currency_undefined` и `operation_currency_undefined` отображаются в результате `process_month` без молчаливой подстановки.
  - Ошибки HTTP замены позиций передаются существующим механизмом ошибки инструмента.
  - Справочник доступных инструментов MCP обновлён.
  - Поведение покрыто функциональными тестами.

  ## Объём и границы

  ### Входит в объём

  #### Возможности

  - В объём входит расширение выборки операций сохранёнными валютными полями заголовка.
  - В объём входит чтение сохранённых валютных полей заголовка и суммы позиции в валюте бюджета в чтении операции и в чтении позиций.
  - В объём входит возврат тех же полей заголовка в успешном ответе частичного обновления операции.
  - В объём входит построение факта плана и факта из сохранённых сумм в валюте бюджета, включая расшифровку.
  - В объём входит проброс доменных кодов ошибок записи валюты и курса в результат `process_month`.
  - В объём входит передача ошибок HTTP замены позиций существующим механизмом ошибки инструмента.

  #### Артефакты приёмки

  - В объём входят схемы и обработчики существующих инструментов выборки, чтения операции, чтения позиций, плана и факта, частичного обновления операции, замены позиций и обработки месяца.
  - В объём входят модули тонких обёрток этих инструментов.
  - В объём входят функциональные тесты с имитацией HTTP.
  - В объём входит обновление справочника доступных инструментов MCP.

  ### Не входит в объём

  #### Зависимости и соседние возможности

  - Не входят модель, миграция схемы и слой сохранения мультивалютности факта (FIN-170).
  - Не входит программный интерфейс HTTP мультивалютности факта (FIN-335).
  - Не входит отображение валюты операции и сумм факта в валюте бюджета в пользовательском интерфейсе (FIN-337).
  - Не входит параметр перевода плановых сумм к валюте бюджета в плане и факте (FIN-159).
  - Не входит HTTP и MCP валюты банковского счёта (FIN-339, FIN-341).
  - Не входит переименование параметра `convert_to_eur` и полей `*_eur` (FIN-338).
  - Не входит провайдер T-Bank и разбор его первичных данных (FIN-167).

  #### Не планируется

  - Не входит новый инструмент списка, чтения или записи операций.
  - Не входит фильтр выборки операций по валюте.
  - Не входит запись валюты операции, валюты бюджета на операции и планового курса на операции через частичное обновление.
  - Не входит приём суммы позиции в валюте бюджета во входных позициях замены.
  - Не входит отдельная колонка суммы операции в валюте бюджета в строке выборки.
  - Не входит сведение сумм в разных валютах в одну строку агрегата выборки по месяцу.
  - Не входит сведение плановой суммы в валюте статьи с фактом в валюте бюджета в сгруппированном представлении.
  - Не входит значение по умолчанию `EUR` на слое MCP.
  - Не входит расширение белого списка ответа инструмента классификации операции.
  - Не входит конвертация сохранённого факта к EUR при чтении, если валюта бюджета на операции не равна EUR.

  ## Факт реализации (до)

  | Область | Текущее поведение | Проблема |
  | ------- | ----------------- | -------- |
  | Выборка операций | Строка собирается из ограниченного набора полей и не содержит валютных ключей заголовка | Оператор не видит сохранённую валюту и курс |
  | Чтение операции и позиций | Тело HTTP передаётся без отбора валютных ключей | После FIN-335 поля есть в HTTP, но норма MCP их не фиксирует |
  | Частичное обновление операции | Ответ отбирает белый список полей без валютных ключей | Успешный ответ теряет валюту и курс |
  | План и факт | Сгруппированное представление ищется по статье; расшифровка запрашивает валюту `EUR` | Факт может быть не в евро; первая найденная строка статьи может не совпасть с фактом |
  | Импорт месяца | Ответ с кодом HTTP 422 пишется в журнал; отдельно извлекаются только заблокированные периоды | Коды `fx_rate_missing` и соседние не выделены; подсказка журнала говорит про заблокированные периоды |
  | `mcp-gaps.md` | Строки выборки и плана и факта без валюты факта | Label `mcp-gap` на FIN-336 |

  ## Целевое поведение

  ### Паритет поверхности (D-01)

  - Набор инструментов операций и плана и факта не расширяется и не сужается.
  - Эта задача не добавляет инструмент создания операции.
  - Норма полного набора CRUD для нового ресурса к этой задаче не применяется.
  - Эта задача расширяет уже существующие инструменты полями уже существующего HTTP-контракта FIN-335.

  | Инструмент MCP | Операция HTTP | Что меняется |
  | -------------- | ------------- | ------------ |
  | `query_transactions` | `GET /api/v1/transactions` | Сохранённые валютные поля заголовка в каждой неагрегированной строке |
  | `get_transaction` | `GET /api/v1/transactions/{transaction_id}` | Сохранённые валютные поля заголовка и сумма в валюте бюджета на позициях |
  | `get_transaction_lines` | `GET /api/v1/transactions/{transaction_id}/lines` | Сумма в валюте бюджета на позициях |
  | `put_transaction` | `PATCH /api/v1/transactions/{transaction_id}` | Сохранённые валютные поля заголовка в ответе; вход их не принимает |
  | `put_transaction_lines` | `PUT /api/v1/transactions/{transaction_id}/lines` | Сумма в валюте бюджета в ответе; вход её не принимает; ошибки HTTP сохраняют прежнюю форму ошибки инструмента |
  | `query_plan_fact` | `GET /api/v1/budget/plan-actual` и расшифровка | Факт из сохранённых сумм в валюте бюджета; элемент `months` по паре периода и валюты строки HTTP; расшифровка без подстановки евро |
  | `process_month` | `POST /api/v1/import` | Коды ошибок записи валюты и курса в журнале без продолжения конвейера |

  - Доменные правила валюты, курса и суммы в валюте бюджета наследуются из FIN-170 и FIN-335 без дублирования формулы в MCP.

  ### Конвейер (D-02)

  ```
  1. получить сессию API (профиль данных, базовый URL)
  2. проверить аргументы MCP до HTTP, если инструмент это уже делает
  3. выполнить существующий вызов HTTP без новых маршрутов
  4. при ожидаемом коде HTTP успеха отобразить сохранённые валютные поля или факт согласно D-04…D-08
  5. иначе вернуть ошибку инструмента с телом ответа API
  6. сетевые сбои пробросить без дополнительной обёртки
  ```

  - Порядок шагов совпадает с существующими обработчиками этих инструментов.
  - MCP не читает справочник курсов при чтении операции и при чтении плана и факта.
  - MCP не пересчитывает сумму позиции в валюте бюджета.
  - MCP не подставляет `EUR`, если ключ валюты в ответе HTTP отсутствует.

  ### Модуль и регистрация (D-03)

  - Расширение выборки выполняется в существующем `scripts/query-transactions.py` и в обработчике `query_transactions`.
  - Расширение плана и факта выполняется в существующем `scripts/query-plan-fact.py` и в обработчике `query_plan_fact`.
  - Возврат полей заголовка частичного обновления выполняется в существующем `scripts/put_transaction.py`.
  - Журнал ошибок импорта выполняется в существующем `scripts/monthly_close_lib.py`.
  - Чтение операции, чтение позиций и замена позиций остаются в своих модулях и не вводят отбор, который отбрасывает новые ключи.
  - Справочник доступных инструментов обновляется в `mcp-gaps.md`.
  - После закрытия задачи label `mcp-gap` снимается с FIN-336.

  ### Выборка операций (D-04)

  #### Состав неагрегированной строки

  - Неагрегированная строка всегда содержит ключ валюты операции (`currency`).
  - Неагрегированная строка всегда содержит ключ валюты бюджета на операции (`budget_currency`).
  - Неагрегированная строка всегда содержит ключ планового курса на операции (`planned_rate`).

  | Поле | Описание | Норма |
  | ---- | -------- | ----- |
  | `amount` | Сумма операции в валюте операции | Уже есть; семантика не меняется |
  | `currency` | Валюта операции | Сохранённый трёхбуквенный код из HTTP; если ключ в HTTP отсутствует, JSON `null` |
  | `budget_currency` | Валюта бюджета на операции | Сохранённый трёхбуквенный код из HTTP; если ключ в HTTP отсутствует, JSON `null` |
  | `planned_rate` | Плановый курс на операции | Строка курса из HTTP либо JSON `null` |

  - Значение берётся из ответа HTTP без нормализации и без fallback.
  - Пустая строка для этих ключей в ответе MCP не используется, если HTTP отдал JSON `null`.
  - Сумма позиции в валюте бюджета в строку выборки не входит.
  - Фильтры выборки не меняются.

  #### Агрегация по месяцу

  - Агрегация по месяцу сохраняет прежнюю семантику суммы поля `amount`.
  - Агрегация по месяцу не разбивает группы по валюте.
  - Агрегация по месяцу не требует валютных ключей на элементе группы.

  #### Пример неагрегированной строки

  ```json
  {
    "id": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee",
    "date": "15.07.2026",
    "amount": 6606.7,
    "indicator": "D",
    "category": "C0001",
    "transaction_type": "C",
    "expense_owner": null,
    "fund_id": null,
    "provider": "tbank",
    "description": "Moscow corridor",
    "currency": "RUB",
    "budget_currency": "EUR",
    "planned_rate": "90.8776"
  }
  ```

  ### Чтение операции и позиций (D-05)

  - Успешный `get_transaction` возвращает тело HTTP операции без отбрасывания ключей `currency`, `budget_currency`, `planned_rate`.
  - Вложенные позиции в этом ответе содержат ключ суммы позиции в валюте бюджета (`budget_amount`), если он есть в HTTP.
  - Успешный `get_transaction_lines` возвращает позиции HTTP без отбрасывания ключа `budget_amount`.
  - MCP не вычисляет эти поля заново.
  - MCP не вводит отдельный ключ валюты на позиции.

  #### Пример фрагмента операции

  ```json
  {
    "ok": true,
    "profile": "cand",
    "base": "http://127.0.0.1:8000",
    "transaction": {
      "id": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee",
      "amount": "6606.70",
      "currency": "RUB",
      "budget_currency": "EUR",
      "planned_rate": "90.8776",
      "lines": [
        {
          "id": "cccccccc-dddd-eeee-ffff-000000000000",
          "line_no": 1,
          "amount": "6606.70",
          "budget_amount": "72.70"
        }
      ]
    }
  }
  ```

  ### Частичное обновление и замена позиций (D-06)

  #### Вход частичного обновления

  - Схема `put_transaction` не объявляет аргументы `currency`, `budget_currency` и `planned_rate`.
  - Незаявленные аргументы верхнего уровня по-прежнему отклоняются схемой MCP до HTTP.

  #### Вход замены позиций

  - Сумма позиции в валюте бюджета (`budget_amount`) не является разрешённым входным полем MCP.
  - Схема элемента массива `lines` не объявляет ключ `budget_amount`.
  - Схема элемента массива `lines` запрещает дополнительные свойства: `additionalProperties` равен `false`.
  - Наличие ключа `budget_amount` в элементе `lines` отклоняется схемой MCP до обработчика.
  - HTTP при таком входе не вызывается.
  - Если обработчик всё же вызван с ключом `budget_amount` в элементе `lines`, он поднимает `ValueError` без вызова HTTP.
  - Прочие незаявленные ключи элемента `lines` отклоняются той же схемой.
  - Отказ HTTP с кодом 422 и кодом ошибки `validation_error` при `budget_amount` во входном теле остаётся контрактом FIN-335 и этой задачей не воспроизводится через MCP.

  #### Ответ

  - Белый список ответа `put_transaction` дополняется ключами `currency`, `budget_currency` и `planned_rate`.
  - Если ключ отсутствует в HTTP, в успешном ответе MCP значение равно JSON `null`.
  - Успешный `put_transaction_lines` возвращает позиции HTTP, включая `budget_amount`.
  - Замена позиций не читает справочник курсов на слое MCP.

  ### План и факт (D-07)

  #### Источник суммы факта

  - Сумма факта в успешном ответе `query_plan_fact` равна полю фактической суммы строки HTTP и не пересчитывается из номинала операции.
  - MCP продолжает читать сгруппированное представление плана и факта.
  - Эта задача не добавляет параметр `convert_to_eur` в `query_plan_fact`.
  - MCP не подставляет евро в поле валюты строки.

  #### Валюта строки плана и факта

  - Ключ `currency` элемента `months` копирует поле валюты строки HTTP сгруппированного плана и факта.
  - Валюта строки HTTP есть ключ денежного агрегата: идентификатор статьи, начало месяца и эта валюта.
  - Для вклада факта валюта строки HTTP равна сохранённой валюте бюджета на операции, согласно FIN-335.
  - Для плановой суммы валюта строки HTTP равна валюте статьи плана, согласно FIN-335.
  - Если валюта статьи плана отличается от валюты бюджета на операции, HTTP отдаёт две строки, и MCP отдаёт два элемента `months`.
  - MCP не выводит валюту строки самостоятельно и не смешивает её с валютой операции.

  #### Разделение строк по валюте

  - Ключ элемента массива `months` равен паре периода и валюты строки HTTP.
  - Период сам по себе уникальность элемента не обеспечивает.
  - Для каждого запрошенного месяца MCP включает все строки сгруппированного представления с этой статьёй, а не только первую.
  - Каждая строка месяца в ответе MCP содержит ключ валюты строки (`currency`) из HTTP.
  - Если для месяца нет строки статьи, MCP сохраняет одну нулевую строку месяца с валютой JSON `null`.
  - Если у статьи в одном месяце есть несколько валют строки HTTP, MCP возвращает несколько элементов с одинаковым периодом и разной валютой.
  - Суммы с разной валютой строки в один элемент не складываются.
  - Клиент, который считает период уникальным ключом элемента `months`, получает поведенчески несовместимое изменение.

  #### Расшифровка

  - Если запрошена расшифровка, MCP передаёт в параметр валюты расшифровки валюту строки этого элемента, а не константу `EUR`.
  - Для нулевой строки с валютой JSON `null` расшифровка не вызывается.
  - Строка расшифровки в ответе MCP сохраняет поля HTTP, включая сумму операции, сумму в валюте бюджета и валюту операции.
  - Валюта операции в строке расшифровки не равна валюте строки плана и факта, если валюта операции отличается от валюты бюджета на операции.

  #### Пример двух строк одного месяца с разной валютой

  ```json
  {
    "months": [
      {
        "period": "2026-07-01",
        "currency": "EUR",
        "plan": 0.0,
        "fact": 72.7,
        "variance": -72.7
      },
      {
        "period": "2026-07-01",
        "currency": "RUB",
        "plan": 1300.0,
        "fact": 0.0,
        "variance": 1300.0
      }
    ]
  }
  ```

  ### Ошибки записи (D-08)

  | Ситуация | Источник | Поведение |
  | -------- | -------- | --------- |
  | Импорт месяца отвечает кодом HTTP 422 и кодом `fx_rate_missing` | API | `process_month` возвращает `ok` равный `false`; конвейер не продолжается; журнал содержит код ошибки и `error.details` как есть |
  | Импорт месяца отвечает кодом HTTP 422 и кодом `budget_currency_undefined` | API | тот же останов; журнал содержит код ошибки и `error.details` как есть |
  | Импорт месяца отвечает кодом HTTP 422 и кодом `operation_currency_undefined` | API | тот же останов; журнал содержит код ошибки и `error.details` как есть |
  | Элемент `lines` содержит ключ `budget_amount` | MCP до HTTP | отклонение схемой MCP; HTTP не вызывается |
  | Прочие ошибки замены позиций и частичного обновления | API | без изменения формы ошибки инструмента |
  | HTTP status чтения не равен 200 | MCP | `RuntimeError` с телом API |
  | Transport / network | HTTP-клиент | исключение без дополнительной обёртки |

  - MCP не вводит собственных кодов ошибок валюты факта.
  - MCP не подставляет евро и не пропускает импорт после этих кодов.
  - Форма останова `process_month` через `ok` равный `false` и журнал сохраняется.
  - Журнал импорта копирует `error.code` в ключ `error_code` и `error.details` в ключ `error_details`, если они есть в теле HTTP.
  - Копирование `error_details` не зависит от кода ошибки и не разбирает содержимое объекта.
  - Для `fx_rate_missing` объект `error_details` содержит `missing_rates` с полями `period`, `from_currency`, `to_currency`, потому что так отвечает HTTP.
  - Для `budget_currency_undefined` и `operation_currency_undefined` в `error_details` сохраняется тот объект `details`, который вернул HTTP, в том числе пустой объект.
  - Обёртки чтения и замены позиций не разбирают `error.code`, чтобы выбрать иной исход, кроме ошибки инструмента.

  #### Пример фрагмента журнала импорта

  ```json
  {
    "ok": false,
    "log": {
      "imports": [
        {
          "provider": "tbank",
          "status": 422,
          "error_code": "fx_rate_missing",
          "error_details": {
            "missing_rates": [
              {
                "period": "2026-07-01",
                "from_currency": "RUB",
                "to_currency": "EUR"
              }
            ]
          }
        }
      ]
    }
  }
  ```

  ### Обратная совместимость (D-09)

  - Вызов `query_transactions` без опоры на новые ключи сохраняет прежние поля строки и прежние фильтры.
  - Добавление валютных ключей в строку выборки и в успешный ответ частичного обновления является расширением тела.
  - Вызывающая сторона, которая неизвестные ключи ответа игнорирует, продолжает разбирать прежние поля этих инструментов.
  - Для статьи с одной валютой строки HTTP `query_plan_fact` по-прежнему возвращает один элемент на месяц и добавляет ключ `currency`.
  - Несколько элементов на один месяц появляются при нескольких валютах строки HTTP.
  - Клиент, который индексирует `months` только по периоду и ожидает ровно один элемент на месяц, после этой задачи получает несовместимое поведение.
  - Запрет дополнительных свойств элемента `lines` сужает вход `put_transaction_lines` относительно прежней схемы, которая дополнительные ключи допускала.
  - Агрегация выборки по месяцу не меняется.
  - Схемы инструментов не получают новых обязательных аргументов.
  - Контракт HTTP FIN-335 этой задачей не меняется.

  ### Инварианты (D-10)

  - После успешной неагрегированной выборки у каждой строки есть ключи `currency`, `budget_currency` и `planned_rate`.
  - После успешного чтения операции в объекте операции есть те же ключи заголовка.
  - После успешного чтения позиций у каждой позиции есть ключ `budget_amount`, если HTTP его вернул.
  - После успешного плана и факта каждый элемент месяца содержит ключ `currency`.
  - Два элемента `months` с одним периодом и разной валютой строки не сливаются.
  - Сумма факта элемента берётся из сохранённой суммы в валюте бюджета и не вычисляется MCP из номинала операции.
  - MCP не считает чтение успешным при коде HTTP, отличном от ожидаемого успеха инструмента.
