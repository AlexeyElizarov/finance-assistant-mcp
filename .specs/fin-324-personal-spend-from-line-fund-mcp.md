# Факт личного фонда в инструментах MCP по фонду позиции

**Статус:** Утверждено (2026-08-21, rev.3).

## Назначение

- Инструменты переноса остатка личного фонда и сверки денежных средств относят факт трат члена через владельца операции и поставщика счёта.
- Нужен тот же факт трат, что даёт фонд расходной позиции, без второй формулы при успешном чтении HTTP переноса остатка.

## Критерий приёмки

- При успешном чтении HTTP переноса остатка факт трат члена в ответе инструмента переноса совпадает с телом этого ответа.
- При локальном запасном расчёте факт трат члена равен сумме расходных позиций месяца, чей фонд является личным фондом этого члена.
- Сверка денежных средств берёт факт трат месяца проверки из того же конвейера, что и перенос остатка.
- Расходные позиции совместного фонда, фондов накоплений и фонда члена до деления в факт личного фонда не входят.
- Расходная позиция без пригодного личного фонда даёт явное предупреждение и не относится к члену молча.
- Поведение покрыто функциональными тестами.

## Объём и границы

### Входит в объём

#### Возможности

- В объём входит чтение факта трат члена в инструменте переноса остатка личного фонда из тела HTTP при ответе с кодом HTTP 200.
- В объём входит локальный запасной расчёт факта трат по фонду расходной позиции, когда чтение HTTP переноса остатка возвращает код HTTP 404.
- В объём входит чтение факта трат месяца проверки в инструменте сверки денежных средств из того же конвейера.
- В объём входит предупреждение о неотнесённой трате с идентификатором расходной позиции.
- В объём входит отказ от владельца операции, поставщика счёта и блока отнесения по счёту как источника факта трат.
- В объём входит отказ от сопоставления ключа классифицированной операции с сохранённым ключом операции.

#### Артефакты приёмки

- В объём входят правки модулей переноса остатка и сверки денежных средств.
- В объём входят функциональные тесты.
- В объём входит обновление справочника доступных инструментов MCP, если описание факта трат в справочнике расходится с этой спецификацией.

### Не входит в объём

#### Зависимости и соседние возможности

- Не входит доменный расчёт факта личного фонда по фонду позиции (FIN-325).
- Не входит HTTP-контракт факта трат в ответе переноса остатка (FIN-326).
- Не входит пользовательский интерфейс сверки денежных средств (FIN-327).
- Не входит удаление промежуточного файла отнесения контуров (FIN-153).
- Не входит удаление колонки владельца операции (FIN-255).
- Не входит пересчёт июля на prod (FOPS-33).
- Не входит проверка сверки июля по фонду (FOPS-10).
- Не входит расчёт базовой доли, авансов и исходящего финансирования.

#### Не планируется

- Не входят новые инструменты MCP.
- Не входит новый HTTP-путь переноса остатка.
- Не входит изменение параметров вызова существующих инструментов.
- Не входит запись, правка или удаление факта трат через MCP.
- Не входит смена текста заметок атрибуции C24.
- Не входит запрос разбивки позиций в чтении HTTP, если клиент его не передавал.

## Факт реализации (до)

| Область | Текущее поведение | Проблема |
| ------- | ----------------- | -------- |
| Перенос остатка, ответ HTTP 200 | Нормализация копирует факт трат из тела HTTP | После FIN-326 тело уже по фонду позиции; этот путь не должен получить вторую формулу |
| Перенос остатка, ветка при коде HTTP 404 | Суммируются классифицированные расходы личных статей, затем член ищется через владельца операции, текстовые правила описания и поставщика счёта | После перехода на фонд владелец пуст, ключ классификации часто не совпадает с сохранённым, факт трат становится нулевым |
| Сверка денежных средств | Факт трат месяца проверки всегда считает ту же старую формулу | Недельный остаток личного фонда неверен тем же способом |
| Предупреждение о неотнесённой трате | В тексте указан ключ классифицированной операции | После перехода на позицию идентификатор должен быть идентификатором расходной позиции |

## Целевое поведение

### Поверхность инструментов (D-01)

- Новые инструменты MCP не вводятся.
- Единственная поверхность этой задачи состоит в расширении существующих инструментов `personal_fund_carryover` и `money_check_report`.
- Имена инструментов, набор параметров вызова и прочие поля ответов, кроме семантики факта трат и идентификатора в предупреждении о неотнесённой трате, не меняются.
- Эта задача не оборачивает новую HTTP-сущность справочника.
- Полный набор операций создания, изменения и удаления для этой поверхности не требуется.

### Конвейер факта трат (D-02)

#### Порядок

- Порядок шагов получения факта трат за учётный месяц обязателен.
- Этот порядок общий для инструментов `personal_fund_carryover` и `money_check_report`.

1. Вызвать чтение HTTP переноса остатка личного фонда для этого месяца.
2. Если ответ имеет код HTTP 200, взять факт трат каждого члена из тела ответа и не выполнять локальный запасной расчёт.
3. Если ответ имеет код HTTP 404, выполнить локальный запасной расчёт по фонду расходной позиции.
4. Если код HTTP не равен 200 и не равен 404, остановить конвейер ошибкой инструмента по D-09.

#### Месяц и флаги чтения

- Для инструмента переноса остатка месяц факта равен закрываемому месяцу (`closed_period`).
- Флаг допуска незакрытого периода в этом чтении равен одноимённому аргументу вызова инструмента.
- Для инструмента сверки денежных средств месяц факта равен месяцу проверки (`check_period`).
- Флаг допуска незакрытого периода в чтении месяца проверки равен истине.
- Локальный запасной расчёт не читает классифицированные операции.
- Локальный запасной расчёт не сопоставляет ключ классифицированной операции с сохранённым ключом операции.

### Успешное тело HTTP (D-03)

- При ответе с кодом HTTP 200 значение факта трат члена (`actual_spend`) в ответе инструмента переноса остатка равно значению того же ключа в теле HTTP для этого члена.
- Инструмент не пересчитывает факт трат по владельцу операции, поставщику счёта или статьям промежуточного файла отнесения контуров.
- Инструмент не выполняет локальный запасной расчёт.
- Предупреждения о неотнесённой трате из тела HTTP входят в корневой список предупреждений инструмента без замены идентификатора.
- Если в теле HTTP на строке члена есть разбивка позиций (`spend_lines`), инструмент переноса остатка пробрасывает её без изменения состава полей.
- Если в теле HTTP разбивки нет, инструмент её не добавляет из локального запасного расчёта.

### Локальный запасной расчёт по фонду позиции (D-04)

#### Применение

- Локальный запасной расчёт выполняется только после ответа HTTP с кодом 404.

#### Формула факта

- Факт трат члена за месяц (`actual_spend`) равен сумме сумм расходных позиций этого месяца, чей фонд является личным фондом этого члена.
- В сумму входят только позиции типа расход (`C`).
- Личным фондом члена считается фонд, у которого правило распределения свободного остатка (`allocation_rule`) равно `equal_share` и идентификатор члена (`member_id`) равен этому члену.
- Совместный фонд, фонд накоплений и фонд члена до деления (`before_split`) в эту сумму не входят.
- Нормы единицы расчёта, состава предупреждений и источника данных, не повторённые здесь, наследуются из FIN-325.
- Локальный запасной расчёт не вводит вторую формулу факта относительно FIN-325.

#### Источник и запреты

- Локальный запасной расчёт читает расходные позиции месяца и каталог фондов через существующие чтения HTTP подключённого профиля.
- Локальный запасной расчёт не читает блок отнесения по поставщику счёта из промежуточного файла отнесения контуров.
- Локальный запасной расчёт не использует владельца операции, поставщика счёта и текстовые правила описания.
- Промежуточный файл отнесения контуров остаётся источником состава членов и отображаемых имён.
- Денежные значения в ответе MCP остаются JSON number с точностью до 0,01.

> Примеры:
>
> - Ответ HTTP с кодом 404. Расходная позиция 40 €, тип `C`, личный фонд Николая, владелец операции пуст. В факт Николая входит 40 €.
> - Ответ HTTP с кодом 404. Расходная позиция 15 €, тип `C`, совместный фонд. В факты личных фондов не входит. Предупреждения `unattributed_spend` нет.
> - Ответ HTTP с кодом 404. Расходная позиция 20 €, тип `C`, фонд office week Алексея с правилом `before_split`. В факт личного фонда Алексея не входит. Предупреждения `unattributed_spend` нет.
> - Ответ HTTP с кодом 200 и факт Алексея 55. Локальный запасной расчёт не выполняется. В ответе инструмента факт Алексея равен 55.

### Предупреждения локального запасного расчёта (D-05)

- Текст предупреждения об отсутствии пригодного личного фонда имеет вид `unattributed_spend:{line_id}`.
- Идентификатор в этом тексте равен сохранённому идентификатору расходной позиции.
- Идентификатор в этом тексте не равен ключу классифицированной операции.
- Расходная позиция, чей фонд является личным фондом члена из множества расчёта, это предупреждение не порождает.
- Расходная позиция известного неличного фонда это предупреждение не порождает.
- Локальный запасной расчёт не добавляет предупреждение `missing_account_attribution`.
- Неотнесённая трата остаётся предупреждением инструмента и не становится ошибкой инструмента.

### Сверка денежных средств (D-06)

#### Факт месяца проверки

- Факт трат месяца проверки (`actual_spend_mtd`) берётся из конвейера D-02 для месяца проверки.
- Сверка не вызывает отдельную формулу факта трат сверх конвейера D-02.
- Блок переноса остатка прошлого месяца по-прежнему читается через журнал или сухой прогон инструмента переноса остатка.
- Сухой прогон инструмента переноса остатка подчиняется D-02 и D-03 для закрываемого месяца.
- Заметки атрибуции C24 не изменяют факт трат месяца проверки.
- Список ссылок неотнесённых трат в блоке C24 собирает идентификаторы из предупреждений `unattributed_spend` после двоеточия.

#### Ошибка чтения HTTP месяца проверки

- Если чтение HTTP месяца проверки вернуло код, отличный от 200 и от 404, инструмент сверки завершается ошибкой.
- Эта ошибка совпадает с ошибкой, которую вернул бы `personal_fund_carryover` при том же коде HTTP, том же теле ошибки и том же месяце факта.
- Инструмент сверки не возвращает успешный отчёт.
- Инструмент сверки не подставляет нулевой факт трат месяца проверки.
- Инструмент сверки не продолжает сбор остальных блоков отчёта без факта трат месяца проверки.
- Инструмент сверки не вводит отдельный код ошибки для этого исхода.

### Разбивка позиций локального запасного расчёта (D-07)

- При локальном запасном расчёте поле разбивки (`spend_lines`) присутствует на строке члена только если у этого члена есть хотя бы одна позиция факта.
- Если у члена нет позиций факта, поле разбивки на этой строке отсутствует.
- Каждый элемент разбивки содержит все поля таблицы ниже.
- Другие поля в элемент разбивки не входят.

| Поле | Описание | Идентифицирующее | Норма |
| ---- | -------- | ---------------- | ----- |
| `line_id` | Идентификатор позиции | да | Сохранённый идентификатор расходной позиции |
| `amount` | Сумма позиции | нет | JSON number, денежное значение с точностью до 0,01 |
| `fund_id` | Идентификатор фонда | нет | Фонд этой расходной позиции |
| `category` | Категория позиции | нет | JSON `null`, если сохранённая категория пуста или состоит из пробелов; иначе непустая строка без крайних пробелов |

### Обратная совместимость (D-08)

- Имена инструментов и параметры вызова сохраняются.
- Имена существующих полей строки члена и корня ответа сохраняются.
- Типы денежных полей строки члена остаются JSON number.
- Семантика факта трат меняется: источником становится фонд расходной позиции либо тело HTTP переноса остатка.
- Семантика предупреждения `unattributed_spend` при локальном запасном расчёте меняется: идентификатор после двоеточия равен идентификатору расходной позиции.
- Клиенты, которые читают только имена полей факта, остатка и финансирования, продолжают получать те же ключи.
- Ветка ответа HTTP с кодом 404 сохраняется до удаления промежуточного файла отнесения (FIN-153).
- Алгоритм факта трат на этой ветке заменяется локальным запасным расчётом по фонду позиции и не сохраняет отнесение через владельца операции, поставщика счёта или статьи промежуточного файла.
- Тесты, которые фиксируют отнесение через владельца операции, поставщика счёта или совпадение ключа классификации с сохранённым ключом операции, подлежат замене тестами этой спецификации.

### Ошибки (D-09)

- Ошибки существующих параметров и статусов периода не меняются.
- Пустой факт трат не является ошибкой инструмента.

| Ситуация | Исход | Код | Сообщение |
| -------- | ----- | --- | --------- |
| Чтение HTTP переноса остатка в `personal_fund_carryover` вернуло код, отличный от 200 и 404 | ошибка инструмента переноса остатка | как в действующем контракте FIN-105 | как в действующем контракте FIN-105 |
| Чтение HTTP месяца проверки в `money_check_report` вернуло код, отличный от 200 и 404 | ошибка инструмента сверки | тот же код, что дал бы `personal_fund_carryover` при том же ответе HTTP | тот же текст, что дал бы `personal_fund_carryover` при том же ответе HTTP |
| Период переноса остатка не окончательно закрыт и флаг допуска не задан | ошибка инструмента переноса остатка | как в действующем контракте FIN-105 | как в действующем контракте FIN-105 |
| У расходной позиции нет пригодного личного фонда | успех инструмента | `unattributed_spend` | предупреждение; сумма не в факте |

## Функциональное тестирование

Норма оформления: `standards/specs/testing/functional-testing.md`.

### Предусловия

- Профиль данных `cand`, постоянная `finance.db` приложения.
- Прогон выполняется через MCP `finance-assistant` после `finance_api_connect` с `data_profile` равным `cand`.
- Сценарии проброса тела HTTP (T2) выполняются при ответе чтения переноса остатка с кодом HTTP 200.
- Сценарии локального запасного расчёта (T1, T3, T4, T5, T6, T7, T8) выполняются при ответе чтения переноса остатка с кодом HTTP 404.
- Живой профиль `cand` после FIN-326 отвечает на чтение переноса остатка кодом HTTP 200 и не закрывает сценарии T1, T3, T4, T5, T6, T7, T8 без имитации кода 404.
- Сценарий ошибки сверки (T9) выполняется при коде HTTP, отличном от 200 и от 404.
- В каталоге фондов есть личные фонды членов с правилом `equal_share` и общий фонд домохозяйства.
- Автотесты на временной SQLite не заменяют приёмку на `cand` для сценариев с кодом HTTP 200, которые на `cand` воспроизводимы.
- Подготовка расходных позиций личного фонда выполняется только для сценариев, которым эти позиции нужны.
- Подготовленные операции месяца приёмки удаляются после прогона.
- Профиль `prod` в приёмке не используется.
