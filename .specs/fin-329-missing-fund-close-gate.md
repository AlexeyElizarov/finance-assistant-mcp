# Проверка отсутствия фонда в инструментах месяца

**Статус:** Утверждено (2026-08-22, rev.3).

## Назначение

- Проверка месяца должна показывать оператору наличие позиций без обязательного фонда.
- Окончательное закрытие месяца через оркестратор не должно выполняться, пока такие позиции есть.

## Критерий приёмки

- Ответ проверки месяца содержит элемент отсутствия фонда из ответа готовности HTTP и предупреждение, когда эта проверка не проходит.
- Окончательное закрытие месяца через оркестратор отклоняется до вызова закрытия по HTTP, пока эта проверка не проходит.
- Окончательное закрытие отклоняется, если у обязательного элемента нет корректного числа позиций.
- Предварительное закрытие месяца эта проверка в оркестраторе не отклоняет.
- Признак успеха проверки месяца не становится ложным только из-за этой проверки.
- Новый инструмент списка позиций без фонда не вводится.
- Поведение покрыто функциональными тестами.

## Объём и границы

### Входит в объём

#### Возможности

- В объём входит проброс элемента отсутствия фонда из ответа готовности HTTP в ответ проверки месяца.
- В объём входит предупреждение проверки месяца, когда эта проверка не проходит.
- В объём входит отказ окончательного закрытия в оркестраторе месяца, когда эта проверка не проходит.
- В объём входит отсутствие отказа предварительного закрытия этой проверкой в оркестраторе.
- В объём входит сохранение действующей формулы признака успеха проверки месяца.

#### Артефакты приёмки

- В объём входят правки обработчиков проверки месяца и оркестратора месяца.
- В объём входят функциональные тесты.
- В объём входит обновление справочника доступных инструментов, если описание ворот закрытия расходится с этой спецификацией.

### Не входит в объём

#### Зависимости и соседние возможности

- Не входит доменная полнота контировки по фонду и состав позиций в объёме проверки (FIN-242).
- Не входит HTTP-контракт готовности и закрытия периода (FIN-328).
- Не входит показ проверки отсутствия фонда на экране закрытия периода (FIN-330).
- Не входит назначение фонда на позицию в пользовательском интерфейсе (FIN-243).
- Не входит правка регламента закрытия месяца и слота в рабочем чеклисте (FOPS-35).
- Не входит назначение фонда на оставшиеся позиции июля (FOPS-34).

#### Не планируется

- Не входит новый инструмент списка позиций без фонда.
- Не входит повторный отбор позиций без фонда вне ответа готовности HTTP.
- Не входит смена параметров вызова существующих инструментов.
- Не входит смена полей проверок расходов C9999, неклассифицированных позиций и категории «Прочее» без пояснения.
- Не входит смена корневого признака готовности HTTP и признака успеха проверки месяца на готовность к окончательному закрытию.
- Не входит компактная строка отчёта по статусам периодов с отдельным счётчиком отсутствия фонда.

## Факт реализации (до)

| Область | Текущее поведение | Проблема |
| ------- | ----------------- | -------- |
| Проверка месяца | Ответ содержит вложенную готовность HTTP целиком | Элемент `missing_fund` не попадает в список предупреждений |
| Признак успеха проверки | Ложен только при блокирующих проверках, хвосте Mastercard и неполной сверке остатков | Исход `warn` у отсутствия фонда признак успеха не меняет и оператору не виден |
| Окончательное закрытие | Пред-ворота смотрят неклассифицированные позиции и категорию «Прочее» без пояснения | Отсутствие фонда пред-ворота не останавливают |
| Корневой признак готовности | Истина не гарантирует успешное окончательное закрытие | Оркестратор вызывает закрытие по HTTP и узнаёт отказ только из ответа с кодом HTTP 422 |

## Целевое поведение

### Поверхность инструментов (D-01)

- Новые инструменты не вводятся.
- Единственная поверхность этой задачи состоит в расширении существующих инструментов `verify_month` и `process_month`.
- Имена инструментов и набор параметров вызова не меняются.
- Эта задача расширяет уже существующие инструменты и не оборачивает новую HTTP-сущность справочника.
- Полный набор операций создания, изменения и удаления для этой поверхности не требуется.
- Идентификаторы позиций без фонда оператор читает из подробностей элемента готовности.
- Отдельный инструмент списка этих идентификаторов не вводится.

### Источник проверки (D-02)

- Инструменты не вычисляют состав позиций без фонда.
- Источник элемента и счётчиков равен элементу с идентификатором `missing_fund` в списке проверок ответа готовности HTTP.
- Правило отбора позиций, граница `202607` и признак пустого фонда задаются спецификацией FIN-242.
- Контракт полей элемента задаётся спецификацией FIN-328.
- Инструменты не читают классифицированные операции, каталог фондов и перенос остатка, чтобы собрать эту проверку.
- Инструменты не урезают список идентификаторов позиций из подробностей элемента.

### Элемент в ответе проверки месяца (D-03)

- Вложенный объект готовности в ответе `verify_month` содержит элемент с идентификатором `missing_fund` без изменения полей.
- Тот же элемент входит во вложенную проверку шага `verify` в журнале `process_month`.
- Элемент присутствует и тогда, когда доменное число позиций равно нулю.
- Элемент присутствует и для периода раньше `202607`.
- Форма элемента совпадает с формой HTTP: идентификатор, исход, признак блокировки, текст и подробности с числом и идентификаторами позиций.

#### Число позиций

- Единственный признак для предупреждения и для ворот закрытия равен числу позиций в подробностях элемента (`details.count`).
- Корректное число позиций является целым числом не меньше нуля.
- Отсутствие ключа, значение `null`, строка, дробное число, отрицательное целое и логическое значение корректным числом не являются.
- Логическое значение не считается целым числом позиций, даже если среда исполнения относит его к целому типу.
- Исход элемента (`status`) не решает, добавлять ли предупреждение и останавливать ли закрытие.
- Исход элемента показывается как в ответе готовности HTTP и не пересчитывается.

#### Предупреждение

- Если число позиций корректно и больше нуля, список предупреждений проверки месяца получает одну строку об отсутствии фонда.
- Текст этой строки равен тексту элемента готовности HTTP: `Нет фонда на позициях: {n}`.
- Значение `{n}` равно этому числу позиций.
- Если число позиций корректно и равно нулю, эту строку в список предупреждений не добавляют.
- Если элемента с идентификатором `missing_fund` нет, строку об отсутствии фонда не добавляют.
- Если элемент есть, а число позиций некорректно, строку об отсутствии фонда не добавляют.
- Эта строка не заменяет предупреждения о расходах C9999, неклассифицированных позициях и категории «Прочее» без пояснения.

#### Пример предупреждения

```json
{
  "ok": true,
  "warnings": [
    "Нет фонда на позициях: 2"
  ],
  "readiness": {
    "ready": true,
    "checks": [
      {
        "id": "missing_fund",
        "status": "warn",
        "blocking": false,
        "message": "Нет фонда на позициях: 2",
        "details": {
          "count": 2,
          "line_ids": [
            "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee",
            "ffffffff-1111-2222-3333-444444444444"
          ]
        }
      }
    ]
  }
}
```

### Признак успеха проверки месяца (D-04)

- Признак успеха проверки месяца (`ok`) остаётся истинным, если список проблем (`issues`) пуст.
- Проверка отсутствия фонда не добавляет элемент в список проблем.
- Исход `warn` у этой проверки не делает признак успеха ложным.
- Корневой признак готовности HTTP (`ready`) эта задача не пересчитывает.
- Истинный признак успеха проверки месяца не означает готовность к окончательному закрытию.
- Истинный корневой признак готовности HTTP не означает, что оркестратор выполнит окончательное закрытие.

### Ворота окончательного закрытия (D-05)

- Пред-ворота срабатывают только при `close` равном `true` и фазе закрытия `final`.
- Оркестратор читает элемент `missing_fund` из вложенной готовности шага проверки.
- Решение ворот строится по числу позиций, а не по исходу элемента.
- Если элемента нет, оркестратор отклоняет закрытие и не вызывает закрытие по HTTP.
- Если элемент есть, а число позиций некорректно, оркестратор отклоняет закрытие и не вызывает закрытие по HTTP.
- Такой элемент считается некорректной обязательной проверкой.
- Если число позиций корректно и больше нуля, оркестратор отклоняет закрытие и не вызывает закрытие по HTTP.
- Если число позиций корректно и равно нулю, эта проверка причину отказа пред-ворот не добавляет.
- Отказ этой проверки не требует ложного корневого признака готовности HTTP.
- Отказ этой проверки не требует ложного признака успеха проверки месяца.

#### Порядок пред-ворот

- Порядок проверок пред-ворот обязателен и fail-fast.

1. Если в готовности нет элемента `unclassified_pending`, элемента `other_without_note` или элемента `missing_fund`, остановить закрытие ошибкой отсутствия обязательных проверок.
2. Если элемент `missing_fund` есть, а число позиций некорректно, остановить закрытие ошибкой некорректной обязательной проверки.
3. Если число неклассифицированных позиций больше нуля, остановить закрытие существующей ошибкой неклассифицированных позиций.
4. Если число позиций категории «Прочее» без пояснения больше нуля, остановить закрытие существующей ошибкой отсутствия пояснения.
5. Если число позиций без фонда корректно и больше нуля, остановить закрытие ошибкой отсутствия фонда.
6. Если пред-ворота пройдены и корневой признак готовности истинен, вызвать закрытие по HTTP.

#### Пример отказа оркестратора

```json
{
  "ok": false,
  "error": "missing fund on lines > 0 — assign fund before final close"
}
```

### Предварительное закрытие и конвейер без закрытия (D-06)

- При фазе закрытия `preliminary` проверка отсутствия фонда не добавляет ошибку пред-ворот.
- При фазе закрытия `preliminary` отсутствие элемента `missing_fund` и некорректное число позиций ошибку пред-ворот не добавляют.
- Если прочие пред-ворота предварительного закрытия пройдены и корневой признак готовности истинен, оркестратор вызывает закрытие по HTTP.
- При `close` равном `false` оркестратор закрытие по HTTP не вызывает.
- При `close` равном `false` корневой признак успеха ответа оркестратора равен признаку успеха вложенной проверки месяца.
- Предупреждение об отсутствии фонда само по себе не делает этот признак ложным.

### Обратная совместимость (D-07)

- Вызов `verify_month` без новых параметров сохраняет набор корневых полей ответа.
- Вызов `process_month` без закрытия сохраняет набор корневых полей ответа.
- Поля и тексты предупреждений расходов C9999, неклассифицированных позиций и категории «Прочее» без пояснения не меняются.
- Новая проверка не заменяет и не объединяет эти три проверки.
- Существующие параметры `close`, `close_phase` и `c9999_acknowledged` не получают новых значений перечисления.

### Ошибки (D-08)

| Ситуация | Исход инструмента | Сообщение |
| -------- | ----------------- | --------- |
| Окончательное закрытие при корректном числе позиций без фонда больше нуля | `ok` равен `false`; закрытие по HTTP не вызывается | `missing fund on lines > 0 — assign fund before final close` |
| Окончательное закрытие при отсутствии элемента `missing_fund` в готовности | `ok` равен `false`; закрытие по HTTP не вызывается | Текст называет отсутствующие обязательные проверки и включает `missing_fund` |
| Окончательное закрытие при элементе `missing_fund` без корректного числа позиций | `ok` равен `false`; закрытие по HTTP не вызывается | Текст называет проверку `missing_fund` как некорректную обязательную |
| Окончательное закрытие при корректном числе равном нулю и прочих пройденных воротах | Закрытие по HTTP вызывается | Успех или отказ задаёт существующий ответ закрытия |
| Предварительное закрытие при корректном числе больше нуля и прочих пройденных воротах | Закрытие по HTTP вызывается | Эта проверка ошибку пред-ворот не добавляет |
| Окончательное закрытие периода раньше `202607` при пустом фонде на позиции и прочих пройденных воротах | Закрытие по HTTP вызывается | Элемент готовности имеет исход `pass` и корректное число `0` |
| Проверка месяца при корректном числе больше нуля и пустом списке проблем | `ok` равен `true` | Предупреждение по D-03; закрытия нет |
