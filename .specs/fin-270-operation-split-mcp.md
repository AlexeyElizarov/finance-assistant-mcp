# Разделение операции по позициям через MCP

**Статус:** Утверждено (2026-08-08, rev.2).

## Назначение

* Разделение одной операции на несколько позиций с разной контировкой недоступно через MCP.
* Операционные процедуры вынуждены обходить ограничение прямым вызовом HTTP API.

## Критерий приёмки

* Через MCP можно полностью заменить набор позиций одной операции согласно целевому поведению.
* Через MCP можно прочитать позиции той же операции и операцию с позициями согласно целевому поведению.
* Сценарий разделения суммы заголовка на две и более позиций с разной контировкой воспроизводится через MCP без прямого HTTP.
* Доменные ошибки HTTP API разделения пробрасываются в ошибку инструмента без потери кода ошибки.
* Поведение покрыто функциональным тестированием.

## Объём и границы

### Входит в объём

#### Возможности

* В объём входит инструмент MCP полной замены набора позиций одной операции.
* В объём входит инструмент MCP чтения списка позиций одной операции.
* В объём входит инструмент MCP чтения операции по идентификатору вместе с позициями.
* В объём входит обход защиты закрытого учётного периода на пути замены тем же параметром, что у существующих инструментов записи операции.

#### Артефакты приёмки

* В объём входят обработчики и схемы инструментов в MCP-сервере.
* В объём входит модуль тонких обёрток над каноническими HTTP-путями FIN-272.
* В объём входят функциональные тесты.
* В объём входит обновление справочника доступных инструментов MCP.

### Не входит в объём

#### Зависимости и соседние возможности

* Не входит модель заголовка и позиций (FIN-268).
* Не входит проектирование HTTP API разделения (FIN-272).
* Не входит пользовательский интерфейс разделения (FIN-274).
* Не входит применение разделения июля на prod (FOPS-24).
* Не входит модель клиринга компенсирующих пополнений и MCP для неё (FIN-269, FIN-271).
* Не входит отдельный путь сбережений 600 € (FIN-267).
* Не входит формирование нескольких заголовков на этапе импорта (FIN-250).

#### Не планируется

* Не входит дублирование доменных инвариантов суммы, номеров позиций и фонда в MCP.
* Не входит частичное обновление отдельных полей одной позиции без полной замены набора.
* Не входит поле числа позиций (`line_count`) в `query_transactions` или в HTTP-списке операций.
* Не входит признак «операция разделена» (`is_split`) как отдельное поле.
* Не входит массив всех позиций в каждой строке `query_transactions`.
* Не входит изменение семантики `put_transaction` (FIN-260) для второй и последующих позиций.
* Не входит один инструмент MCP с перечислением действия вместо отдельных инструментов.
* Не входит переименование путей `transactions` в `operations`.

## Обратная совместимость

* Три новых инструмента добавляются без изменения семантики существующих инструментов MCP.
* Инструмент `put_transaction` сохраняет прежнее поведение и по-прежнему действует на контировку первой позиции.
* Контракт `query_transactions` этой задачей не меняется.
* Контракт HTTP API FIN-272 этой задачей не меняется.

## Целевое поведение

### Набор инструментов (D-01)

#### Таблица инструментов

| Инструмент MCP | Операция HTTP | Смысл |
| -------------- | ------------- | ----- |
| `put_transaction_lines` | `PUT /api/v1/transactions/{transaction_id}/lines` | Полная замена набора позиций |
| `get_transaction_lines` | `GET /api/v1/transactions/{transaction_id}/lines` | Чтение списка позиций |
| `get_transaction` | `GET /api/v1/transactions/{transaction_id}` | Чтение операции с позициями |

#### Правила

* Инструменты являются тонкой обёрткой над каноническими путями FIN-272.
* Отдельный `get_transaction_lines` сохраняется наряду с `get_transaction`: симметрия с REST FIN-272, узкое чтение позиций без чтения полной модели операции.
* Разделение есть успешная замена позиций со списком длиной больше одного при сохранении суммы заголовка.
* Отдельная сущность или инструмент с именем «split» не вводится.
* Доменные инварианты не дублируются в MCP.

### Конвейер замены (D-02)

```
1. получить сессию API (профиль данных, базовый URL)
2. проверить аргументы MCP до HTTP
3. сформировать тело запроса с ключом lines из аргументов
4. сформировать путь и параметр обхода закрытого периода
5. выполнить вызов метода PUT
6. при успехе обернуть полезную нагрузку в конверт ok / profile / base / lines
7. иначе вернуть ошибку инструмента с телом ответа API
8. сетевые сбои пробросить без дополнительной обёртки
```

* Порядок шагов фиксирован.
* Один вызов MCP соответствует одному вызову канонического `PUT`.

### Конвейер чтения (D-03)

```
1. получить сессию API (профиль данных, базовый URL)
2. проверить аргументы MCP до HTTP
3. сформировать путь чтения
4. выполнить вызов метода GET
5. при успехе обернуть полезную нагрузку в конверт ok / profile / base и поле результата
6. иначе вернуть ошибку инструмента с телом ответа API
7. сетевые сбои пробросить без дополнительной обёртки
```

* Для `get_transaction_lines` поле результата называется `lines`.
* Для `get_transaction` поле результата называется `transaction`.
* Один вызов MCP соответствует одному вызову канонического `GET`.

### Модуль и регистрация (D-04)

* Логика обёрток размещается в `scripts/put_transaction_lines.py`, `scripts/get_transaction_lines.py` и `scripts/get_transaction.py`.
* Допускается общий вспомогательный модуль для сборки тела позиций и проброса ошибок, если это не меняет публичные контракты инструментов.
* Обработчики и схемы инструментов регистрируются в `server.py`.

### Валидация до HTTP (D-05)

* Тип аргумента проверяет схема MCP.
* Обработчик не дублирует проверку типов.
* Идентификатор операции (`transaction_id`) после `strip` непуст.
* Для `put_transaction_lines` аргумент `lines` после разбора есть непустой массив.
* Нарушение правил до HTTP даёт `ValueError` без вызова API.
* Остальные инварианты состава позиций, суммы, фонда и закрытого периода проверяет только backend.

### Параметр закрытого периода (D-06)

* Параметр обхода защиты закрытого учётного периода (`allow_closed`) необязателен у `put_transaction_lines`.
* Значение по умолчанию равно `false`.
* Семантика совпадает с FIN-272 и с инструментом `put_transaction`.
* Инструменты чтения параметр обхода не принимают.

### Вход замены (D-07)

#### Параметры вызова

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; по умолчанию из сессии или `prod` |
| `base` | string | нет | Базовый URL API; по умолчанию из сессии |
| `transaction_id` | string | да | Идентификатор операции в пути |
| `allow_closed` | bool | нет | Обход защиты закрытого учётного периода; по умолчанию `false` |
| `lines` | array | да | Полный набор позиций в семантике FIN-272 |

#### Элемент `lines`

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `id` | string | нет | Идентификатор существующей позиции |
| `line_no` | integer | да | Номер позиции |
| `amount` | string | да | Абсолютная сумма позиции |
| `assignment` | object | да | Полное состояние контировки |

#### Поля `assignment`

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `type` | string \| null | нет | Тип |
| `category` | string \| null | нет | Категория |
| `project` | string \| null | нет | Проект |
| `fund_id` | string \| null | нет | Фонд |
| `source` | string | нет | Происхождение контировки |
| `state` | string | нет | Состояние полноты |
| `note` | string \| null | нет | Пояснение |

* Состав и семантика полей совпадают с FIN-272.
* MCP не нормализует omit и пустые строки сверх того, что уже делает HTTP-слой.
* Тело HTTP-запроса содержит только ключ `lines`.

### Вход чтения (D-08)

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; по умолчанию из сессии или `prod` |
| `base` | string | нет | Базовый URL API; по умолчанию из сессии |
| `transaction_id` | string | да | Идентификатор операции в пути |

### Результат успеха замены (D-09)

* Успешный ответ API имеет код HTTP 200.
* При успехе ответ инструмента содержит `ok: true`, профиль данных, базовый URL и массив `lines`.
* Представление элементов `lines` совпадает с ответом FIN-272.

### Результат успеха чтения позиций (D-10)

* Успешный ответ API имеет код HTTP 200.
* При успехе ответ инструмента содержит `ok: true`, профиль данных, базовый URL и массив `lines`.
* Представление совпадает с успешным ответом замены.

### Результат успеха чтения операции (D-11)

* Успешный ответ API имеет код HTTP 200.
* При успехе ответ инструмента содержит `ok: true`, профиль данных, базовый URL и объект `transaction`.
* Объект `transaction` совпадает с моделью ответа FIN-272 для пути чтения операции, включая массив `lines`.

### Инварианты (D-12)

* MCP не выполняет повторных попыток после получения доменной ошибки.
* MCP не выполняет поиск фонда, категории, проекта или члена домохозяйства до вызова HTTP API.
* После разделения `put_transaction` по-прежнему меняет только первую позицию; контировка второй и последующих задаётся только через `put_transaction_lines`.
* Идентификатор заголовка операции сохраняется; сумма и направление заголовка этим вызовом не меняются.

### Ошибки (D-13)

* Ответ API без кода HTTP 200 даёт `RuntimeError` через `format_api_error`.
* Мягкий ответ вида `{ "ok": false }` без исключения не используется.
* Текст ошибки инструмента сохраняет код HTTP и код ошибки API при их наличии.

| Ситуация | Источник | Поведение MCP |
| -------- | -------- | ------------- |
| Пустой идентификатор операции | до HTTP | `ValueError` |
| Отсутствует или пуст `lines` у замены | до HTTP | `ValueError` |
| Операция не найдена | HTTP 404, `transaction_not_found` | ошибка инструмента |
| Ошибка схемы тела | HTTP 422, `validation_error` | ошибка инструмента |
| Число позиций меньше одного | HTTP 422, `invalid_lines` | ошибка инструмента |
| Сумма позиции не положительна | HTTP 422, `invalid_line_amount` | ошибка инструмента |
| Сумма позиций не равна сумме заголовка | HTTP 422, `line_amount_mismatch` | ошибка инструмента |
| Набор номеров позиций некорректен | HTTP 422, `invalid_line_no` | ошибка инструмента |
| Повтор идентификатора позиции во входе | HTTP 422, `duplicate_line_id` | ошибка инструмента |
| Идентификатор позиции не принадлежит операции | HTTP 422, `unknown_line` | ошибка инструмента |
| Неизвестный фонд | HTTP 404, `unknown_fund` | ошибка инструмента |
| Фонд не принадлежит активному домохозяйству | HTTP 422, `fund_not_in_active_household` | ошибка инструмента |
| Дата операции вне интервала фонда | HTTP 422, `fund_not_valid_for_transaction_date` | ошибка инструмента |
| Закрытый период без обхода | HTTP 422, `period_closed` | ошибка инструмента |

## Функциональное тестирование

### Предусловия

* Подключение MCP `finance_api_connect` с профилем данных `cand` или `test`.
* На том же профиле доступны пути FIN-272.
* Есть операция с одной позицией на сумму `100.00` в открытом учётном периоде.
* В справочнике есть не меньше двух допустимых фондов на дату этой операции.
* Есть операция в закрытом учётном периоде либо период временно закрыт для шага.
* Профиль `prod` для заполнения факта прогона не использовать без отдельной ops-команды.
