# MCP-инструменты сопоставления сторон внутреннего перевода

**Статус:** Утверждено (2026-08-30, rev.10).

## Назначение

- Операторы на пути только через MCP не создают, не читают и не удаляют сопоставление сторон внутреннего перевода без обхода сырым HTTP.
- Нужен паритет инструментов MCP с публичной HTTP-поверхностью сопоставления.

## Входит в объём

- Создание одного сопоставления сторон внутреннего перевода.
- Пакетное создание сопоставлений.
- Чтение сопоставления по идентификатору.
- Список сопоставлений профиля, в том числе отбор по позиции.
- Удаление одного сопоставления.
- Пакетное удаление сопоставлений.
- Чтение состояния сопоставления в том виде, в каком его отдаёт HTTP: стороны, валюта выравнивания и курс выравнивания.
- Проброс доменных ошибок HTTP в ошибку инструмента.
- Обновление справочника доступных инструментов MCP.

## Вне объёма

- Модель данных, DDL и инварианты слоя сохранения (FIN-349).
- Проектирование HTTP-контракта сопоставления (FIN-350).
- Пользовательский интерфейс сопоставления (FIN-352).
- Автоматический подбор пар равных сумм в одной валюте (FIN-203).
- Применение июльского сопоставления на операционном профиле (FOPS-40).
- Вложение сопоставления в выборку операций и в чтение операции.
- Инструменты погашения расхода.
- Частичное обновление сохранённого сопоставления.
- Приём курса выравнивания и валюты выравнивания от вызывающей стороны.
- Пагинация списка.
- Фильтр списка по учётному периоду и по банковскому счёту.
- Один инструмент MCP с перечислением действия вместо отдельных инструментов.

## Целевое поведение

#### Набор инструментов (D-01)

- Для публичной HTTP-поверхности FIN-350 MCP предоставляет однозначно соответствующую поверхность.
- Каждой операции HTTP API соответствует отдельный MCP-инструмент с той же функциональной семантикой.
- MCP не исключает операции этой HTTP-поверхности.
- MCP не добавляет самостоятельные операции предметной области поверх этой поверхности.
- Создание, чтение и удаление разведены по разным инструментам.
- Индивидуальные и пакетные операции разведены по разным инструментам.
- Частичное обновление сопоставления не вводится.
- Один инструмент с перечислением действия не используется.
- Идентификатор сопоставления при создании задаёт слой сохранения.
- Клиент MCP поле идентификатора при создании не передаёт.
- Доменные правила тел, атомарность пакетов, коды ошибок и порядок элементов массивов и коллекций ответа задаёт FIN-350.
- MCP не переопределяет доменные правила FIN-350.
- Повторение отдельных ожидаемых результатов в сценариях приёмки не создаёт самостоятельной нормы MCP.
- Существующие инструменты MCP этой задачей не меняются.
- Поля сопоставления в выборку операций и в чтение операции не добавляются.
- Набор инструментов:

| Инструмент MCP | Операция HTTP | Смысл |
| -------------- | ------------- | ----- |
| `list_internal_transfer_matches` | `GET /api/v1/internal-transfer-matches` | Список |
| `get_internal_transfer_match` | `GET /api/v1/internal-transfer-matches/{match_id}` | Чтение по идентификатору |
| `create_internal_transfer_match` | `POST /api/v1/internal-transfer-matches` | Создание одной записи |
| `create_internal_transfer_matches` | `POST /api/v1/internal-transfer-matches/batch` | Пакетное создание |
| `delete_internal_transfer_match` | `DELETE /api/v1/internal-transfer-matches/{match_id}` | Удаление одной записи |
| `delete_internal_transfer_matches` | `DELETE /api/v1/internal-transfer-matches` | Пакетное удаление |

#### Конвейер (D-02)

```
1. проверить аргументы MCP по схеме
2. определить эффективный profile
3. определить эффективный base
4. выполнить дополнительную валидацию обработчика
5. получить сессию API для этого профиля и URL
6. собрать путь, параметры запроса и тело
7. выполнить вызов метода GET, POST или DELETE
8. сравнить код HTTP с ожидаемым кодом успеха этой операции
9. при совпадении с кодом HTTP 200 или 201 ожидать тело ответа и обернуть сущность или коллекцию в конверт ok / profile / base
10. при совпадении с кодом HTTP 204 не ожидать тела ответа и вернуть только конверт ok / profile / base
11. при любом ином коде, включая другой код класса 2xx, вернуть ошибку инструмента по D-14
12. сетевые сбои пробросить без дополнительной обёртки
```

- Порядок шагов фиксирован.
- Успех операции определяется совпадением кода HTTP с ожидаемым кодом успеха этой операции, а не принадлежностью кода классу `2xx`.
- Эффективный `profile` и эффективный `base` определяются по D-04 после проверки схемы.
- Дополнительная валидация обработчика выполняется после определения эффективного `profile` и эффективного `base` и до получения сессии API.
- Сессия API выбирается или создаётся по паре эффективный `profile` и эффективный `base`.
- Ошибки разрешения API-сессии, эффективного профиля и URL наследуются из общего механизма MCP-сессий и этой задачей не преобразуются.
- Вызов `finance_api_connect` с другим профилем не подставляет этот профиль в последующие вызовы инструментов.
- Ожидаемый код успеха:

| Инструмент | Ожидаемый код успеха | Тело при успехе |
| ---------- | -------------------- | --------------- |
| `list_internal_transfer_matches` | 200 | да |
| `get_internal_transfer_match` | 200 | да |
| `create_internal_transfer_match` | 201 | да |
| `create_internal_transfer_matches` | 201 | да |
| `delete_internal_transfer_match` | 204 | нет |
| `delete_internal_transfer_matches` | 204 | нет |

#### Модуль и регистрация (D-03)

- Логика обёрток размещается в `scripts/internal_transfer_matches.py`.
- Обработчики и схемы инструментов регистрируются в `server.py`.
- Справочник доступных инструментов обновляется в `mcp-gaps.md`.
- Снятие метки `mcp-gap` с FIN-351 выполняется при переводе задачи в Done и не входит в критерий функциональной приёмки.

#### Валидация до HTTP (D-04)

- Схема MCP проверяет типы и обязательность объявленных аргументов.
- Схема MCP отклоняет незаявленные аргументы.
- Нарушение схемы даёт ошибку валидации MCP до HTTP.
- При нарушении схемы сессия API не получается и HTTP не вызывается.
- Тип Python-исключения при отклонении схемой не фиксируется.
- Обработчик не дублирует проверку типов.
- Обработчик не дублирует отклонение незаявленных аргументов.
- Обработчик применяет `strip` к значениям, используемым при формировании HTTP-вызова, для `profile`, `base` и фильтра позиции; для `match_id` и элементов `ids` `strip` используется только в проверке непустоты.
- Проверка непустоты с `ValueError` применяется только там, где это указано явно.
- Нарушение правил обработчика даёт `ValueError` без получения сессии API и без вызова HTTP.
- Формат UUID, атомарность пакета и доменные инварианты FIN-349 и FIN-350 проверяет только backend.
- После проверки схемы строковый аргумент `profile` нормализуется через `strip`.
- Отсутствие аргумента `profile` или пустое значение после `strip` означает `prod` и не даёт `ValueError`.
- После проверки схемы, если аргумент `base` передан и после `strip` непуст, это значение есть URL-переопределение.
- Если аргумент `base` отсутствует или после `strip` пуст, используется URL по умолчанию конфигурации MCP для этого профиля.
- Для чтения и удаления одной записи `match_id` должен быть непустым после `strip`.
- В путь HTTP передаётся исходное строковое значение `match_id` без нормализации.
- Для создания одной записи обязательны ключи `debit_line_ids` и `credit_line_ids` типа `array[string]`.
- Обработчик создания одной записи не применяет к элементам этих массивов `strip` и проверку непустоты.
- Пустой массив идентификаторов позиций на схеме MCP допускается и передаётся HTTP.
- Для пакетного создания обработчик проверяет наличие непустого массива `internal_transfer_matches`.
- Пустой массив `internal_transfer_matches` даёт `ValueError` без получения сессии API и без вызова HTTP.
- Схема MCP проверяет каждый элемент пакетного создания по D-10.
- Обработчик не применяет к полям элементов пакетного создания `strip` и проверку непустоты.
- Пустые строковые значения элементов массивов идентификаторов позиций передаются backend.
- Для пакетного удаления обработчик проверяет наличие непустого массива `ids` типа `array[string]`.
- Пустой массив `ids` даёт `ValueError` без получения сессии API и без вызова HTTP.
- Каждый элемент `ids` должен быть непустым после `strip`.
- В тело HTTP передаётся исходное строковое значение элемента `ids` без нормализации.
- Отсутствие ключа фильтра позиции в списке означает список без ограничения по позиции.
- Ключ фильтра позиции со значением `null`, пустой строкой или строкой из пробелов отклоняется на MCP-уровне до HTTP.
- Если ключ фильтра позиции передан, значение после `strip` уходит в параметр запроса HTTP.

#### Отсутствие ключа (D-05)

- Ключ, отсутствующий в аргументах MCP, не попадает в JSON тела запроса и не попадает в параметры запроса.
- Поля создания не допускают JSON `null` вместо массива идентификаторов позиций.
- Явная передача `null` для обязательного массива отклоняется на MCP-уровне до HTTP.
- При этой ошибке HTTP не вызывается.
- Пустая строка не преобразуется в `null`.
- Значение по умолчанию параметра в коде не смешивает «ключ не передан» и «ключ передан со значением `null`».
- Построение JSON-тела опирается на поля тела FIN-350 из переданных аргументов.
- Ключи идентификатора сопоставления, валюты выравнивания, курса выравнивания, сумм выравнивания и типа записи сохранения в аргументах создания не объявляются.

#### Инварианты (D-06)

- MCP не ослабляет инварианты HTTP API сопоставления.
- Аргументы `profile` и `base` никогда не входят в тело HTTP и не входят в параметры запроса HTTP.
- Аргумент `allow_closed` при передаче входит только в параметры запроса HTTP.
- JSON-тело запроса содержит только поля тела соответствующего контракта FIN-350.
- MCP не нормализует значения REST-ответа.
- MCP не нормализует структуру REST-ответа.
- MCP не пересортировывает массивы и элементы коллекции в теле ответа HTTP.
- Порядок `debit_line_ids`, `credit_line_ids`, сумм выравнивания и элементов списка наследуется из FIN-350.
- При коде HTTP 204 ключ сущности отсутствует.
- Обёртка успеха добавляет только конверт `ok` / `profile` / `base` и ключ сущности или коллекции.
- Поля `profile` и `base` в успешном ответе содержат эффективные значения после разрешения по D-04.
- Связанные операции и позиции вызовами этой задачи не изменяются.
- Снимки планового курса и суммы в валюте бюджета на связанных операциях вызовами этой задачи не переписываются.

#### Список (D-07)

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; отсутствие ключа означает `prod`; норма D-02 |
| `base` | string | нет | Базовый URL API; отсутствие ключа означает URL по умолчанию для профиля; норма D-04 |
| `line_id` | string | нет | Фильтр по позиции; отсутствие ключа означает список всего профиля |

- При успехе ответ инструмента содержит `ok: true`, профиль, базовый URL и коллекцию `internal_transfer_matches`.
- Пустой список допустим и сохраняет `ok: true`.
- Успех соответствует ответу API с кодом HTTP 200.
- Ошибка фильтра по позиции пробрасывается по D-14.
- Существующая позиция без сопоставления даёт успешный пустой массив.
- Существующая позиция с сопоставлением даёт массив из одного элемента.

#### Чтение по идентификатору (D-08)

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; отсутствие ключа означает `prod`; норма D-02 |
| `base` | string | нет | Базовый URL API; отсутствие ключа означает URL по умолчанию для профиля; норма D-04 |
| `match_id` | string | да | Идентификатор сопоставления в пути |

- При успехе ответ инструмента содержит `ok: true` и объект `internal_transfer_match`.
- Успех соответствует ответу API с кодом HTTP 200.
- Тело объекта совпадает с HTTP-моделью FIN-350, включая валюту выравнивания, курс выравнивания, идентификаторы позиций сторон и суммы выравнивания.
- Отсутствие сопоставления и синтаксически неверный идентификатор пробрасываются по D-14.

#### Создание одной записи (D-09)

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; отсутствие ключа означает `prod`; норма D-02 |
| `base` | string | нет | Базовый URL API; отсутствие ключа означает URL по умолчанию для профиля; норма D-04 |
| `debit_line_ids` | array[string] | да | Идентификаторы позиций стороны списания |
| `credit_line_ids` | array[string] | да | Идентификаторы позиций стороны зачисления |
| `allow_closed` | boolean | нет | Обход закрытого учётного периода; норма D-13 |

- Поле идентификатора сопоставления в аргументах создания не передаётся.
- Успешное создание соответствует ответу API с кодом HTTP 201.
- При успехе ответ инструмента содержит `ok: true` и объект `internal_transfer_match` с выданным идентификатором.
- Идентификатор, валюту выравнивания, курс выравнивания и суммы выравнивания выдаёт HTTP.
- Пустой массив идентификаторов позиций передаётся HTTP и даёт ошибку инструмента по D-14.
- Обработчик не переставляет элементы `debit_line_ids` и `credit_line_ids` во входном теле HTTP.

```json
{
  "ok": true,
  "profile": "cand",
  "base": "http://127.0.0.1:8001",
  "internal_transfer_match": {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "clearing_currency": "RUB",
    "clearing_rate": "98.29048",
    "debit_line_ids": ["line-c24-bitfi"],
    "credit_line_ids": ["line-getbit-5502", "line-getbit-7116", "line-getbit-8023"],
    "debit_clearing_amounts": ["20641.00"],
    "credit_clearing_amounts": ["5502.00", "7116.00", "8023.00"]
  }
}
```

#### Пакетное создание (D-10)

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; отсутствие ключа означает `prod`; норма D-02 |
| `base` | string | нет | Базовый URL API; отсутствие ключа означает URL по умолчанию для профиля; норма D-04 |
| `internal_transfer_matches` | array[object] | да | Непустой массив элементов, схема ниже |
| `allow_closed` | boolean | нет | Обход закрытого учётного периода на весь пакет; норма D-13 |

- `profile`, `base` и `allow_closed` являются аргументами инструмента, а не полями элемента.
- Каждый элемент содержит ровно два ключа: `debit_line_ids` и `credit_line_ids`.
- Тип каждого из этих ключей есть `array[string]`.
- Любой иной ключ элемента отклоняется схемой MCP до HTTP.
- Успех соответствует ответу API с кодом HTTP 201.
- При успехе ответ инструмента содержит `ok: true` и коллекцию `internal_transfer_matches`.
- Порядок элементов в ответе совпадает с порядком элементов во входном массиве.
- MCP не реализует собственную атомарность и не агрегирует ошибки.
- Атомарность пакета наследуется из FIN-350.
- Обработчик не переставляет элементы `debit_line_ids` и `credit_line_ids` во входном теле HTTP.

```json
{
  "debit_line_ids": ["line-c24-bitfi"],
  "credit_line_ids": ["line-getbit-7116", "line-getbit-8023", "line-getbit-5502"]
}
```

#### Удаление одной записи (D-11)

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; отсутствие ключа означает `prod`; норма D-02 |
| `base` | string | нет | Базовый URL API; отсутствие ключа означает URL по умолчанию для профиля; норма D-04 |
| `match_id` | string | да | Идентификатор сопоставления в пути |
| `allow_closed` | boolean | нет | Обход закрытого учётного периода; норма D-13 |

- Успех соответствует ответу API с кодом HTTP 204.
- Ответ инструмента содержит `ok: true`, профиль и базовый URL без объекта `internal_transfer_match`.
- Нормы D-06.12 и D-06.13 применяются к удалению.
- Отсутствие сопоставления и синтаксически неверный идентификатор пробрасываются по D-14.

#### Пакетное удаление (D-12)

| Поле | Тип | Обяз. | Описание |
| ---- | --- | ----- | -------- |
| `profile` | string | нет | Профиль данных; отсутствие ключа означает `prod`; норма D-02 |
| `base` | string | нет | Базовый URL API; отсутствие ключа означает URL по умолчанию для профиля; норма D-04 |
| `ids` | array[string] | да | Идентификаторы сопоставлений; семантика значения UUID по FIN-350; тип схемы string, не UUID |
| `allow_closed` | boolean | нет | Обход закрытого учётного периода на весь пакет; норма D-13 |

- Успех соответствует ответу API с кодом HTTP 204.
- Ответ инструмента содержит `ok: true`, профиль и базовый URL без коллекции.
- MCP не реализует собственную атомарность и не агрегирует ошибки.
- Атомарность пакета наследуется из FIN-350.

#### Обход закрытого периода (D-13)

- Инструменты создания одной записи, пакетного создания, удаления одной записи и пакетного удаления принимают необязательный аргумент `allow_closed`.
- Тип аргумента есть boolean.
- Отсутствие аргумента означает, что параметр запроса HTTP не добавляется.
- HTTP при отсутствии параметра трактует обход как ложь, как в FIN-350.
- Явное значение истины уходит в параметр запроса как `allow_closed=true`.
- Явное значение лжи уходит в параметр запроса как `allow_closed=false`.
- Инструменты чтения аргумент не принимают.
- Схема чтения отклоняет незаявленный ключ `allow_closed` до HTTP.

#### Ошибки (D-14)

- Код HTTP, отличный от ожидаемого кода успеха этой операции, даёт `RuntimeError`.
- Текст `RuntimeError` содержит тело ответа HTTP целиком, как оно получено.
- Если тело является ошибочным телом FIN-350, в этом тексте без потери присутствуют `error.code` и `error.details`.
- Если это ошибка элемента пакета FIN-350, в этом тексте присутствует `error.details.index`.
- Если код HTTP неожиданный, включая другой код класса `2xx`, наличие `error.code` и `error.details` не требуется.
- MCP не предоставляет структурированные поля ошибки на объекте `RuntimeError`.
- Мягкий ответ вида `{ "ok": false }` без исключения не используется.
- MCP не вводит собственных кодов ошибок сопоставления.
- Сетевой сбой HTTP-клиента пробрасывается как исходное исключение без замены на `RuntimeError` и без доменного кода сопоставления.

| Ситуация | Источник | Что видит вызывающая сторона |
| -------- | -------- | ---------------------------- |
| Нарушение схемы MCP | MCP до HTTP | ошибка валидации MCP; сессия не получается; HTTP не вызывается |
| Пустое обязательное строковое поле после `strip` | MCP до HTTP | `ValueError`; сессия не получается; HTTP не вызывается |
| Пустой массив пакетного создания или пакетного удаления | MCP до HTTP | `ValueError`; сессия не получается; HTTP не вызывается |
| Ошибочное тело FIN-350 | HTTP | `RuntimeError`; текст содержит тело целиком, включая `error.code` и `error.details` |
| Ошибка элемента пакета FIN-350 | HTTP | `RuntimeError`; в тексте есть тело HTTP, включая `error.details.index` |
| Неожиданный код HTTP, включая другой `2xx` | HTTP | `RuntimeError`; текст содержит тело как есть; `error.*` не требуется |
| Сетевой сбой HTTP-клиента | HTTP-клиент | исходное исключение; `RuntimeError` не создаётся |
| Ошибка разрешения API-сессии, эффективного профиля или URL | общий механизм MCP-сессий | исходная ошибка механизма; эта задача её не преобразует |

## Предположения, предусловия и ограничения

- HTTP API FIN-350 доступен по эффективному `base` для эффективного `profile`.
- Созданная или выбранная сессия API работает с тем же эффективным профилем.
- Инварианты сторон, курса, баланса и участия позиции задаёт FIN-349.
- HTTP и MCP их не переопределяют.

## Критерий приёмки

#### Продуктовый результат

- Сопоставление сторон внутреннего перевода создаётся, читается по идентификатору, перечисляется и удаляется через MCP согласно целевому поведению.
- Пакетное создание и пакетное удаление выполняются через MCP согласно целевому поведению, включая атомарный отказ пакета.
- Курс выравнивания возвращается в успешном ответе создания и чтения и не принимается во входных аргументах.
- Снимки планового курса на связанных операциях после записи сопоставления через MCP не изменяются.
- Сценарий разновалютного сопоставления с несколькими позициями на стороне зачисления воспроизводится через MCP без сырого HTTP.
- Доменные ошибки HTTP с телом FIN-350 отображаются ошибкой инструмента `RuntimeError`, текст которой содержит это тело целиком, включая `error.code`.
- Код HTTP, отличный от ожидаемого кода успеха операции, включая другой код класса `2xx`, даёт ошибку инструмента с телом ответа как есть.
- Пустой список сопоставлений является успешным ответом.
- Существующие инструменты MCP сохраняют прежнюю семантику.

#### Контроль реализации

- Поведение, допускающее автоматизированную функциональную проверку, покрыто функциональными тестами.
- Справочник доступных инструментов MCP содержит все шесть инструментов этой задачи.
- Автотесты на mock HTTP проверяют состав сформированного запроса: отсутствие незаявленных ключей, построение параметра `allow_closed` для каждого из четырёх инструментов записи, отсутствие запроса сессии и отсутствие HTTP-вызова при ошибке схемы, при пустом пакете и при пустом обязательном строковом поле после `strip`.
- Автотесты на mock HTTP проверяют отказ при коде HTTP класса `2xx`, который не равен ожидаемому коду успеха операции.
- Автотесты на mock HTTP проверяют успешный пустой список `internal_transfer_matches` равный `[]`.
- Автотесты на mock HTTP проверяют, что несколько идентификаторов на обеих сторонах уходят в тело HTTP без потери элементов и без перестановки со стороны MCP.

### Автоматизация

- Функциональные тесты MCP на mock HTTP покрывают создание, чтение, список, удаление, пакет, откат пакета, валидацию до HTTP и проброс доменных ошибок.
- Автотест проверяет построение параметра `allow_closed` для каждого из четырёх инструментов записи: при отсутствии аргумента параметра нет; при явном значении лжи есть `allow_closed=false`; при явном значении истины есть `allow_closed=true`.
- Автотест проверяет, что при `debit_line_ids` равном `["d1", "d2"]` и `credit_line_ids` равном `["c1", "c2"]` тело HTTP содержит оба массива без потери элементов и без перестановки со стороны MCP.
- Автотест проверяет, что при отсутствии ключа `debit_line_ids` сессия API не запрашивается и HTTP-клиент не вызывается.
- Автотест проверяет, что при `debit_line_ids` равном `null` сессия API не запрашивается и HTTP-клиент не вызывается.
- Автотест проверяет, что при незаявленных ключах `id` и `clearing_rate` сессия API не запрашивается и HTTP-клиент не вызывается.
- Автотест проверяет, что при пустом массиве пакетного создания и пакетного удаления сессия API не запрашивается и HTTP-клиент не вызывается.
- Автотест проверяет, что при ключе `allow_closed` на `list_internal_transfer_matches` и `get_internal_transfer_match` сессия API не запрашивается и HTTP-клиент не вызывается.
- Автотест пакетной ошибки проверяет, что текст `RuntimeError` содержит тело ответа HTTP целиком, включая `error.details.index`, и что у исключения нет структурированного атрибута `details`.
- Автотест проверяет, что ответ с кодом HTTP 201 для `get_internal_transfer_match` даёт `RuntimeError`, текст которого содержит тело ответа как есть; наличие `error.code` не требуется.
- Автотест проверяет, что ответ с кодом HTTP 200 для `create_internal_transfer_match` даёт `RuntimeError`, текст которого содержит тело ответа как есть; наличие `error.code` не требуется.
- Автотест проверяет, что ответ с кодом HTTP 200 для `delete_internal_transfer_match` даёт `RuntimeError`, текст которого содержит тело ответа как есть; наличие `error.code` не требуется.
- Автотест проверяет, что нестроковый `profile` отклоняется схемой до получения сессии API.
- Автотест проверяет, что при отсутствии аргумента `profile` сессия запрашивается для профиля `prod`.
- Автотест проверяет, что при `profile` равном `" cand "` сессия запрашивается для профиля `cand`.
- Автотест проверяет, что при `profile` равном `"   "` сессия запрашивается для профиля `prod`.
- Автотест проверяет, что при отсутствии аргумента `base` используется URL по умолчанию конфигурации MCP для эффективного профиля.
- Автотест проверяет, что при `profile` равном `cand` и отсутствии `base` используется URL по умолчанию профиля `cand`, а не профиля `prod`.
- Автотест проверяет, что при `base` равном `"   "` используется тот же URL по умолчанию эффективного профиля.
- Автотест проверяет, что при `base` равном `" http://127.0.0.1:9 "` сессия запрашивается с URL `http://127.0.0.1:9`.
- Автотест проверяет, что успешный ответ содержит в конверте те же эффективные `profile` и `base`, с которыми запрошена сессия.
- Автотест проверяет, что HTTP-ответ с пустым массивом `internal_transfer_matches` даёт `ok: true` и `internal_transfer_matches` равный `[]`.
- Автотест проверяет, что при пустом `match_id` сессия API не запрашивается и возникает `ValueError`.
- Автотест проверяет, что при `line_id` из пробелов сессия API не запрашивается и возникает `ValueError`.
- Автотест проверяет, что при элементе `ids` равном `"   "` сессия API не запрашивается, HTTP-клиент не вызывается и возникает `ValueError`.
- Автотест проверяет, что `match_id` со значением `"  <uuid>  "` уходит в путь HTTP с пробелами и даёт `RuntimeError` с кодом `validation_error`.
- Автотест проверяет, что элемент `ids` со значением `"  <uuid>  "` уходит в тело HTTP с пробелами и даёт `RuntimeError` с кодом `validation_error`.
- Автотест проверяет, что исключение сетевого сбоя HTTP-клиента, включая `ConnectionError` и `Timeout`, пробрасывается без замены на `RuntimeError`.
- Автотесты на mock HTTP не заменяют прогон функциональной приёмки в окружении из предусловий прогона.
